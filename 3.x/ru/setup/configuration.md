# Общая конфигурация

Все файлы конфигурации October CMS хранятся в каталоге `config`. Каждый параметр конфигурации содержит встроенную документацию.

## Конфигурация через переменные окружения

Многие параметры October CMS можно настроить с помощью переменных окружения. Переменные окружения могут быть установлены на уровне сервера или определены для [виртуального хоста веб-приложения](https://httpd.apache.org/docs/2.4/env.html).

::: aside
October CMS использует [библиотеку DotEnv](https://github.com/vlucas/phpdotenv) для удобного управления переменными окружения.
:::

Переменные окружения также можно определить в файле `.env`, который скрипт установки автоматически создаёт в корневом каталоге проекта. В чистой установке October CMS базовый каталог содержит файл `.env.example` с типичными значениями для локального окружения.

Например, подключение к базе данных можно указать с помощью следующих переменных:

```ini
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=database
DB_USERNAME=root
DB_PASSWORD=
```

Любая переменная в файле `.env` может быть переопределена внешними переменными окружения, заданными на уровне сервера или виртуального хоста.

Значения конфигурации загружаются в следующем порядке:

1. системные переменные окружения
2. переменные в файле .env
3. значения в конфигурационных PHP-файлах.

::: warning
Никогда не добавляйте файл `.env` в систему контроля версий. Это создаст угрозу безопасности в случае, если злоумышленник получит доступ к репозиторию.
:::

### Файлы конфигурации для конкретных окружений

Если файл конфигурации должен загружаться в зависимости от текущего окружения приложения, например, промежуточного или рабочего, можно использовать серверную переменную `APP_ENV`. Пример конфигурации Apache:

```text
SetEnv APP_ENV "staging"
```

Когда переменная `APP_ENV` определена, платформа пытается загрузить файл .env с суффиксом, соответствующим имени окружения, например, **.env.staging**. Если файл не существует, ошибки не возникнет. Если существуют оба файла — **.env.staging** и **.env**, файл **.env** полностью игнорируется.

При использовании кэшированной или [оптимизированной конфигурации](./web-server-config.md) в файле **.env** можно указать значение `APP_CONFIG_CACHE` для изменения пути к файлу кэша. Это гарантирует, что каждое окружение получит правильные кэшированные значения конфигурации.

```ini
APP_CONFIG_CACHE=storage/framework/config-staging.php
```

## Настройка для рабочего окружения

Существует несколько важных и часто используемых параметров конфигурации, которые необходимо установить для рабочих окружений.

### Режим отладки

Параметр `debug` находится в файле `config/app.php` и должен быть отключён в рабочем окружении. По умолчанию значение загружается из переменной окружения `APP_DEBUG`. После установки режим отладки включён в файле `.env`.

```ini
APP_DEBUG=false
```

Когда режим отладки включён, отображаются подробные сообщения об ошибках, а также другие функции отладки. Хотя это полезно во время разработки, режим отладки обязательно должен быть отключён на рабочем сайте. Он не позволяет потенциально конфиденциальной информации отображаться для посетителей сайта.

Возможности, предоставляемые при включённом режиме отладки:

- [подробные сообщения об ошибках](../cms/pages.md#error-page)
- при неудачной аутентификации пользователя указывается конкретная причина
- [объединённые ресурсы](../markup/filter-theme.md) по умолчанию не минифицируются

### Защита от CSRF

October CMS предоставляет встроенный механизм защиты от [межсайтовой подделки запросов](https://owasp.org/www-community/attacks/csrf). Когда защита от CSRF включена, October CMS сохраняет случайный токен в сессии пользователя. [Открывающий тег формы](../extend/services/html.md#opening-a-form) и [тег токена формы](../extend/services/html.md#form-tokens) добавляют скрытое поле со значением токена в форму. Для всех запросов POST, PUT или DELETE платформа проверяет, совпадает ли отправленное значение токена с сохранённым в сессии пользователя.

Защита от CSRF включена по умолчанию. Параметр `enable_csrf_protection` находится в файле `config/system.php`. По умолчанию значение загружается из переменной окружения `ENABLE_CSRF`.

### Публичная папка

Для рабочих окружений рекомендуется использовать [публичную папку](../setup/web-server-config.md), чтобы изолировать внутренние файлы от публичных. Это дополнительный уровень защиты, используемый вместе с [конфигурацией веб-сервера](../setup/web-server-config.md), которая предоставляет доступ только к индексному PHP-файлу и статическим файлам ресурсов.

### Установка резервной темы

[Активная тема CMS](../cms/themes/themes.md) обычно берётся из базы данных. Проблема, которая может возникнуть в рабочем окружении — при сбое подключения к базе данных вместо сайта отображается демонстрационная тема или общий экран ошибки. Чтобы избежать этого, обязательно установите резервную тему в файловой конфигурации.

Резервная активная тема задаётся в файле `config/cms.php` и загружается из переменной окружения `ACTIVE_THEME`. Убедитесь, что указана корректная тема, поскольку это значение будет использоваться при отсутствии доступа к базе данных.

```ini
ACTIVE_THEME=my-theme
```

### Отключение редактора

Одна из уникальных особенностей October CMS — возможность безопасно обновлять сайт в рабочем окружении, например, вносить небольшие правки в HTML или быстро добавлять новые страницы. Это удобно для небольших приложений, тогда как крупные приложения могут требовать более строгого контроля над изменениями в рабочем окружении.

Чтобы запретить изменения в рабочем окружении, вы можете отключить редактор одним из следующих способов:

- загружать только необходимые модули с помощью конфигурации `system.load_modules`
- не развёртывать файлы редактора, находящиеся в [каталоге модулей](./directory-structure.md)
- использовать [разрешения](../extend/backend/permissions.md) для ограничения доступа к редактору

::: tip
Также рекомендуется сделать [каталоги app и themes](./directory-structure.md) доступными только для чтения.
:::

В качестве альтернативы можно [включить безопасный режим](../setup/web-server-config.md), чтобы сохранить редактор активным в рабочем окружении. Безопасный режим позволяет обновлять HTML, CSS и другие файлы, но блокирует обновление секции PHP-кода и любых потенциально небезопасных функций Twig.
