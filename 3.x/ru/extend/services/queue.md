# Очередь

Очереди позволяют отложить обработку ресурсоёмкой задачи, такой как отправка электронного письма, на более позднее время, тем самым значительно ускоряя веб-запросы к вашему приложению.

## Конфигурация

Конфигурационный файл очередей хранится в `config/queue.php`. В этом файле вы найдёте конфигурации подключений для каждого из включённых драйверов очередей, таких как база данных, [Beanstalkd](https://beanstalkd.github.io), [Amazon SQS](https://aws.amazon.com/sqs/), [Redis](https://redis.io), null и синхронный (для локального использования) драйвер. Драйвер очереди `null` просто отбрасывает задания в очереди, чтобы они никогда не выполнялись.

### Требования к драйверам

Для перечисленных драйверов очередей необходимы следующие зависимости. Эти зависимости могут быть установлены через менеджер пакетов Composer.

Подключение | Пакет
------------- | -------------
Amazon SQS | `aws/aws-sdk-php ~3.0`
Beanstalkd | `pda/pheanstalk ~4.0`
Redis      | `predis/predis ~1.0` или PHP-расширение phpredis

## Основы использования

Для добавления нового задания в очередь используйте метод `Queue::push`.

```php
Queue::push(SendEmail::class, ['message' => $message]);
```

Первый аргумент метода `push` — это имя класса, который должен использоваться для обработки задания. Второй аргумент — массив данных, которые должны быть переданы обработчику. Обработчик задания может быть определён как файл **app/SendEmail.php** следующим образом.

```php
class SendEmail
{
    public function fire($job, $data)
    {
        //
    }
}
```

Обратите внимание, что единственный обязательный метод — это `fire`, который получает экземпляр `Job`, а также массив `data`, который был помещён в очередь. Если вы хотите, чтобы задание использовало метод, отличный от `fire`, вы можете указать метод при добавлении задания:

```php
Queue::push('SendEmail@send', ['message' => $message]);
```

#### Указание имени очереди для задания

Вы также можете указать очередь / канал, в который должно быть отправлено задание:

```php
Queue::push('SendEmail@send', ['message' => $message], 'emails');
```

#### Отложенное выполнение задания

Иногда вы можете захотеть отложить выполнение задания в очереди. Например, вы можете захотеть поставить в очередь задание, которое отправляет клиенту электронное письмо через 15 минут после регистрации. Вы можете сделать это с помощью метода `Queue::later`:

```php
$date = Carbon::now()->addMinutes(15);

Queue::later($date, 'SendEmail', ['message' => $message]);
```

В этом примере мы используем библиотеку дат [Carbon](https://github.com/briannesbitt/Carbon) для указания задержки, которую мы хотим назначить заданию. Альтернативно вы можете передать количество секунд задержки в виде целого числа.

> **Примечание**: Сервис Amazon SQS имеет ограничение задержки в 900 секунд (15 минут).

#### Очереди и модели

Если ваше задание в очереди принимает модель в своих данных, только идентификатор модели будет сериализован в очередь. Когда задание фактически обрабатывается, система очередей автоматически повторно получит полный экземпляр модели из базы данных. Всё это полностью прозрачно для вашего приложения и предотвращает проблемы, которые могут возникнуть при сериализации полных экземпляров моделей.

#### Удаление обработанного задания

После обработки задания оно должно быть удалено из очереди, что можно сделать с помощью метода `delete` на экземпляре `Job`:

```php
public function fire($job, $data)
{
    // Process the job...

    $job->delete();
}
```

#### Возврат задания обратно в очередь

Если вы хотите вернуть задание обратно в очередь, вы можете сделать это с помощью метода `release`:

```php
public function fire($job, $data)
{
    // Process the job...

    $job->release();
}
```

Вы также можете указать количество секунд ожидания перед освобождением задания:

```php
$job->release(5);
```

#### Проверка количества попыток выполнения

Если во время обработки задания возникает исключение, оно автоматически будет возвращено в очередь. Вы можете проверить количество попыток выполнения задания с помощью метода `attempts`:

```php
if ($job->attempts() > 3) {
    //
}
```

#### Получение идентификатора задания

Вы также можете получить идентификатор задания:

```php
$job->getJobId();
```

## Постановка замыканий в очередь

Вы также можете поместить Closure в очередь. Это очень удобно для быстрых и простых задач, которые нужно поставить в очередь:

#### Добавление замыкания в очередь

```php
Queue::push(function($job) use ($id) {
    Account::delete($id);

    $job->delete();
});
```

::: tip
Вместо того чтобы делать объекты доступными для замыканий в очереди через директиву `use`, рассмотрите передачу первичных ключей и повторное получение связанных моделей изнутри вашего задания очереди. Это часто позволяет избежать неожиданного поведения сериализации.
:::

## Запуск обработчика очереди

October CMS включает некоторые консольные команды, которые обрабатывают задания в очереди. Для обработки новых заданий по мере их добавления в очередь запустите команду `queue:work`:

```bash
php artisan queue:work
```

После запуска эта задача будет продолжать работать, пока не будет остановлена вручную. Вы можете использовать монитор процессов, такой как [Supervisor](#oc-supervisor-configuration), чтобы убедиться, что обработчик очереди не прекращает работу.

Процессы обработчика очереди хранят загруженное состояние приложения в памяти. Они не распознают изменения в вашем коде после запуска. При развёртывании изменений перезапускайте обработчики очереди.

#### Обработка одного задания

Для обработки только первого задания в очереди используйте опцию `--once`:

```bash
php artisan queue:work --once
```

#### Указание подключения и очереди

Вы также можете указать, какое подключение очереди должен использовать обработчик:

```bash
php artisan queue:work --once connection
```

Вы можете передать разделённый запятыми список подключений очереди в команду `work` для установки приоритетов очереди:

```bash
php artisan queue:work --once --queue=high,low
```

В этом примере задания в очереди `high` всегда будут обрабатываться перед переходом к заданиям из очереди `low`.

#### Указание параметра тайм-аута задания

Вы также можете установить время (в секундах), в течение которого каждому заданию разрешено выполняться:

```bash
php artisan queue:work --once --timeout=60
```

#### Указание длительности ожидания очереди

Кроме того, вы можете указать количество секунд ожидания перед опросом новых заданий:

```bash
php artisan queue:work --once --sleep=5
```

Обратите внимание, что очередь «засыпает» только если в очереди нет заданий. Если доступно больше заданий, очередь продолжит обрабатывать их без ожидания.

## Демон обработчика очереди

По умолчанию `queue:work` обрабатывает задания без перезагрузки фреймворка. Это приводит к значительному снижению использования CPU по сравнению с командой `queue:work --once`, но при дополнительной сложности необходимости опустошения очередей текущих заданий во время развёртывания.

Для запуска обработчика очереди в режиме демона просто опустите флаг `--once`:

```bash
php artisan queue:work connection

php artisan queue:work connection --sleep=3

php artisan queue:work connection --sleep=3 --tries=3
```

Вы можете использовать команду `php artisan help queue:work` для просмотра всех доступных опций.

### Развёртывание с демоном обработчика очереди

Самый простой способ развернуть приложение, использующее демон обработчика очереди, — перевести приложение в режим обслуживания в начале развёртывания. Это можно сделать через область настроек в панели управления. Когда приложение находится в режиме обслуживания, October не будет принимать новые задания из очереди, но продолжит обрабатывать существующие задания.

Самый простой способ перезапустить обработчики — включить следующую команду в ваш скрипт развёртывания:

```bash
php artisan queue:restart
```

Эта команда даст указание всем обработчикам очереди перезапуститься после завершения обработки текущего задания.

::: tip
Эта команда использует систему кэширования для планирования перезапуска. По умолчанию APCu не работает для CLI-команд. Если вы используете APCu, добавьте `apc.enable_cli=1` в вашу конфигурацию APCu.
:::

### Разработка для демона обработчика очереди

Демоны обработчика очереди не перезапускают платформу перед обработкой каждого задания. Поэтому вы должны быть внимательны и освобождать тяжёлые ресурсы до завершения задания. Например, если вы выполняете обработку изображений с библиотекой GD, вы должны освободить память с помощью `imagedestroy` после завершения.

Аналогично, ваше подключение к базе данных может разрываться при использовании долго работающим демоном. Вы можете использовать метод `Db::reconnect`, чтобы убедиться, что у вас свежее подключение.

## Конфигурация Supervisor

### Установка Supervisor

Supervisor — это монитор процессов для операционной системы Linux, который автоматически перезапускает ваш процесс `queue:work` в случае сбоя. Для установки Supervisor на Ubuntu вы можете использовать следующую команду:

```bash
sudo apt-get install supervisor
```

### Настройка Supervisor

Конфигурационные файлы Supervisor обычно хранятся в директории `/etc/supervisor/conf.d`. В этой директории вы можете создать любое количество конфигурационных файлов, которые указывают Supervisor, как ваши процессы должны быть отслежены. Например, давайте создадим файл `october-worker.conf`, который запускает и мониторит процесс `queue:work`.

```ini
[program:october-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/october/artisan queue:work --sleep=3 --tries=3
autostart=true
autorestart=true
user=october
numprocs=8
redirect_stderr=true
stdout_logfile=/path/to/october/worker.log
```

В этом примере директива `numprocs` даёт указание Supervisor запустить 8 процессов `queue:work` и мониторить все из них, автоматически перезапуская их в случае сбоя. Конечно, вы должны изменить часть `queue:work` директивы command, чтобы отразить желаемое подключение очереди. Директива `user` должна быть изменена на имя пользователя, который имеет разрешение на выполнение команды.

### Запуск Supervisor

После создания конфигурационного файла вы можете обновить конфигурацию Supervisor и запустить процессы с помощью следующих команд:

```bash
sudo supervisorctl reread

sudo supervisorctl update

sudo supervisorctl start october-worker:*
```

Для получения дополнительной информации о Supervisor обратитесь к [документации Supervisor](http://supervisord.org/index.html).

## Неудачные задания

Поскольку не всё всегда идёт по плану, иногда ваши задания в очереди будут завершаться неудачей. Не волнуйтесь, это случается с лучшими из нас! Существует удобный способ указать максимальное количество попыток выполнения задания. После того как задание превысит это количество попыток, оно будет вставлено в таблицу `failed_jobs`. Имя таблицы неудачных заданий может быть настроено через конфигурационный файл `config/queue.php`.

Вы можете указать максимальное количество попыток выполнения задания с помощью переключателя `--tries` команды `queue:work`:

```bash
php artisan queue:work connection-name --tries=3
```

Если вы хотите зарегистрировать событие, которое будет вызвано при неудаче задания очереди, вы можете использовать метод `Queue::failing`. Это событие — отличная возможность уведомить вашу команду по электронной почте или через другой сторонний сервис.

```php
Queue::failing(function($connection, $job, $data) {
    //
});
```

Вы также можете определить метод `failed` непосредственно в классе задания очереди, позволяя выполнять специфические для задания действия при возникновении неудачи:

```php
public function failed($data)
{
    // Called when the job is failing...
}
```

Исходный массив `data` также будет автоматически передан в метод failed.

### Повторная обработка неудачных заданий

Для просмотра всех неудачных заданий вы можете использовать Artisan-команду `queue:failed`:

```bash
php artisan queue:failed
```

Команда `queue:failed` выведет идентификатор задания, подключение, очередь и время неудачи. Идентификатор задания может быть использован для повторной попытки выполнения неудачного задания. Например, чтобы повторить неудачное задание с идентификатором 5, следует выполнить следующую команду:

```bash
php artisan queue:retry 5
```

Если вы хотите удалить неудачное задание, вы можете использовать команду `queue:forget`:

```bash
php artisan queue:forget 5
```

Чтобы удалить все неудачные задания, вы можете использовать команду `queue:flush`:

```bash
php artisan queue:flush
```
