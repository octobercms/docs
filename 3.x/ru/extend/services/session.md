# Сессия

Поскольку HTTP-приложения не имеют состояния, сессии предоставляют способ хранения информации о пользователе между запросами. October CMS поставляется с разнообразными интерфейсами сессий, доступными для использования через единый API. Поддержка популярных сервисов, таких как [Memcached](http://memcached.org), [Redis](https://redis.io) и базы данных, включена из коробки.

## Конфигурация

Конфигурация сессии хранится в `config/session.php`. Обязательно ознакомьтесь с документированными опциями, доступными вам в этом файле.

- `file` — сессии хранятся в `storage/framework/sessions`.
- `cookie` — сессии хранятся в безопасных, зашифрованных cookies.
- `database` — сессии хранятся в базе данных, используемой вашим приложением.
- `memcached` / `redis` — сессии хранятся в одном из этих быстрых хранилищ на основе кэша.
- `array` — сессии хранятся в простом PHP-массиве и не будут сохраняться между запросами.

По умолчанию October CMS настроен на использование драйвера сессий `file`, который хорошо подходит для большинства приложений. Драйвер `array` обычно используется для запуска модульных тестов для предотвращения сохранения данных сессии.

## Сохранение данных

Используя фасад `Session`, вы можете вызывать различные функции для взаимодействия с базовыми данными. Например, метод `put` сохраняет новый фрагмент данных в сессии.

```php
Session::put('key', 'value');
```

::: warning
October CMS использует ключ сессии `flash` внутренне, поэтому вы должны избегать использования этого имени в качестве ключа.
:::

Метод `push` может использоваться для добавления нового значения к значению сессии, которое является массивом. Например, если ключ `user.teams` содержит массив названий команд, вы можете добавить новое значение в массив следующим образом:

```php
Session::push('user.teams', 'developers');
```

## Получение данных

Когда вы получаете значение из сессии, вы также можете передать значение по умолчанию в качестве второго аргумента метода `get`. Это значение по умолчанию будет возвращено, если указанный ключ не существует в сессии. Если вы передаёте `Closure` в качестве значения по умолчанию в метод `get`, `Closure` будет выполнено и его результат возвращён.

```php
$value = Session::get('key');

$value = Session::get('key', 'default');

$value = Session::get('key', function() { return 'default'; });
```

Если вы хотите получить все данные из сессии, вы можете использовать метод `all`.

```php
$data = Session::all();
```

Метод `has` может использоваться для проверки, существует ли элемент в сессии. Этот метод вернёт `true`, если элемент существует.

```php
if (Session::has('users')) {
    //
}
```

## Удаление данных

Метод `pull` извлечёт и удалит элемент из сессии.

```php
$value = Session::pull('key', 'default');
```

Метод `forget` удалит фрагмент данных из сессии. Если вы хотите удалить все данные из сессии, вы можете использовать метод `flush`.

```php
Session::forget('key');

Session::flush();
```

## Регенерация сессии

Если вам нужно регенерировать идентификатор сессии, вы можете использовать метод `regenerate`.

```php
Session::regenerate();
```

Чтобы регенерировать идентификатор сессии и удалить все данные из сессии в одном выражении, вы можете использовать метод `invalidate`.

```php
Session::invalidate();
```

## Временные данные

Иногда вы можете захотеть сохранить элементы в сессии только для следующего запроса. Вы можете сделать это с помощью метода `Session::flash`. Данные, сохранённые в сессии с помощью этого метода, будут доступны только во время следующего HTTP-запроса, а затем будут удалены. Временные данные в основном полезны для кратковременных сообщений о состоянии.

```php
Session::flash('key', 'value');
```

Если вам нужно сохранить временные данные на более длительный период, вы можете использовать метод `reflash`, который сохранит все временные данные на дополнительный запрос. Если вам нужно сохранить только определённые временные данные, вы можете использовать метод `keep`.

```php
Session::reflash();

Session::keep(['username', 'email']);
```
