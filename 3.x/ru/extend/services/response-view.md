# Ответы и представления

## Базовые ответы

Ответ может быть возвращён практически из любого PHP-метода, используемого страницей. Это включает все CMS-методы, содержащиеся в [жизненном цикле выполнения макета](../../cms/themes/layouts.md) и [определениях AJAX-обработчиков](../../cms/ajax/handlers.md).

#### Возврат строк из CMS-метода

Возврат строки из метода CMS-страницы, макета или компонента остановит процесс в этой точке и переопределит поведение по умолчанию, поэтому здесь будет отображена строка «Hello World» вместо отображения страницы.

```php
public function onStart()
{
    return 'Hello World';
}
```

#### Возврат строк из AJAX-обработчиков

Возврат строки из AJAX-обработчика добавит строку в коллекцию ответов, используя ключ по умолчанию `result`. Запрошенные фрагменты по-прежнему будут включены в ответ.

```php
public function onDoSomething()
{
    return 'Hello World';
    // ['result' => 'Hello World']
}
```

#### Возврат строк из маршрутов

Возврат строки из [определения маршрута](../system/routing.md) действует так же, как CMS-метод, и отображает строку в качестве ответа.

```php
Route::get('/', function() {
    return 'Hello World';
});
```

#### Создание пользовательских ответов

Для более надёжного решения возврат объекта `Response` предоставляет множество методов для построения HTTP-ответов. Мы рассмотрим эту тему подробнее в данной статье.

```php
$contents = 'Page not found';
$statusCode = 404;
return Response::make($contents, $statusCode);
```

### Добавление заголовков к ответам

Имейте в виду, что большинство методов ответа являются цепочечными, что позволяет строить ответы последовательно. Например, вы можете использовать метод `header` для добавления серии заголовков к ответу перед отправкой его пользователю:

```php
return Response::make($content)
    ->header('Content-Type', $type)
    ->header('X-Header-One', 'Header Value')
    ->header('X-Header-Two', 'Header Value');
```

Практическим примером может быть возврат XML-ответа:

```php
return Response::make($xmlString)->header('Content-Type', 'text/xml');
```

### Добавление cookies к ответам

Метод `withCookie` позволяет легко прикреплять cookies к ответу. Например, вы можете использовать метод withCookie для генерации cookie и прикрепления его к экземпляру ответа:

```php
return Response::make($content)->withCookie('name', 'value');
```

Метод `withCookie` принимает дополнительные необязательные аргументы, которые позволяют дополнительно настроить свойства вашего cookie:

```php
->withCookie($name, $value, $minutes, $path, $domain, $secure, $httpOnly)
```

## Другие типы ответов

Фасад `Response` может использоваться для удобной генерации других типов экземпляров ответов.

### Ответы с представлениями

Если вам нужен доступ к методам класса `Response`, но вы хотите вернуть представление в качестве содержимого ответа, вы можете использовать метод `Response::view` для удобства:

```php
return Response::view('acme.blog::hello')->header('Content-Type', $type);
```

### JSON-ответы

Метод `json` автоматически установит заголовок `Content-Type` в application/json, а также преобразует заданный массив в JSON с помощью PHP-функции `json_encode`:

```php
return Response::json(['name' => 'Steve', 'state' => 'CA']);
```

Если вы хотите создать JSONP-ответ, вы можете использовать метод `json` в сочетании с `setCallback`:

```php
return Response::json(['name' => 'Steve', 'state' => 'CA'])
    ->setCallback(Input::get('callback'));
```

### Загрузка файлов

Метод `download` может использоваться для генерации ответа, который заставляет браузер пользователя загрузить файл по указанному пути (первый аргумент). Метод `download` опционально принимает имя файла (второй аргумент), которое определяет имя файла, видимое пользователю при загрузке, и массив HTTP-заголовков (третий аргумент).

```php
return Response::download($pathToFile);

return Response::download($pathToFile, $name, $headers);

return Response::download($pathToFile)->deleteFileAfterSend(true);
```

::: tip
Symfony HttpFoundation, который управляет загрузкой файлов, требует, чтобы загружаемый файл имел имя в ASCII-кодировке.
:::

#### Потоковые загрузки

В некоторых случаях вы можете захотеть превратить строковый ответ в загружаемый ответ без записи содержимого на диск. Используйте метод `streamDownload` для решения этой задачи. Метод принимает callback-функцию (первый аргумент), имя файла (второй аргумент) и необязательный массив заголовков (третий аргумент).

```php
return Response::streamDownload(function() {
    echo 'CSV Contents...';
}, 'export.csv');
```

### Файловые ответы

Метод `file` используется для отображения файла, такого как изображение или PDF, непосредственно в браузере пользователя вместо инициации загрузки. Этот метод принимает путь к файлу (первый аргумент) и массив заголовков (второй аргумент).

```php
return Response::file($pathToFile);

return Response::file($pathToFile, $headers);
```

## Перенаправления

Ответы перенаправления обычно являются экземплярами класса `Illuminate\Http\RedirectResponse` и содержат надлежащие заголовки, необходимые для перенаправления пользователя на другой URL. Самый простой способ сгенерировать экземпляр `RedirectResponse` — использовать метод `to` фасада `Redirect`.

```php
return Redirect::to('user/login');
```

### Возврат перенаправления с данными сессии

Перенаправление на новый URL и [сохранение данных в сессии](./session.md) обычно выполняются одновременно. Поэтому для удобства вы можете создать экземпляр `RedirectResponse` и сохранить данные в сессии в одной цепочке методов:

```php
return Redirect::to('user/login')->with('message', 'Login Failed');
```

::: tip
Поскольку метод `with` сохраняет данные в сессии, вы можете получить данные с помощью обычного метода `Session::get`.
:::

#### Перенаправление на предыдущий URL

Вы можете захотеть перенаправить пользователя на его предыдущее местоположение, например, после отправки формы. Вы можете сделать это с помощью метода `back`:

```php
return Redirect::back();

return Redirect::back()->withInput();
```

#### Перенаправление на текущую страницу

Иногда вы хотите просто обновить текущую страницу. Вы можете сделать это с помощью метода `refresh`:

```php
return Redirect::refresh();
```

## Макросы ответов

Если вы хотите определить пользовательский ответ, который можно повторно использовать в различных маршрутах и контроллерах, вы можете использовать метод `Response::macro`:

```php
Response::macro('caps', function($value) {
    return Response::make(strtoupper($value));
});
```

Функция `macro` принимает имя в качестве первого аргумента и Closure в качестве второго. Closure макроса будет выполнено при вызове имени макроса на классе `Response`:

```php
return Response::caps('foo');
```

Вы можете определять свои макросы в методе `boot` [файла регистрации плагина](../extending.md). Альтернативно плагины могут предоставить файл с именем **init.php** в директории плагина, который вы можете использовать для размещения регистрации макросов.

## Представления

Представления — отличный способ хранить системную логику отображения, такую как разметка, используемая API или конечной точкой, или разметка, общая для CMS и панели управления. Представления также используются [сервисом почты](../system/sending-mail.md) для предоставления содержимого шаблонов по умолчанию. Представления обычно хранятся в директории `views` плагина.

Простое представление может выглядеть следующим образом:

```twig
<!-- View stored in plugins/acme/blog/views/greeting.htm -->

<html>
    <body>
        <h1>Hello, {{ name }}</h1>
    </body>
</html>
```

Представления также могут быть разобраны с использованием PHP-шаблонов с расширением `.php`:

```php
<!-- View stored in plugins/acme/blog/views/greeting.php -->

<html>
    <body>
        <h1>Hello, <?= $name ?></h1>
    </body>
</html>
```

Это представление может быть возвращено в браузер с помощью метода `View::make`:

```php
return View::make('acme.blog::greeting', ['name' => 'Charlie']);
```

Первый аргумент — это «подсказка пути», которая содержит имя плагина, разделённое двумя двоеточиями `::`, за которым следует имя файла представления. Второй аргумент, переданный в `View::make`, — это массив данных, которые должны быть доступны в представлении.

::: tip
Подсказка пути чувствительна к регистру, и имя плагина всегда должно быть в нижнем регистре.
:::

#### Передача данных в представления

```php
// Using conventional approach
$view = View::make('acme.blog::greeting')->with('name', 'Steve');

// Using magic methods
$view = View::make('acme.blog::greeting')->withName('steve');
```

В примере выше переменная `name` будет доступна из представления и будет содержать `Steve`. Как и выше, если вы хотите передать массив данных, вы можете сделать это в качестве второго аргумента метода `make`:

```php
$view = View::make('acme.blog::greeting', $data);
```

Также возможно сделать часть данных доступной для всех представлений:

```php
View::share('name', 'Steve');
```

#### Передача вложенного представления в представление

Иногда вы можете захотеть передать представление в другое представление. Например, имея вложенное представление, хранящееся по пути `plugins/acme/blog/views/child/view.php`, мы могли бы передать его в другое представление следующим образом:

```php
$view = View::make('acme.blog::greeting')->nest('child', 'acme.blog::child.view');

$view = View::make('acme.blog::greeting')->nest('child', 'acme.blog::child.view', $data);
```

Вложенное представление затем может быть отрендерено из родительского представления:

```twig
<html>
    <body>
        <h1>Hello!</h1>
        {{ child|raw }}
    </body>
</html>
```

#### Определение существования представления

Если вам нужно проверить, существует ли представление, используйте метод `View::exists`:

```php
if (View::exists('acme.blog::mail.customer')) {
    //
}
```
