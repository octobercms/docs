# Событие

## Основы использования

Класс `Event` предоставляет простую реализацию паттерна «наблюдатель», позволяя вам подписываться и слушать события в вашем приложении. Например, вы можете слушать, когда пользователь входит в систему, и обновлять дату его последнего входа.

```php
Event::listen('auth.login', function($user) {
    $user->last_login = new DateTime;
    $user->save();
});
```

Это событие доступно с помощью метода `Event::fire`, который вызывается как часть логики входа пользователя, тем самым делая логику расширяемой.

```php
Event::fire('auth.login', [$user]);
```

::: tip
Полный список всех событий, доступных в самом October CMS, смотрите в [документации API](https://octobercms.com/docs/api).
:::

## Подписка на события

Метод `Event::listen` используется в основном для подписки на события и может быть вызван из любого места в коде вашего приложения. Первый аргумент — имя события.

```php
Event::listen('acme.blog.myevent', ...);
```

Второй аргумент может быть замыканием, которое определяет, что должно произойти при вызове события. Замыкание может принимать необязательные аргументы, предоставляемые вызывающим событием.

```php
Event::listen('acme.blog.myevent', function($arg1, $arg2) {
    // Do something
});
```

Вы также можете передать ссылку на любой вызываемый объект или выделенный класс события, и он будет использоваться вместо этого.

```php
Event::listen('auth.login', [$this, 'LoginHandler']);
```

::: tip
Вызываемый метод может выбрать, указать все, некоторые или ни одного аргумента. В любом случае событие не выбросит ошибок, если только не указано слишком много аргументов.
:::

### Где регистрировать слушателей

Наиболее распространённое место — метод `boot` [файла регистрации плагина](../extending.md).

```php
class Plugin extends PluginBase
{
    // ...

    public function boot()
    {
        Event::listen(...);
    }
}
```

Альтернативно плагины могут предоставить файл с именем **init.php** в директории плагина, который вы можете использовать для размещения логики регистрации событий. Например:

```php
Event::listen(...);
```

Поскольку ни один из этих подходов не является изначально «правильным», выберите подход, который вам удобен, исходя из размера вашего приложения.

### Подписка с приоритетом

Вы также можете указать приоритет третьим аргументом при подписке на события. Слушатели с более высоким приоритетом будут запущены первыми, а слушатели с одинаковым приоритетом будут запущены в порядке подписки.

```php
// Run first
Event::listen('auth.login', function() { ... }, 10);

// Run second
Event::listen('auth.login', function() { ... }, 5);
```

### Остановка событий

Иногда вы можете захотеть остановить распространение события к другим слушателям. Вы можете сделать это, вернув `false` из вашего слушателя:

```php
Event::listen('auth.login', function($event) {
    // Handle the event

    return false;
});
```

### Слушатели с маской

При регистрации слушателя события вы можете использовать звёздочки для указания слушателей с маской. Слушатели с маской получают сначала имя вызванного события, а затем параметры, переданные через событие в виде массива.

Следующий слушатель обрабатывает все события, начинающиеся с `foo.`.

```php
Event::listen('foo.*', function($event, $params) {
    // Handle the event...
});
```

Вы можете использовать метод `Event::firing` для определения, какое именно событие было вызвано.

```php
Event::listen('foo.*', function($event, $params) {
    if (Event::firing() === 'foo.bar') {
        // ...
    }
});
```

## Вызов событий

Вы можете использовать метод `Event::fire` в любом месте вашего кода, чтобы сделать логику расширяемой. Это означает, что другие разработчики или даже ваш собственный внутренний код могут «подключиться» к этой точке кода и внедрить специфическую логику. Первым аргументом должно быть имя события.

```php
Event::fire('myevent');
```

Всегда хорошей практикой является добавление префикса пространства имён вашего плагина к именам событий — это предотвратит конфликты с другими плагинами.

```php
Event::fire('acme.blog.myevent');
```

Второй аргумент — массив значений, которые будут переданы в качестве аргументов слушателю, подписанному на событие.

```php
Event::fire('acme.blog.myevent', [$arg1, $arg2]);
```

Третий аргумент указывает, должно ли событие быть останавливающим, то есть должно ли оно остановиться, если возвращено «ненулевое» значение. По умолчанию этот аргумент установлен в false.

```php
Event::fire('acme.blog.myevent', [...], true);
```

Если событие является останавливающим, первое возвращённое значение будет захвачено.

```php
// Single result, event halted
$result = Event::fire('acme.blog.myevent', [...], true);
```

В противном случае возвращается коллекция всех ответов от всех событий в виде массива.

```php
// Multiple results, all events fired
$results = Event::fire('acme.blog.myevent', [...]);
```

## Передача аргументов по ссылке

При обработке или фильтрации значения, переданного в событие, вы можете добавить к переменной префикс `&` для передачи по ссылке. Это позволяет нескольким слушателям манипулировать результатом и передавать его следующему.

```php
Event::fire('cms.processContent', [&$content]);
```

При прослушивании события аргумент также должен быть объявлен с символом `&` в определении замыкания. В примере ниже к переменной `$content` будет добавлено «AB» к результату.

```php
Event::listen('cms.processContent', function (&$content) {
    $content = $content . 'A';
});

Event::listen('cms.processContent', function (&$content) {
    $content = $content . 'B';
});
```

### Отложенные события

Вызов событий может быть отложен [совместно с очередями](./queue.md). Используйте метод `Event::queue` для «постановки в очередь» события для вызова, но не его немедленного вызова.

```php
Event::queue('foo', [$user]);
```

Вы можете использовать метод `Event::flush` для сброса всех событий в очереди.

```php
Event::flush('foo');
```

## Использование классов в качестве слушателей

В некоторых случаях вы можете захотеть использовать класс для обработки события вместо Closure. Класс-слушатели события будут разрешены из [контейнера IoC приложения](./application.md), предоставляя вам полную мощь внедрения зависимостей для ваших слушателей.

### Подписка на отдельные методы

Класс события может быть зарегистрирован методом `Event::listen` как любой другой, передавая имя класса в виде строки.

```php
Event::listen('auth.login', LoginHandler::class);
```

По умолчанию будет вызван метод `handle` класса `LoginHandler`:

```php
class LoginHandler
{
    public function handle($data)
    {
        // ...
    }
}
```

Если вы не хотите использовать метод `handle` по умолчанию, вы можете указать имя метода, на который следует подписаться.

```php
Event::listen('auth.login', [LoginHandler::class, 'onLogin']);
```

### Подписка на весь класс

Подписчики событий — это классы, которые могут подписываться на несколько событий изнутри самого класса. Подписчики должны определить метод `subscribe`, которому будет передан экземпляр диспетчера событий.

```php
class UserEventHandler
{
    /**
     * subscribe register the listeners for the subscriber.
     * @param  Illuminate\Events\Dispatcher  $events
     * @return array
     */
    public function subscribe($events)
    {
        $events->listen('auth.login', [static::class, 'userLogin']);

        $events->listen('auth.logout', [static::class, 'userLogout']);
    }

    /**
     * userLogin handles user login events.
     */
    public function userLogin($event)
    {
        // ...
    }

    /**
     * userLogout handles user logout events.
     */
    public function userLogout($event)
    {
        // ...
    }
}
```

После определения подписчик может быть зарегистрирован методом `Event::subscribe`.

```php
Event::subscribe(new UserEventHandler);
```

Вы также можете использовать [контейнер IoC приложения](./application.md) для разрешения вашего подписчика. Для этого просто передайте имя вашего подписчика в метод `subscribe`.

```php
Event::subscribe(UserEventHandler::class);
```

## Трейт Event Emitter

Иногда вы хотите привязать события к одному экземпляру объекта. Вы можете использовать альтернативную систему событий, реализовав трейт `October\Rain\Support\Traits\Emitter` в вашем классе.

```php
class UserManager
{
    use \October\Rain\Support\Traits\Emitter;
}
```

Этот трейт предоставляет метод для прослушивания событий с помощью `bindEvent`.

```php
$manager = new UserManager;
$manager->bindEvent('user.beforeRegister', function($user) {
    // Check if the $user is a spammer
});
```

Метод `fireEvent` используется для вызова событий.

```php
$manager = new UserManager;
$manager->fireEvent('user.beforeRegister', [$user]);
```

Эти события будут происходить только на локальном объекте, в отличие от глобальных событий.
