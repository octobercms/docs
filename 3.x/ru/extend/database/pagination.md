# Пагинация

## Основы использования

Существует несколько способов постраничной разбивки записей, наиболее распространённый — вызов метода `paginate` для запроса или модели. Это вернёт специальную постраничную коллекцию с дополнительными методами для отображения результатов.

### Пагинация результатов конструктора запросов

Существует несколько способов постраничной разбивки элементов. Самый простой — использовать метод `paginate` [конструктора запросов](./query.md) или [запроса модели](./model.md). Метод `paginate` автоматически устанавливает правильные limit и offset на основе текущей страницы, просматриваемой пользователем. По умолчанию текущая страница определяется по значению параметра `?page` в строке запроса HTTP-запроса. Конечно, это значение определяется автоматически и автоматически вставляется в ссылки, генерируемые пагинатором.

Для начала рассмотрим вызов метода `paginate` для запроса. В этом примере единственным аргументом, переданным в `paginate`, является количество элементов, которые вы хотите отображать «на странице». В данном случае укажем, что мы хотим отображать `15` элементов на странице.

```php
$users = Db::table('users')->paginate(15);
```

::: warning
В настоящее время операции пагинации, использующие оператор `groupBy`, не могут выполняться эффективно. Если вам нужно использовать `groupBy` с постраничным набором результатов, рекомендуется выполнить запрос к базе данных и создать пагинатор вручную.
:::

#### Простая пагинация

Если вам нужно отображать только простые ссылки «Далее» и «Назад» в представлении пагинации, вы можете использовать метод `simplePaginate` для выполнения более эффективного запроса. Это очень полезно для больших наборов данных, если вам не нужно отображать ссылку на каждый номер страницы при рендеринге представления.

```php
$users = Db::table('users')->simplePaginate(15);
```

#### Указание номера страницы

По умолчанию пагинатор берёт номер текущей страницы из параметра строки запроса `?page`. Вы можете указать номер страницы с помощью методов `paginateAtPage` и `simplePaginateAtPage`. Количество элементов на странице передаётся первым аргументом, а номер текущей страницы — вторым.

```php
$recordsPerPage = 15;
$currentPage = 1;

$users = Db::table('users')->paginateAtPage($recordsPerPage, $currentPage);

$users = Db::table('users')->simplePaginateAtPage($recordsPerPage, $currentPage);
```

#### Указание пользовательского имени параметра запроса

Методы `paginateCustom` и `simplePaginateCustom` используются для указания пользовательского имени параметра строки запроса. Следующий пример будет использовать параметр `?secondPage` для определения номера страницы.

```php
$recordsPerPage = 15;

$users = Db::table('users')->paginateCustom($recordsPerPage, 'secondPage');

$users = Db::table('users')->simplePaginateCustom($recordsPerPage, 'secondPage');
```

### Пагинация результатов модели

Вы также можете использовать пагинацию для запросов [модели базы данных](./model.md). В этом примере мы разобьём модель `User` по `15` элементов на странице. Как видите, синтаксис практически идентичен пагинации результатов конструктора запросов:

```php
$users = User::paginate(15);
```

Конечно, вы можете вызвать `paginate` после установки других ограничений запроса, таких как условия `where`:

```php
$users = User::where('votes', '>', 100)->paginate(15);
```

Вы также можете использовать метод `simplePaginate` при пагинации моделей:

```php
$users = User::where('votes', '>', 100)->simplePaginate(15);
```

Вы можете указать номер страницы вручную, передав второй аргумент. Здесь мы разбиваем по `15` элементов на странице, указывая, что находимся на странице `2`:

```php
$users = User::where('votes', '>', 100)->paginate(15, 2);
```

### Создание пагинатора вручную

Иногда вам может понадобиться создать экземпляр пагинатора вручную, передав ему массив элементов. Вы можете сделать это, создав экземпляр `Illuminate\Pagination\Paginator` или `Illuminate\Pagination\LengthAwarePaginator`, в зависимости от ваших потребностей.

Класс `Paginator` не нуждается в информации об общем количестве элементов в наборе результатов, поэтому он не имеет методов для получения индекса последней страницы. `LengthAwarePaginator` принимает почти те же аргументы, что и `Paginator`, однако ему требуется общее количество элементов в наборе результатов.

Другими словами, `Paginator` соответствует методу `simplePaginate` конструктора запросов и моделей, а `LengthAwarePaginator` соответствует методу `paginate`.

При ручном создании экземпляра пагинатора вы должны самостоятельно «нарезать» массив результатов, который передаёте пагинатору. Если вы не знаете, как это сделать, обратитесь к PHP-функции [array_slice](http://php.net/manual/en/function.array-slice.php).

## Отображение результатов в представлении

Когда вы вызываете методы `paginate` или `simplePaginate` для конструктора запросов или запроса модели, вы получаете экземпляр пагинатора. При вызове метода `paginate` вы получите экземпляр `Illuminate\Pagination\LengthAwarePaginator`. При вызове метода `simplePaginate` вы получите экземпляр `Illuminate\Pagination\Paginator`. Эти объекты предоставляют несколько методов, описывающих набор результатов. Помимо этих вспомогательных методов, экземпляры пагинатора являются итераторами и могут быть перебраны как массив.

После получения результатов вы можете отобразить их и отрендерить ссылки на страницы с помощью PHP или [Twig-функции Pager](../../markup/function/pager.md).

```php
<div class="container">
    <?php foreach ($users as $user): ?>
        <?= $user->name ?>
    <?php endforeach ?>
</div>

<?= $users->links() ?>
```

Метод `render` отрендерит ссылки на остальные страницы набора результатов. Каждая из этих ссылок уже будет содержать правильную переменную строки запроса `?page`. HTML, генерируемый методом `render`, совместим с CSS-фреймворком [Bootstrap](https://getbootstrap.com).

::: tip
При вызове метода `render` из Twig-шаблона обязательно используйте фильтр `|raw`, чтобы HTML-ссылки не были экранированы.
:::

#### Настройка URI пагинатора

Метод `setPath` позволяет настроить URI, используемый пагинатором при генерации ссылок. Например, если вы хотите, чтобы пагинатор генерировал ссылки вида `http://example.tld/custom/url?page=N`, передайте `custom/url` в метод `setPath`:

```php
$users = User::paginate(15);
$users->setPath('custom/url');
echo $users->render();
```

#### Добавление параметров к ссылкам пагинации

Вы можете добавить параметры к строке запроса ссылок пагинации с помощью метода `appends`. Например, чтобы добавить `&sort=votes` к каждой ссылке пагинации, выполните следующий вызов `appends`.

```php
echo $users->appends(['sort' => 'votes'])->render();
```

Если вы хотите добавить «хэш-фрагмент» к URL-адресам пагинатора, используйте метод `fragment`. Например, чтобы добавить `#foo` в конец каждой ссылки пагинации, выполните следующий вызов метода `fragment`.

```php
echo $users->fragment('foo')->render();
```

#### Дополнительные вспомогательные методы

Вы также можете получить дополнительную информацию о пагинации с помощью следующих методов экземпляров пагинатора:

```php
$results->count()
$results->currentPage()
$results->hasMorePages()
$results->lastPage() // Not available when using simplePaginate
$results->nextPageUrl()
$results->perPage()
$results->previousPageUrl()
$results->total() // Not available when using simplePaginate
$results->url($page)
```

## Преобразование результатов в JSON

Классы результатов пагинатора реализуют контракт `Illuminate\Contracts\Support\JsonableInterface` и предоставляют метод `toJson`, поэтому очень просто преобразовать результаты пагинации в JSON. Вы также можете преобразовать экземпляр пагинатора в JSON, просто вернув его из маршрута или обработчика AJAX:

```php
Route::get('users', function () {
    return User::paginate();
});
```

JSON от пагинатора будет включать метаинформацию, такую как `total`, `current_page`, `last_page` и другие. Фактические объекты результатов будут доступны через ключ `data` в JSON-массиве. Вот пример JSON, создаваемого при возврате экземпляра пагинатора из маршрута:

#### Пример JSON пагинатора

```json
{
    "total": 50,
    "per_page": 15,
    "current_page": 1,
    "last_page": 4,
    "next_page_url": "http://octobercms.app?page=2",
    "prev_page_url": null,
    "from": 1,
    "to": 15,
    "data":[
        {
            // Result Object
        },
        {
            // Result Object
        }
    ]
}
```
