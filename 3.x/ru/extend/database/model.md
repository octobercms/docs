# Запросы модели

При запросе данных из базы данных модель получает значения в первую очередь с помощью методов `get` или `first`, в зависимости от того, хотите ли вы получить несколько моделей или одну модель соответственно. Запросы, производные от модели, возвращают экземпляр `October\Rain\Database\Builder`.

## Получение нескольких моделей

После создания модели и [соответствующей таблицы базы данных](./structure.md) вы готовы начать получать данные из базы данных. Представьте каждую модель как мощный [конструктор запросов](./query.md), позволяющий запрашивать таблицу базы данных, связанную с моделью.

```php
$flights = Flight::all();
```

### Доступ к значениям столбцов

Если у вас есть экземпляр модели, вы можете получить доступ к значениям столбцов модели, обращаясь к соответствующему свойству. Например, давайте пройдём по каждому экземпляру `Flight`, возвращённому нашим запросом, и выведем значение столбца `name`.

```php
foreach ($flights as $flight) {
    echo $flight->name;
}
```

### Добавление дополнительных ограничений

Метод `all` вернёт все результаты из таблицы модели. Поскольку каждая модель служит [конструктором запросов](./query.md), вы также можете добавлять ограничения к запросам, а затем использовать метод `get` для получения результатов:

```php
$flights = Flight::where('active', 1)
    ->orderBy('name', 'desc')
    ->take(10)
    ->get();
```

::: tip
Поскольку модели являются конструкторами запросов, вам следует ознакомиться со всеми доступными методами [конструктора запросов](./query.md). Вы можете использовать любой из этих методов в запросах модели.
:::

### Коллекции

Для методов, таких как `all` и `get`, которые возвращают несколько результатов, будет возвращён экземпляр `Collection`. Этот класс предоставляет [множество полезных методов](./collection.md) для работы с вашими результатами. Конечно, вы можете просто перебирать эту коллекцию как массив.

```php
foreach ($flights as $flight) {
    echo $flight->name;
}
```

### Разбиение результатов на части

Если вам нужно обработать тысячи записей, используйте команду `chunk`. Метод `chunk` получит «часть» моделей, передавая их заданному `Closure` для обработки. Использование метода `chunk` позволяет экономить память при работе с большими наборами результатов.

```php
Flight::chunk(200, function ($flights) {
    foreach ($flights as $flight) {
        //
    }
});
```

Первый аргумент, передаваемый методу — это количество записей, которые вы хотите получить на каждую «часть». Closure, передаваемое в качестве второго аргумента, будет вызвано для каждой части, полученной из базы данных.

## Получение одной модели

Помимо получения всех записей для данной таблицы, вы также можете получить отдельные записи с помощью `find` и `first`. Вместо коллекции моделей эти методы возвращают один экземпляр модели.

```php
// Retrieve a model by its primary key
$flight = Flight::find(1);

// Retrieve the first model matching the query constraints
$flight = Flight::where('active', 1)->first();
```

### Исключения «Не найдено»

Иногда вы можете захотеть выбросить исключение, если модель не найдена. Это особенно полезно в маршрутах или контроллерах. Методы `findOrFail` и `firstOrFail` получат первый результат запроса. Однако, если результат не найден, будет выброшено исключение `Illuminate\Database\Eloquent\ModelNotFoundException`.

```php
$model = Flight::findOrFail(1);

$model = Flight::where('legs', '>', 100)->firstOrFail();
```

При [разработке API](../system/routing.md), если исключение не перехвачено, HTTP-ответ `404` автоматически отправляется обратно пользователю, поэтому нет необходимости писать явные проверки для возврата ответов `404` при использовании этих методов.

```php
Route::get('/api/flights/{id}', function ($id) {
    return Flight::findOrFail($id);
});
```

### Получение агрегатов

Вы также можете использовать `count`, `sum`, `max` и другие [агрегатные функции](./query.md), предоставляемые конструктором запросов. Эти методы возвращают соответствующее скалярное значение вместо полного экземпляра модели:

```php
$count = Flight::where('active', 1)->count();

$max = Flight::where('active', 1)->max('price');
```

## Вставка и обновление моделей

Вставка и обновление данных — это основная функция моделей, она делает процесс простым по сравнению с традиционными SQL-операторами.

### Базовая вставка

Для создания новой записи в базе данных просто создайте новый экземпляр модели, установите атрибуты модели, затем вызовите метод `save`:

```php
$flight = new Flight;
$flight->name = 'Sydney to Canberra';
$flight->save();
```

В этом примере мы просто создаём новый экземпляр модели `Flight` и присваиваем атрибут `name`. При вызове метода `save` запись будет вставлена в базу данных. Временные метки `created_at` и `updated_at` также будут автоматически установлены, поэтому нет необходимости устанавливать их вручную.

### Базовое обновление

Метод `save` может также использоваться для обновления моделей, которые уже существуют в базе данных. Для обновления модели вы должны получить её, установить любые атрибуты, которые хотите обновить, а затем вызвать метод `save`. Опять же, временная метка `updated_at` будет автоматически обновлена, поэтому нет необходимости вручную устанавливать её значение:

```php
$flight = Flight::find(1);
$flight->name = 'Darwin to Adelaide';
$flight->save();
```

Обновления также могут быть выполнены для любого количества моделей, соответствующих данному запросу. В этом примере все рейсы, которые `active` и имеют `destination` равный `San Diego`, будут отмечены как задержанные:

```php
Flight::where('is_active', true)
    ->where('destination', 'Perth')
    ->update(['delayed' => true]);
```

Метод `update` ожидает массив пар столбцов и значений, представляющих столбцы, которые должны быть обновлены.

### Массовое присваивание

Вы также можете использовать метод `create` для сохранения новой модели в одну строку. Вставленный экземпляр модели будет возвращён вам из метода. Однако перед этим вам необходимо указать свойство `fillable` или `guarded` в модели, так как все модели защищены от массового присваивания. Обратите внимание, что ни `fillable`, ни `guarded` не влияют на отправку форм панели управления, а только на использование метода `create` или `fill`.

Уязвимость массового присваивания возникает, когда пользователь передаёт неожиданный HTTP-параметр через запрос, и этот параметр изменяет столбец в вашей базе данных, который вы не ожидали. Например, злоумышленник может отправить параметр `is_admin` через HTTP-запрос, который затем передаётся в метод `create` вашей модели, позволяя пользователю повысить себя до администратора.

Для начала вы должны определить, какие атрибуты модели вы хотите сделать доступными для массового присваивания. Вы можете сделать это с помощью свойства `$fillable` модели. Например, сделаем атрибут `name` нашей модели `Flight` доступным для массового присваивания:

```php
class Flight extends Model
{
    /**
     * @var array fillable attributes that are mass assignable.
     */
    protected $fillable = ['name'];
}
```

После того как мы сделали атрибуты доступными для массового присваивания, мы можем использовать метод `create` для вставки новой записи в базу данных. Метод `create` возвращает сохранённый экземпляр модели:

```php
$flight = Flight::create(['name' => 'Flight 10']);
```

В то время как `$fillable` служит «белым списком» атрибутов, доступных для массового присваивания, вы также можете использовать `$guarded`. Свойство `$guarded` должно содержать массив атрибутов, которые вы не хотите делать доступными для массового присваивания. Все остальные атрибуты, не входящие в массив, будут доступны для массового присваивания. Таким образом, `$guarded` функционирует как «чёрный список». Конечно, вы должны использовать либо `$fillable`, либо `$guarded` — не оба:

```php
class Flight extends Model
{
    /**
     * The attributes that aren't mass assignable.
     *
     * @var array
     */
    protected $guarded = ['price'];
}
```

В приведённом выше примере все атрибуты, **кроме `price`**, будут доступны для массового присваивания.

### Другие методы создания

Иногда вы можете захотеть только создать новый экземпляр модели. Вы можете сделать это с помощью метода `make`. Метод `make` просто вернёт новый экземпляр без сохранения или создания чего-либо.

```php
$flight = Flight::make(['name' => 'Flight 10']);

// Functionally the same as...
$flight = new Flight;
$flight->fill(['name' => 'Flight 10']);
```

Есть ещё два метода, которые вы можете использовать для создания моделей путём массового присваивания атрибутов: `firstOrCreate` и `firstOrNew`. Метод `firstOrCreate` попытается найти запись в базе данных, используя заданные пары столбец/значение. Если модель не может быть найдена в базе данных, будет вставлена запись с заданными атрибутами.

Метод `firstOrNew`, как и `firstOrCreate`, попытается найти запись в базе данных, соответствующую заданным атрибутам. Однако, если модель не найдена, будет возвращён новый экземпляр модели. Обратите внимание, что модель, возвращённая `firstOrNew`, ещё не сохранена в базе данных. Вам нужно будет вызвать `save` вручную для её сохранения:

```php
// Retrieve the flight by the attributes, otherwise create it
$flight = Flight::firstOrCreate(['name' => 'Flight 10']);

// Retrieve the flight by the attributes, or instantiate a new instance
$flight = Flight::firstOrNew(['name' => 'Flight 10']);
```

## Удаление моделей

Для удаления модели вызовите метод `delete` на экземпляре модели:

```php
$flight = Flight::find(1);

$flight->delete();
```

В приведённом выше примере мы получаем модель из базы данных перед вызовом метода `delete`. Однако, если вы знаете первичный ключ модели, вы можете удалить модель без её предварительного получения. Для этого вызовите метод `destroy`:

```php
Flight::destroy(1);

Flight::destroy([1, 2, 3]);

Flight::destroy(1, 2, 3);
```

Вы также можете выполнить запрос на удаление для набора моделей. В этом примере мы удалим все рейсы, отмеченные как неактивные:

```php
$deletedRows = Flight::where('active', 0)->delete();
```

::: warning
Важно отметить, что [события модели](../system/models.md) не будут вызваны при удалении записей напрямую из запроса.
:::

## Области запросов

Области позволяют вам определять общие наборы ограничений, которые вы можете легко повторно использовать в приложении. Например, вам может часто требоваться получить всех пользователей, которые считаются «популярными». Для определения области просто добавьте префикс `scope` к методу модели.

```php
class User extends Model
{
    /**
     * scopePopular query to only include popular users.
     */
    public function scopePopular($query)
    {
        return $query->where('votes', '>', 100);
    }

    /**
     * scopeActive query to only include active users.
     */
    public function scopeActive($query)
    {
        return $query->where('is_active', 1);
    }
}
```

После определения области вы можете вызывать методы области при запросе модели. Однако вам не нужно включать префикс `scope` при вызове метода. Вы можете даже объединять вызовы различных областей, например:

```php
$users = User::popular()->active()->orderBy('created_at')->get();
```

Иногда вы можете захотеть определить область, принимающую параметры. Для начала просто добавьте дополнительные параметры к вашей области. Параметры области должны быть определены после аргумента `$query`:

```php
class User extends Model
{
    /**
     * Scope a query to only include users of a given type.
     */
    public function scopeApplyType($query, $type)
    {
        return $query->where('type', $type);
    }
}
```

Теперь вы можете передавать параметры при вызове области:

```php
$users = User::applyType('admin')->get();
```
