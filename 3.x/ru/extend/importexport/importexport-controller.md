# Контроллер импорта и экспорта

Класс `Backend\Behaviors\ImportExportController` — это поведение контроллера, предоставляющее функции для импорта и экспорта данных. Поведение предоставляет две страницы: Импорт и Экспорт. Страница Импорт позволяет пользователю загрузить CSV-файл и сопоставить столбцы с базой данных. Страница Экспорт делает обратное и позволяет пользователю скачать столбцы из базы данных в виде CSV-файла. Поведение предоставляет действия контроллера `import()` и `export()`.

Конфигурация поведения импорта и экспорта определяется в двух частях, каждая часть зависит от специального класса модели вместе с файлом определения списка и полей формы. Для использования поведения вы должны добавить его в свойство `$implement` класса контроллера. Также должно быть определено свойство класса `$importExportConfig`, и его значение должно ссылаться на YAML-файл, используемый для настройки свойств поведения.

```php
namespace Acme\Shop\Controllers;

class Products extends Controller
{
    public $implement = [
        \Backend\Behaviors\ImportExportController::class
    ];

    public $importExportConfig = 'config_import_export.yaml';

    // [...]
}
```

## Настройка поведения

Файл конфигурации, указанный в свойстве `$importExportConfig`, определяется в формате YAML. Файл должен быть размещён в [директории представлений](../system/views.md) контроллера. Ниже приведён пример файла конфигурации.

```yaml
# config_import_export.yaml
import:
    title: Import Subscribers
    modelClass: Acme\Campaign\Models\SubscriberImport
    list: $/acme/campaign/models/subscriber/columns.yaml

export:
    title: Export Subscribers
    modelClass: Acme\Campaign\Models\SubscriberExport
    list: $/acme/campaign/models/subscriber/columns.yaml
```

Ниже перечислены необязательные свойства конфигурации. Определяйте их, если хотите, чтобы поведение поддерживало страницу импорта или страницу экспорта, или обе.

Свойство | Описание
------------- | -------------
**defaultRedirect** | используется как резервная страница перенаправления, когда конкретная страница перенаправления не определена.
**import** | массив конфигурации или ссылка на файл конфигурации для страницы Импорта.
**export** | массив конфигурации или ссылка на файл конфигурации для страницы Экспорта.
**defaultFormatOptions** | массив конфигурации или ссылка на файл конфигурации для параметров формата CSV по умолчанию.

### Страница импорта

Для поддержки страницы Импорта добавьте следующую конфигурацию в YAML-файл.

```yaml
import:
    title: Import Subscribers
    modelClass: Acme\Campaign\Models\SubscriberImport
    list: $/acme/campaign/models/subscriberimport/columns.yaml
    redirect: acme/campaign/subscribers
```

Следующие свойства конфигурации поддерживаются для страницы Импорта.

Свойство | Описание
------------- | -------------
**title** | заголовок страницы, может ссылаться на [строку локализации](../system/localization.md).
**list** | определяет доступные столбцы списка для импорта.
**form** | предоставляет дополнительные поля, используемые как параметры импорта, необязательно.
**redirect** | страница перенаправления после завершения импорта, необязательно.
**permissions** | разрешения пользователя, необходимые для выполнения операции, необязательно.

### Страница экспорта

Для поддержки страницы Экспорта добавьте следующую конфигурацию в YAML-файл.

```yaml
export:
    title: Export Subscribers
    modelClass: Acme\Campaign\Models\SubscriberExport
    list: $/acme/campaign/models/subscriberexport/columns.yaml
    redirect: acme/campaign/subscribers
```

Следующие свойства конфигурации поддерживаются для страницы Экспорта:

Свойство | Описание
------------- | -------------
**title** | заголовок страницы, может ссылаться на [строку локализации](../system/localization.md).
**fileName** | имя файла для экспортируемого файла без расширения. По умолчанию: `export`
**list** | определяет доступные столбцы списка для экспорта.
**form** | предоставляет дополнительные поля, используемые как параметры экспорта, необязательно.
**redirect** | страница перенаправления после завершения экспорта, необязательно.
**useList** | установите в true или значение определения списка для включения интеграции со списками. По умолчанию: `false`.

### Параметры формата

Для переопределения параметров формата по умолчанию добавьте следующую конфигурацию в YAML-файл:

```yaml
defaultFormatOptions:
    fileFormat: json
```

Следующие свойства конфигурации (все необязательные) поддерживаются для параметров формата, включая их применимый тип формата.

Свойство | Описание | Формат
-------- | ----------- | ------
**fileFormat** | Формат файла: `json`, `csv` или `csv_custom`, по умолчанию: `json`. |
**customJson** | Использовать пользовательский формат для типа `json`. | JSON
**firstRowTitles** | Первая строка содержит заголовки, только импорт. | CSV
**delimiter** | Символ-разделитель. | CSV (Custom)
**enclosure** | Символ-ограничитель. | CSV (Custom)
**escape** | Символ экранирования. | CSV (Custom)
**encoding** | Кодировка файла, только импорт. | CSV (Custom)

## Представления импорта и экспорта

Для каждой функции страницы импорта и экспорта вы должны предоставить [файл представления](../system/views.md) с соответствующим именем — **import.htm** и **export.htm**.

Поведение импорта/экспорта добавляет два метода в класс контроллера: `importRender` и `exportRender`. Эти методы рендерят разделы импорта и экспорта согласно файлу конфигурации YAML, описанному выше.

### Представление импорта

Представление **import.htm** отображает страницу Импорта, которая позволяет пользователям импортировать данные. Типичная страница Импорта содержит хлебные крошки, сам раздел импорта и кнопки отправки. Атрибут **data-request** должен ссылаться на AJAX-обработчик `onImport`, предоставляемый поведением. Ниже приведено содержимое типичного файла представления import.htm.

```php
<?= Form::open(['class' => 'layout']) ?>

    <div class="layout-row">
        <?= $this->importRender() ?>
    </div>

    <div class="form-buttons">
        <button
            type="submit"
            data-control="popup"
            data-handler="onImportLoadForm"
            data-keyboard="false"
            class="btn btn-primary">
            Import records
        </button>
    </div>

<?= Form::close() ?>
```

### Представление экспорта

Представление **export.htm** отображает страницу Экспорта, которая позволяет пользователям экспортировать файл из базы данных. Типичная страница Экспорта содержит хлебные крошки, сам раздел экспорта и кнопки отправки. Атрибут **data-request** должен ссылаться на AJAX-обработчик `onExport`, предоставляемый поведением. Ниже приведено содержимое типичной формы export.htm.

```php
<?= Form::open(['class' => 'layout']) ?>

    <div class="layout-row">
        <?= $this->exportRender() ?>
    </div>

    <div class="form-buttons">
        <button
            type="submit"
            data-control="popup"
            data-handler="onExportLoadForm"
            data-keyboard="false"
            class="btn btn-primary">
            Export records
        </button>
    </div>

<?= Form::close() ?>
```

## Интеграция с поведением списка

Существует альтернативный подход к экспорту данных, который использует [поведение списка](../lists/list-controller.md) для предоставления данных экспорта. Для использования этой функции вы должны добавить определение `Backend\Behaviors\ListController` в поле `$implement` класса контроллера. Вам не нужно использовать представление экспорта, и все настройки будут взяты из списка. Вот единственная необходимая конфигурация:

```yaml
export:
    useList: true
```

Затем просто добавьте кнопку экспорта в [панель инструментов списка](../lists/list-controller.md):

```php
<a
    href="<?= Backend::url('acme/campaign/subscribers/export') ?>"
    class="btn btn-default oc-icon-download">
    Export Records
</a>
```

Аналогично, для добавления кнопки импорта код будет выглядеть так:

```php
<a
    href="<?= Backend::url('acme/campaign/subscribers/import') ?>"
    class="btn btn-default oc-icon-upload">
    Import Records
</a>
```


Если вы используете [множественные определения списков](../lists/list-controller.md), вы можете указать определение списка.

```yaml
export:
    useList: orders
    fileName: orders.csv
```

Параметр `useList` также поддерживает расширенные свойства конфигурации.

```yaml
export:
    useList:
        definition: orders
        raw: true
```

Поддерживаются следующие свойства конфигурации:

Свойство | Описание
------------- | -------------
**definition** | определение списка, из которого берутся записи, необязательно.
**raw** | выводить необработанные значения атрибутов из записи, по умолчанию: false.
