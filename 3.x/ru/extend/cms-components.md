# Создание CMS-компонентов

Файлы и директории компонентов находятся в поддиректории **components** директории плагина. Каждый компонент имеет PHP-файл, определяющий класс компонента, и необязательную директорию частичных представлений компонента. Имя директории частичных представлений совпадает с именем класса компонента в нижнем регистре. Пример структуры директории компонента:

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `components`
|           |   ├── blogposts  _← Директория частичных представлений_
|           |   |   └── default.htm  _← Разметка по умолчанию (необязательно)_
|           |   └── BlogPosts.php  _← Класс компонента_
|           └── Plugin.php
:::

Компоненты должны быть [зарегистрированы в файле регистрации плагина](../extend/extending.md) с помощью метода `registerComponents`. Компоненты могут быть настроены с помощью свойств и их [определений типов Inspector](../element/inspector-types.md).

## Определение класса компонента

Команда `create:component` создаёт новый класс компонента и представление компонента по умолчанию. Первый аргумент указывает имя автора и плагина. Второй аргумент указывает имя класса компонента.

```bash
php artisan create:component Acme.Blog BlogPosts
```

Файл класса компонента определяет функциональность и свойства компонента. Имя файла класса компонента должно совпадать с именем класса компонента. Классы компонентов должны наследовать класс `Cms\Classes\ComponentBase`. Компонент из следующего примера должен быть определён в файле **plugins/acme/blog/components/BlogPosts.php**.

```php
namespace Acme\Blog\Components;

class BlogPosts extends \Cms\Classes\ComponentBase
{
    public function componentDetails()
    {
        return [
            'name' => 'Blog Posts',
            'description' => 'Displays a collection of blog posts.',
            'icon' => 'icon-puzzle-piece'
        ];
    }

    /**
     * posts becomes available on the page as {{ component.posts }}
     */
    public function posts()
    {
        return ['First Post', 'Second Post', 'Third Post'];
    }
}
```

Метод `componentDetails` является обязательным. Метод должен возвращать массив с двумя ключами: `name` и `description`. Имя и описание отображаются в пользовательском интерфейсе панели управления CMS.

Когда этот [компонент прикреплён к странице или макету](../cms/themes/components.md), свойства и методы класса становятся доступными на странице через переменную компонента, имя которой совпадает с коротким именем компонента или псевдонимом. Например, если компонент BlogPost из предыдущего примера определён на странице с его коротким именем:

```ini
url = "/blog"

[blogPosts]
==
```

Вы сможете обращаться к его методу `posts` через переменную `blogPosts`. Обратите внимание, что Twig поддерживает нотацию свойств для методов, поэтому вам не нужно использовать скобки.

```twig
{% for post in blogPosts.posts %}
    {{ post }}
{% endfor %}
```

### Регистрация компонента

Компоненты должны быть зарегистрированы путём переопределения метода `registerComponents` в [файле регистрации плагина](../extend/extending.md). Это сообщает CMS о компоненте и предоставляет **короткое имя** для его использования. Пример регистрации компонента:

```php
public function registerComponents()
{
    return [
        \October\Demo\Components\Todo::class => 'demoTodo'
    ];
}
```

Это зарегистрирует класс компонента Todo с псевдонимом по умолчанию **demoTodo**. Более подробная информация об использовании компонентов находится в [статье о CMS-компонентах](../cms/themes/components.md).

## Свойства компонента

При добавлении компонента на страницу или в макет вы можете настроить его с помощью свойств. Свойства определяются методом `defineProperties` класса компонента. В следующем примере показано, как определить свойство компонента с типом Inspector **string**.

```php
public function defineProperties()
{
    return [
        'maxItems' => [
            'title' => 'Max items',
            'description' => 'The most amount of todo items allowed',
            'default' => 10,
            'type' => 'string',
            'validation' => [
                'regex' => [
                    'message' => 'The Max Items property can contain only numeric symbols.',
                    'pattern' => '^[0-9]+$'
                ]
            ]
        ]
    ];
}
```

Метод должен возвращать массив с ключами свойств в качестве индексов и параметрами свойств в качестве значений. Ключи свойств используются для доступа к значениям свойств компонента внутри класса компонента.

::: tip
Параметры свойств и доступные типы описаны в [статье о типах Inspector](../element/inspector-types.md).
:::

Внутри компонента вы можете прочитать значение свойства с помощью метода `property`:

```php
$this->property('maxItems');
```

Если значение свойства не определено, вы можете передать значение по умолчанию вторым параметром метода `property`:

```php
$this->property('maxItems', 6);
```

Вы также можете загрузить все свойства как массив:

```php
$properties = $this->getProperties();
```

Для доступа к свойству из Twig-частичных представлений компонента используйте переменную `__SELF__`, которая ссылается на объект компонента:

```twig
{{ __SELF__.property('maxItems') }}
```

## Параметры маршрутизации

Компоненты могут напрямую обращаться к значениям параметров маршрутизации, определённым в [URL страницы](../cms/themes/pages.md).

```php
// Returns the URL segment value, eg: /page/:post_id
$postId = $this->param('post_id');
```

В некоторых случаях свойство компонента может быть жёстко заданным значением или ссылаться на значение из URL. В этом примере с жёстко заданным значением используется запись блога с идентификатором `2`:

```ini
url = "/blog/hard-coded-page"

[blogPost]
id = "2"
```

Альтернативно значение может быть динамически получено из URL страницы с помощью [внешнего значения свойства компонента](../cms/themes/components.md).

```ini
url = "/blog/:my_custom_parameter"

[blogPost]
id = "{{ :my_custom_parameter }}"
```

В обоих случаях значение можно получить с помощью метода `property`:

```php
$this->property('id');
```

Если вам нужно получить имя параметра маршрутизации:

```php
// Returns "my_custom_parameter"
$this->paramName('id');
```

## Обработка цикла выполнения страницы

Компоненты могут участвовать в событиях цикла выполнения страницы, переопределяя метод `onRun` в классе компонента. CMS-контроллер выполняет этот метод каждый раз при загрузке страницы или макета. Внутри метода вы можете внедрять переменные в среду Twig через свойство `page`:

```php
public function onRun()
{
    // This code will be executed when the page or layout is
    // loaded and the component is attached to it.

    $this->page['var'] = 'value'; // Inject some variable to the page
}
```

### Обработчики жизненного цикла выполнения страницы

При загрузке страницы October выполняет функции-обработчики, которые могут быть определены в PHP-секции макета и страницы, а также в классах компонентов. Последовательность выполнения обработчиков следующая.

1. Функция `onInit()` макета.
1. Функция `onInit()` страницы.
1. Функция `onStart()` макета.
1. Метод `onRun()` компонентов макета.
1. Функция `onBeforePageStart()` макета.
1. Функция `onStart()` страницы.
1. Метод `onRun()` компонентов страницы.
1. Функция `onEnd()` страницы.
1. Функция `onEnd()` макета.

### Инициализация компонента

Иногда вам может потребоваться выполнить код в момент первого создания экземпляра класса компонента. Вы можете переопределить метод `init` в классе компонента для обработки любой логики инициализации — он выполнится до AJAX-обработчиков и до жизненного цикла выполнения страницы. Например, этот метод может использоваться для динамического прикрепления другого компонента к странице.

```php
public function init()
{
    $this->addComponent(\Acme\Blog\Components\BlogPosts::class, 'blogPosts');
}
```

### Остановка с ответом

Как и все методы в [жизненном цикле выполнения макета](../cms/themes/layouts.md), если метод `onRun` компонента возвращает значение, цикл останавливается в этой точке и ответ возвращается в браузер. Здесь мы возвращаем сообщение об отказе в доступе с помощью фасада `Response`:

```php
public function onRun()
{
    if (true) {
        return Response::make('Access denied!', 403);
    }
}
```

Вы также можете вернуть ответ 404 из метода `onRun`:

```php
public function onRun()
{
    if (true) {
        $this->setStatusCode(404);
        return $this->controller->run('404');
    }
}
```

## AJAX-обработчики

Компоненты могут содержать AJAX-обработчики событий. Они определяются в классе компонента точно так же, как в [коде страницы или макета](../cms/ajax/handlers.md). Пример метода AJAX-обработчика, определённого в классе компонента:

```php
public function onAddItem()
{
    $value1 = post('value1');
    $value2 = post('value2');
    $this->page['result'] = $value1 + $value2;
}
```

Если псевдоним этого компонента — *demoTodo*, к обработчику можно обратиться как `demoTodo::onAddItem`. Подробнее об использовании AJAX с компонентами см. в [статье об AJAX-обработчиках](../cms/ajax/handlers.md).

## Разметка по умолчанию

Все компоненты могут поставляться с разметкой по умолчанию, которая используется при включении компонента на страницу тегом `{% component %}`, хотя это необязательно. Разметка по умолчанию хранится в **директории частичных представлений компонента**, имя которой совпадает с именем класса компонента в нижнем регистре.

Разметка по умолчанию компонента должна быть размещена в файле **default.htm**. Например, разметка по умолчанию компонента Demo ToDo определена в файле **/plugins/october/demo/components/todo/default.htm**. Затем она может быть вставлена в любое место страницы тегом `{% component %}`:

::: cmstemplate
```ini
url = "/todo"

[demoTodo]
```
```twig
{% component 'demoTodo' %}
```
:::

Разметка по умолчанию также может принимать параметры, переопределяющие свойства компонента на момент рендеринга.

```twig
{% component 'demoTodo' maxItems="7" %}
```

Эти свойства не будут доступны в методе `onRun`, поскольку они устанавливаются после завершения цикла страницы. Вместо этого они могут быть обработаны путём переопределения метода `onRender` в классе компонента. CMS-контроллер выполняет этот метод перед рендерингом разметки по умолчанию.

```php
public function onRender()
{
    // This code will be executed before the default component
    // markup is rendered on the page or layout.

    $this->page['var'] = 'Maximum items allowed: ' . $this->property('maxItems');
}
```

## Частичные представления компонента

В дополнение к разметке по умолчанию компоненты также могут предоставлять дополнительные частичные представления, которые могут использоваться на фронтенде или внутри самой разметки по умолчанию. Если компонент Demo ToDo имел бы частичное представление **pagination**, оно находилось бы в **/plugins/october/demo/components/todo/pagination.htm** и отображалось на странице с помощью:

```twig
{% partial 'demoTodo::pagination' %}
```

Существует упрощённый контекстный метод. При вызове внутри частичного представления компонента он будет ссылаться непосредственно на себя. При вызове внутри частичного представления темы он просканирует все компоненты, используемые на странице/макете, на наличие совпадающего имени и использует его.

```twig
{% partial '@pagination' %}
```

Несколько компонентов могут совместно использовать частичные представления, разместив файл в директории **components/partials**. Частичные представления из этой директории используются как запасной вариант, когда обычное частичное представление компонента не найдено. Например, общее частичное представление в **/plugins/acme/blog/components/partials/shared.htm** может быть отображено на странице любым компонентом с помощью:

```twig
{% partial '@shared' %}
```

### Ссылка на «self»

Компоненты могут ссылаться на себя внутри своих частичных представлений с помощью переменной `__SELF__`. По умолчанию она возвращает [короткое имя или псевдоним компонента](../cms/themes/components.md).

```twig
<form data-request="{{__SELF__}}::onEventHandler">
    [...]
</form>
```

Компоненты также могут ссылаться на собственные свойства.

```twig
{% for item in __SELF__.items() %}
    {{ item }}
{% endfor %}
```

Если внутри частичного представления компонента нужно отрендерить другое частичное представление компонента, конкатенируйте переменную `__SELF__` с именем частичного представления:

```twig
{% partial __SELF__~"::screenshot-list" %}
```

### Уникальный идентификатор

Если идентичный компонент вызывается дважды на одной странице, свойство `id` может использоваться для ссылки на каждый экземпляр.

```twig
{{__SELF__.id}}
```

ID уникален при каждом отображении компонента.

```twig
<!-- ID: demoTodo527c532e9161b -->
{% component 'demoTodo' %}

<!-- ID: demoTodo527c532ec4c33 -->
{% component 'demoTodo' %}
```

## Рендеринг частичных представлений из кода

Вы можете программно рендерить частичные представления компонента внутри PHP-кода с помощью метода `renderPartial`. Метод проверит наличие частичного представления с именем `component-partial.htm` в компоненте и вернёт результат как строку. Второй параметр используется для передачи переменных представления. Та же логика разрешения путей применяется при рендеринге частичного представления компонента в PHP, как и в Twig; используйте префикс `@` для ссылки на частичные представления внутри самого компонента.

```php
$content = $this->renderPartial('@component-partial.htm');

$content = $this->renderPartial('@component-partial.htm', [
    'name' => 'John Smith'
]);
```

Например, для рендеринга частичного представления в ответ на [AJAX-обработчик](../cms/ajax/handlers.md):

```php
function onGetTemplate()
{
    return ['#someDiv' => $this->renderPartial('@component-partial.htm')];
}
```

Другой пример — переопределение всего ответа страницы путём возврата значения из цикла выполнения страницы `onRun`. Этот код конкретно вернёт XML-ответ с помощью фасада `Response`:

```php
public function onRun()
{
    $content = $this->renderPartial('@default.htm');
    return Response::make($content)->header('Content-Type', 'text/xml');
}
```

## Внедрение ресурсов страницы с помощью компонентов

Компоненты могут внедрять ресурсы (CSS и JavaScript файлы) на страницы или макеты, к которым они прикреплены. Используйте методы контроллера `addCss` и `addJs` для добавления ресурсов в CMS-контроллеры. Это можно сделать в методе `onRun` компонента.

```php
public function onRun()
{
    $this->addJs('/plugins/acme/blog/assets/javascript/blog-controls.js');
}
```

Если путь, указанный в аргументе методов `addCss` и `addJs`, начинается со слэша (`/`), он будет относительным к корню сайта. Если путь к ресурсу не начинается со слэша, он относителен к директории компонента.

Методы `addCss` и `addJs` принимают второй аргумент, определяющий атрибуты внедряемого ресурса в виде массива.

```php
public function onRun()
{
    $this->addJs('/plugins/acme/blog/assets/javascript/blog-controls.js', ['defer' => true]);
}
```
