# Публикация пакетов

October CMS использует [Composer](https://getcomposer.org/) для публикации пакетов и полностью совместим с ним, поэтому его документация применяется как расширение этой статьи.

Для публикации вашего плагина или темы на маркетплейсе October CMS вам сначала нужно стать автором и выбрать код автора. Этот код определит имя ваших пакетов и не может быть изменён позже.

Ваш пакет должен располагаться в репозитории системы контроля версий, доступном для шлюза October CMS, таком как [GitHub](https://github.com/) или [BitBucket](https://bitbucket.org/). Для приватных пакетов сервер может получить к ним доступ, используя учётные данные, которые вы предоставите в процессе публикации.

Убедитесь, что `name` вашего пакета заканчивается на **-plugin** или **-theme** соответственно. Это поможет другим найти ваш пакет и соответствует [руководству для разработчиков](https://octobercms.com/help/guidelines/developer#package-naming).

::: warning
При обновлении ваших плагинов или тем для совместимости с более новыми версиями October CMS необходимо следовать [семантическому версионированию](https://semver.org/), чтобы защитить старые сайты от критических изменений.
:::

## Публикация плагинов

При публикации вашего плагина файл `composer.json` должен содержать как минимум следующее JSON-содержимое. Обратите внимание, что имя пакета должно заканчиваться на **-plugin** и включать пакет `composer/installers` в качестве зависимости.

```json
{
    "name": "acme/blog-plugin",
    "type": "october-plugin",
    "description": "Enter a meaningful description here",
    "require": {
        "composer/installers": "~1.0"
    }
}
```

Плагин с кодом **Acme.Blog** будет иметь имя пакета Composer `acme/blog-plugin` и будет установлен в директорию **plugins/acme/blog**.

## Публикация тем

При публикации вашей темы файл `composer.json` должен содержать как минимум следующее JSON-содержимое. Обратите внимание, что имя пакета должно заканчиваться на **-theme** и включать пакет `composer/installers` в качестве зависимости.

```json
{
    "name": "acme/boilerplate-theme",
    "type": "october-theme",
    "description": "Enter a meaningful description here",
    "require": {
        "composer/installers": "~1.0"
    }
}
```

Плагин с кодом **Acme.Boilerplate** будет иметь имя пакета Composer `acme/boilerplate-theme` и будет установлен в директорию **themes/boilerplate**.

## Объявление зависимостей

Плагины и темы могут требовать определённую версию October CMS, а также зависеть от других пакетов. Просто включите их в ваш файл composer.json.

### Требование версии October CMS

Просто добавьте требование пакета `october/rain` с желаемым [шаблоном целевой версии](https://getcomposer.org/doc/articles/versions.md). Следующий пример потребует, чтобы установка платформы использовала версию 3.1 October CMS или выше.

```json
"require": {
    "october/rain": ">=3.1"
}
```

### Требование другого плагина

Перейдите в директорию вашей темы или плагина и откройте файл composer.json, чтобы включить зависимость и её целевую версию. Следующий пример включит плагин Acme.Blog с [диапазоном версий 1.2](https://getcomposer.org/doc/articles/versions.md).

```json
"require": {
    "acme/blog-plugin": "^1.2"
}
```

Вы также должны убедиться, что этот пакет включён в свойство `$require` в [файле регистрации плагина](../system/plugins.md).

### Требование другой темы

Перейдите в директорию вашей темы или плагина и откройте файл composer.json, чтобы включить зависимость и её целевую версию. Следующий пример включит тему Acme.Vanilla с [диапазоном версий 1.2](https://getcomposer.org/doc/articles/versions.md).

```json
"require": {
    "acme/vanilla-theme": "^1.2"
}
```

Убедитесь, что этот пакет включён в свойство `require` в [файле информации о теме](../../cms/themes/settings.md).

### Разработка со сторонними пакетами

Для создания нового плагина или темы, использующих внешний пакет или библиотеку, вы должны установить его в ваш корневой файл Composer, а затем скопировать определение в файл Composer вашего плагина. Например, если вы хотите, чтобы ваш плагин `acme/blog-plugin` зависел от пакета `aws/aws-sdk-php`.

1. В корневой директории выполните `composer require aws/aws-sdk-php`. Это установит пакет в корневой файл Composer и обеспечит его совместимость с другими пакетами.

2. После завершения откройте файл **composer.json** в корневой директории, чтобы найти новое определение зависимости. Например, вы увидите что-то вроде этого:

```json
"require": {
    "aws/aws-sdk-php": "^3.158"
}
```

3. Скопируйте это определение из корневого файла **composer.json** и включите его в файл **plugins/acme/blog/composer.json** вашего плагина. Теперь зависимость доступна вашему приложению и также требуется плагином для использования другими.

## Создание тега релиза

Пакеты в October CMS следуют [семантическому версионированию](https://semver.org/), и Composer использует git для определения стабильности и влияния данного релиза.

### Семантическое версионирование

Семантическое версионирование — это процесс, который защищает старые сайты от критических изменений. Важно отметить, что по умолчанию Composer не будет автоматически обновлять мажорную версию.

Следующий путь обновления версии будет **ручным процессом**:

- Обновление с `v1.0.0` до `v2.0.0`

Composer **автоматически обновит** минорные и патч-версии:

- Обновление с `v1.2.0` до `v1.3.0`
- Обновление с `v1.3.5` до `v1.3.6`

Прочитайте статью Composer о [версиях и ограничениях Composer](https://getcomposer.org/doc/articles/versions.md), чтобы узнать больше.

### Просмотр ваших тегов

Используйте команду `git tag` для просмотра существующих тегов вашего пакета.

```bash
$ git tag
v1.0
v2.0
```

### Создание нового тега

Для создания нового тега добавьте (`-a`) версию с необязательным (`-m`) сообщением.

```bash
git tag -a v2.0.1 -m "Version 2 is here!"
```

### Увеличение версии в файле

Помимо создания тегов, вы также должны увеличить версию в вашем [файле версий плагина](../system/plugins.md) или [настройках темы](../../cms/themes/settings.md). Этот файл информирует шлюз October CMS о последней версии и содержит историю предыдущих версий.

Для понимания того, как это работает:

- Шлюз использует файл версий, найденный в **ветке по умолчанию** репозитория.
- Composer будет устанавливать и обновлять, используя **последний стабильный тег** репозитория.

Это означает, что файл версий в ветке по умолчанию всегда должен соответствовать последнему стабильному тегу в Git.

## Приватные плагины и темы

Composer позволяет вам добавлять приватные репозитории из GitHub и других провайдеров в ваши проекты October CMS. Убедитесь, что вы следовали тем же инструкциям для публикации плагинов и тем соответственно.

В любом случае у вас должна быть копия вашего приватного плагина или темы, хранящаяся где-то, доступном основному проекту. Команды `plugin:install` и `theme:install` могут использоваться для установки приватных плагинов из удалённого или локального источника. Это добавит расположение в ваш файл Composer и установит его как любой другой пакет.

### Установка из удалённого источника

Используйте опцию `--from` для указания расположения вашего удалённого источника при установке.

```bash
php artisan plugin:install Acme.Blog --from=git@github.com:acme/blog-plugin.git
```

Для использования конкретной версии или ветки используйте опцию `--want`, например, для запроса версии ветки **develop**.

```bash
php artisan plugin:install Acme.Blog --from=git@github.com:acme/blog-plugin.git --want=dev-develop
```

::: tip
Если вы используете адрес `git@` репозитория, Composer предпочтёт исходную версию и клонирует репозиторий, чтобы вы могли продолжать отправлять обновления как обычно.
:::

### Установка из локального источника

Для установки плагина с помощью Composer из того же источника проекта.

```bash
php artisan plugin:install Acme.Blog --from=./plugins/acme/blog
```

Вы также можете использовать источник, находящийся на локальном или сетевом диске.

```bash
php artisan plugin:install Acme.Blog --from=/home/sam/private-plugins/acme-blog
```
