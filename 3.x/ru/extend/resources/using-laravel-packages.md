# Использование пакетов Laravel

При включении пакетов Laravel в плагины October CMS есть несколько вещей, на которые следует обратить внимание.

### Конфигурационные файлы

Пакеты Laravel часто предоставляют конфигурационные файлы. Вы должны продублировать эту конфигурацию в директорию вашего плагина. Например, если файл назывался **purifier.php** и содержал некоторые базовые значения конфигурации.

```php
return [
    'encoding' => 'UTF-8',
    'finalize' => true,
    'cachePath' => storage_path('app/purifier'),
    'cacheFileMode' => 0755,
];
```

Скопируйте этот файл в директорию вашего плагина, например, **plugins/acme/blog/config/purifier.php**. Важно скопировать и поддерживать весь файл, так как отсутствующие ключи не будут унаследованы из базовой конфигурации.

Далее вы должны перенести содержимое конфигурации вашего плагина в конфигурацию пакета внутри метода `boot()`.

```php
public function boot()
{
    Config::set('purifier', Config::get('acme.blog::purifier'));
}
```

Это установит все значения конфигурации пакета равными значениям конфигурации вашего плагина. Следующие значения будут равны.

```php
Config::get('purifier.encoding') === Config::get('acme.blog::purifier.encoding');
```

Теперь вы можете предоставлять значения конфигурации пакета так же, как и обычные значения конфигурации плагина, используя [стандартный подход к конфигурации](../settings/file-settings.md).

### Псевдонимы и поставщики сервисов

Если пакет Laravel содержит поставщиков сервисов и псевдонимы, вы должны вручную зарегистрировать их в ваших плагинах, используя фасад `App` в методе `register()`.

```php
public function register()
{
    // Register the aliases provided by the packages used by your plugin
    App::registerClassAlias('Purifier', \Mews\Purifier\Facades\Purifier::class);

    // Register the service providers provided by the packages used by your plugin
    App::register(\Mews\Purifier\PurifierServiceProvider::class);
}
```

### Миграции и модели

Пакеты Laravel, которые взаимодействуют с базой данных, часто включают собственные миграции базы данных и модели Eloquent. Вы должны продублировать эти миграции и модели в директорию вашего плагина.

Убедитесь, что классы моделей наследуют базовый класс `October\Rain\Database\Model` вместо базового класса модели Laravel Eloquent, чтобы воспользоваться расширенными технологическими возможностями October CMS.

Также хорошей идеей будет переименовать таблицы базы данных и добавить к ним префикс с кодом вашего автора и именем плагина. Например, таблица с именем `posts` должна быть переименована в `rainlab_blog_posts`.
