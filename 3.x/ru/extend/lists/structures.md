# Сортировка записей

October CMS предоставляет возможности для сортировки и переупорядочивания записей базы данных. Для поведений, поддерживающих структурированные списки, вы можете определить свойство **structure** для включения этой функции. Различные [трейты модели](../database/traits.md) используются для поддержки переупорядочивания, включая вложенные множества, простые деревья и сортируемые модели.

## Настройка поведения

Поведения панели управления [Контроллер списков](./list-controller.md) и [Контроллер связей](../forms/form-controller.md) в настоящее время поддерживают возможность переупорядочивания записей с помощью свойства **structure** в соответствующем определении. При определении страница отображает список записей с маркером перетаскивания, позволяющим их сортировать и реструктурировать.

```yaml
# config_list.yaml

# ...

structure:
    showTree: true
    showReorder: true
    showSorting: false
    maxDepth: 2
```

Ниже перечислены доступные свойства конфигурации.

Свойство | Описание
------------- | -------------
**showTree** | отображает древовидную иерархию для записей родитель/потомок. По умолчанию: `true`
**treeExpanded** | должны ли узлы дерева быть развёрнутыми по умолчанию. По умолчанию: `true`
**showReorder** | отображает интерфейс для переупорядочивания записей. По умолчанию: `true`
**showSorting** | позволяет сортировать записи, отключает структуру при сортировке. По умолчанию: `true`
**maxDepth** | определяет максимальное количество уровней, допустимых для переупорядочивания. По умолчанию: `null`
**dragRow** | позволяет перетаскивать всю строку в дополнение к маркеру переупорядочивания. По умолчанию: `true`
**permissions** | [разрешения](../../extend/backend/permissions.md), которые должен иметь текущий пользователь панели управления для изменения структуры. Поддерживает как строку для одного разрешения, так и массив разрешений, из которых достаточно одного для предоставления доступа.

## Поддерживаемые типы моделей

В зависимости от требований для управления вложенными и отсортированными записями может использоваться различный интерфейс модели. Поведение адаптируется в зависимости от того, какой трейт реализован.

### Вложенное множество

Используйте трейт `NestedTree`, когда необходима фиксированная структура. Это включает отношения родитель-потомок и когда записи должны отображаться в определённом порядке.

```php
class Category extends Model
{
    use \October\Rain\Database\Traits\NestedTree;
}
```

Подробнее о трейте `NestedTree` читайте в [документации по базам данных](../database/traits.md).

### Простое дерево

Используйте трейт `SimpleTree`, когда необходимо базовое отношение родитель-потомок.

```php
class Category extends Model
{
    use \October\Rain\Database\Traits\SimpleTree;
}
```

Подробнее о трейте `SimpleTree` читайте в [документации по базам данных](../database/traits.md).

### Сортируемая модель

Используйте трейт `Sortable`, когда записи должны отображаться в определённом порядке.

```php
class User extends Model
{
    use \October\Rain\Database\Traits\Sortable;
}
```

Подробнее о трейте `Sortable` читайте в [документации по базам данных](../database/traits.md).

## Сортировка связанных записей

Сортировка связанных записей возможна с помощью [Контроллера связей](../forms/relation-controller.md) с использованием свойства **structure**. Поддерживаемые типы связей перечислены ниже.

- [Has Many](../database/relations.md#relation-one-to-many) использует трейт `Sortable` для связанной модели.
- [Belongs To Many](../database/relations.md#relation-many-to-many) использует трейт `SortableRelation` для родительской модели (см. ниже).

### Трейт модели SortableRelation

Используйте трейт модели `SortableRelation`, когда записи должны сортироваться внутри сводной таблицы, например, для типа связи [Belongs To Many](../database/relations.md#many-to-many). Этот трейт требует определения свойства `pivotSortable` в связи, где значение — это имя сортируемого столбца в сводной таблице.

```php
class User extends Model
{
    use \October\Rain\Database\Traits\SortableRelation;

    /**
     * @var array belongsToMany
     */
    public $belongsToMany = [
        'roles' => [
            Role::class,
            'table' => 'users_roles',
            'pivotSortable' => 'sort_order',
        ]
    ];
}
```

Затем в вашей конфигурации связи вы должны включить свойство `showReorder` и отключить свойство `showTree`.

```yaml
roles:
    #...
    structure:
        showReorder: true
        showTree: false
```
