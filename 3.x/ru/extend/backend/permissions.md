# Разрешения

Разрешения позволяют пользователям иметь определённые привилегии и функции в панели управления. Примером может быть возможность создавать или удалять записи, или просматривать журналы сервера. Эти разрешения основаны на назначенной роли и могут быть предоставлены на уровне отдельного пользователя.

## Коды разрешений

Коды разрешений определяют одно разрешение и являются строковыми ключами, использующими «точечную» нотацию, например `some.area.permission_name`. Эти разрешения предоставляются пользователям либо путём прямого назначения, либо через наследование от их роли.

При проверке наличия у пользователя конкретного разрешения разрешения его роли наследуются, а затем переопределяются разрешениями, назначенными непосредственно пользователю. Например:

- Если у пользователя **Боб** есть роль **Genius**; и
- Роль **Genius** имеет разрешение `eat_cake`; но
- У **Боба** разрешение `eat_cake` специально установлено как запрещённое; тогда
- **Боб** не сможет `eat_cake`.

Однако:

- Если **Бобу** назначено разрешение `eat_vegetables` напрямую, но;
- Роль **Genius** его не имеет, тогда;
- **Боб** всё равно получит `eat_vegetables`.

### Вложенные разрешения

Коды разрешений поддерживают вложенную структуру для более чистого интерфейса при выборе разрешений. Для вложения кода разрешения «точечное» значение должно быть прямым потомком своего родителя, поддерживается неограниченная вложенность.

В следующем примере разрешение `manage_entries` должно быть предоставлено, чтобы коды `manage_entries.create` и `manage_entries.publish` стали доступными. Визуально это выглядит так:

::: dir
├── manage_entries
|   ├── manage_entries.create
|   └── manage_entries.publish
└── delete_entries
:::

## Уровни доступа

Доступ ко всем частям экземпляра October CMS контролируется системой разрешений. Метод `BackendAuth::userHasAccess` — это быстрый способ проверить, авторизован ли текущий пользователь и имеет ли он разрешение на определённую область.

```php
// Returns true if the user has permission
$permissionGranted = BackendAuth::userHasAccess('utilities.logs');
```

### Суперпользователи

Администраторам может быть присвоен специальный флаг «суперпользователь», который разрешает доступ ко всем областям. При его предоставлении система разрешений обходится, предоставляя доступ ко всем областям. Суперпользователи не видны другим обычным администраторам.

::: warning
Любой суперпользователь может создавать и удалять других суперпользователей, поэтому этот статус должен предоставляться только администратору высшего уровня или владельцу приложения.
:::

### Роли

Роли используют модель `Backend\Models\UserRole` и являются группировками разрешений с именем и описанием для идентификации роли. Администратору может быть назначена только одна роль одновременно.

October CMS поставляется с двумя системными ролями по умолчанию: `developer` и `publisher`. Можно создать любое количество пользовательских ролей с собственными комбинациями разрешений и применить их к пользователям.

::: tip
Системные роли не могут изменять свои разрешения, однако их можно удалить, если они не нужны.
:::

### Иерархия ролей

Каждой роли назначается ранговая позиция в панели управления, представленная столбцом `sort_order` в базе данных. Это позволяет установить базовую организационную структуру, при которой пользователи могут управлять только ролями ниже своей.

В следующем примере **Старший редактор** может управлять всеми пользователями, превосходя по рангу роли **Штатный автор** и **Фактчекер**. При этом роль **Фактчекер** не может видеть пользователей или управлять разрешениями выше неё — в ролях **Штатный автор** и **Старший редактор**.

- Старший редактор
- Штатный автор
- Фактчекер

Если предоставлено разрешение **Управление администраторами → Управление ролями**, пользователи могут управлять своими пользователями, разрешениями и ролями, существующими ниже их текущей роли.

## Регистрация разрешений

Плагины могут регистрировать разрешения пользователей панели управления, переопределяя метод `registerPermissions` в [файле регистрации плагина](../extending.md). Разрешения определяются как массив, где ключи соответствуют ключам разрешений, а значения — описаниям разрешений. Ключи разрешений состоят из имени автора, имени плагина и имени функции. Вот пример кода.

```
acme.blog.access_categories
```

Следующий пример показывает, как регистрировать элементы разрешений панели управления. Разрешения определяются ключом разрешения и описанием. В интерфейсе управления разрешениями панели управления разрешения отображаются как список флажков. Контроллеры панели управления могут использовать разрешения, определённые плагинами, для ограничения доступа пользователей к страницам или функциям.

```php
public function registerPermissions()
{
    return [
        'acme.blog.access_posts' => [
            'label' => 'Manage the blog posts',
            'tab' => 'Blog',
            'order' => 200,
        ],
        // ...
    ];
}
```

Вы также можете указать опцию `roles` как массив, где каждое значение — код API роли. Когда роль создаётся с этим кодом, она становится системной ролью, которая всегда предоставляет это разрешение пользователям с этой ролью.

```php
public function registerPermissions()
{
    return [
        'acme.blog.access_categories' => [
            'label' => 'Manage the blog categories',
            'tab' => 'Blog',
            'order' => 200,
            'roles' => ['developer']
        ]
        // ...
    ];
}
```

## Ограничение доступа к страницам панели управления

В классе контроллера панели управления вы можете указать, какие разрешения необходимы для доступа к страницам контроллера. Это делается через свойство контроллера `$requiredPermissions`. Это свойство должно содержать массив ключей разрешений. Если разрешения пользователя совпадают с любым разрешением из списка, фреймворк позволит пользователю видеть страницы контроллера.

```php
namespace Acme\Blog\Controllers;

use Backend\Classes\BackendController;

class Posts extends BackendController
{
    public $requiredPermissions = ['acme.blog.access_posts'];
}
```

Вы также можете использовать символ **звёздочки** для обозначения условия «все разрешения». В следующем примере страницы контроллера доступны для всех пользователей, имеющих любые разрешения, начинающиеся со строки «acme.blog.»:

```php
public $requiredPermissions = ['acme.blog.*'];
```

## Ограничение доступа к функциям

Модель пользователя панели управления имеет методы, позволяющие определить, имеет ли пользователь определённые разрешения. Вы можете использовать эту возможность для ограничения функциональности пользовательского интерфейса панели управления. Методы разрешений, поддерживаемые пользователем панели управления: `userHasAccess` и `userHasPermission`. Оба метода принимают два параметра: строку ключа разрешения (или массив строк ключей) и необязательный параметр, указывающий, что все разрешения, перечисленные первым параметром, обязательны.

Метод `userHasAccess` возвращает **true** для любого разрешения, если пользователь является суперпользователем. Метод `userHasPermission` более строг — возвращает true только если пользователь действительно имеет указанные разрешения в своей учётной записи или через роль. Как правило, `userHasAccess` является предпочтительным методом, так как он учитывает абсолютные полномочия суперпользователя. Следующий пример показывает использование методов в коде контроллера.

```php
if (BackendAuth::userHasAccess('acme.blog.*')) {
    // ...
}

if (BackendAuth::userHasPermission([
    'acme.blog.access_posts',
    'acme.blog.access_categories'
])) {
    // ...
}
```

Вы также можете использовать эти методы в представлениях панели управления для скрытия элементов интерфейса. Следующий пример показывает, как скрыть кнопку в [форме панели управления](../forms/form-controller.md).

```php
<?php if (BackendAuth::userHasAccess('acme.blog.delete_categories')): ?>
    <button
        type="button"
        class="oc-icon-trash-o btn-icon danger"
        data-request="onDelete"
        data-load-indicator="Deleting Category..."
        data-request-confirm="Do you really want to delete this category?">
    </button>
<?php endif ?>
```
