# Планирование задач

::: aside
Инструкции по настройке задачи планировщика см. в [руководстве по установке](../../setup/installation.md).
:::

Раньше разработчикам приходилось создавать отдельную запись Cron для каждой задачи, которую нужно было запланировать. Однако это порой доставляло неудобства. Расписание задач не находилось под контролем версий, и для добавления записей Cron приходилось подключаться к серверу по SSH. Планировщик команд позволяет гибко и выразительно определять расписание команд прямо в самом приложении, и на сервере требуется только одна запись Cron.

<a id="oc-defining-schedules"></a>
## Определение расписаний

Все запланированные задачи можно определить, переопределив метод `registerSchedule` в [файле регистрации плагина](../extending.md). Метод принимает единственный аргумент `$schedule` и используется для определения команд вместе с их частотой выполнения.

Для начала рассмотрим пример планирования задачи. В этом примере мы запланируем вызов `Closure` каждый день в полночь. Внутри `Closure` мы выполним запрос к базе данных для очистки таблицы:

```php
class Plugin extends PluginBase
{
    // ...

    public function registerSchedule($schedule)
    {
        $schedule->call(function () {
            Db::table('recent_users')->delete();
        })->daily();
    }
}
```

Помимо планирования вызовов `Closure`, вы также можете планировать [консольные команды](../console-commands.md) и команды операционной системы. Например, вы можете использовать метод `command` для планирования консольной команды:

```php
$schedule->command('cache:clear')->daily();
```

Метод `exec` может использоваться для выполнения команды операционной системы:

```php
$schedule->exec('node /home/acme/script.js')->daily();
```

### Параметры частоты расписания

Разумеется, существует множество вариантов расписания, которые вы можете назначить вашей задаче:

Метод  | Описание
------------- | -------------
`->cron('* * * * *');`  |  Запуск задачи по пользовательскому расписанию Cron
`->everyMinute();`  |  Запуск задачи каждую минуту
`->everyFiveMinutes();`  |  Запуск задачи каждые пять минут
`->everyTenMinutes();`  |  Запуск задачи каждые десять минут
`->everyThirtyMinutes();`  |  Запуск задачи каждые тридцать минут
`->hourly();`  |  Запуск задачи каждый час
`->daily();`  |  Запуск задачи каждый день в полночь
`->dailyAt('13:00');`  |  Запуск задачи каждый день в 13:00
`->twiceDaily(1, 13);`  |  Запуск задачи ежедневно в 1:00 и 13:00
`->weekly();`  |  Запуск задачи каждую неделю
`->monthly();`  |  Запуск задачи каждый месяц

Эти методы могут быть объединены с дополнительными ограничениями для создания ещё более точных расписаний, выполняющихся только в определённые дни недели. Например, для планирования команды еженедельно по понедельникам:

```php
$schedule->call(function () {
    // Runs once a week on Monday at 13:00...
})->weekly()->mondays()->at('13:00');
```

Ниже приведён список дополнительных ограничений расписания:

Метод  | Описание
------------- | -------------
`->weekdays();`  |  Ограничить задачу рабочими днями
`->sundays();`  |  Ограничить задачу воскресеньем
`->mondays();`  |  Ограничить задачу понедельником
`->tuesdays();`  |  Ограничить задачу вторником
`->wednesdays();`  |  Ограничить задачу средой
`->thursdays();`  |  Ограничить задачу четвергом
`->fridays();`  |  Ограничить задачу пятницей
`->saturdays();`  |  Ограничить задачу субботой
`->when(Closure);`  |  Ограничить задачу на основе проверки условия

#### Ограничения проверкой условия

Метод `when` может использоваться для ограничения выполнения задачи на основе результата заданной проверки условия. Другими словами, если переданное `Closure` возвращает `true`, задача будет выполнена, при условии что никакие другие ограничивающие условия не препятствуют её запуску:

```php
$schedule->command('emails:send')->daily()->when(function () {
    return true;
});
```

### Предотвращение перекрытия задач

По умолчанию запланированные задачи будут запущены, даже если предыдущий экземпляр задачи всё ещё выполняется. Чтобы предотвратить это, используйте метод `withoutOverlapping`:

```php
$schedule->command('emails:send')->withoutOverlapping();
```

В этом примере консольная команда `emails:send` будет запускаться каждую минуту, если она ещё не выполняется. Метод `withoutOverlapping` особенно полезен, если у вас есть задачи, время выполнения которых сильно варьируется, и вам не нужно точно предсказывать, сколько времени займёт данная задача.

## Вывод задач

Планировщик предоставляет несколько удобных методов для работы с выводом, генерируемым запланированными задачами. Во-первых, с помощью метода `sendOutputTo` вы можете направить вывод в файл для последующего изучения.

```php
$schedule->command('emails:send')
    ->daily()
    ->sendOutputTo($filePath);
```

С помощью метода `emailOutputTo` вы можете отправить вывод на электронную почту по указанному адресу. Обратите внимание, что вывод сначала должен быть направлен в файл с помощью метода `sendOutputTo`. Также перед отправкой вывода задачи по электронной почте необходимо настроить [почтовые сервисы](../../setup/mail-config.md).

```php
$schedule->command('foo')
    ->daily()
    ->sendOutputTo($filePath)
    ->emailOutputTo('foo@example.tld');
```

::: tip
Методы `emailOutputTo` и `sendOutputTo` доступны только для метода `command` и не поддерживаются для `call`.
:::

## Хуки задач

С помощью методов `before` и `after` вы можете указать код, который будет выполняться до и после завершения запланированной задачи:

```php
$schedule->command('emails:send')
    ->daily()
    ->before(function () {
        // Task is about to start...
    })
    ->after(function () {
        // Task is complete...
    });
```

#### Пинг URL

С помощью методов `pingBefore` и `thenPing` планировщик может автоматически выполнять пинг заданного URL до или после завершения задачи. Этот метод полезен для уведомления внешнего сервиса о том, что ваша запланированная задача начинается или завершена:

```php
$schedule->command('emails:send')
    ->daily()
    ->pingBefore($url)
    ->thenPing($url);
```
