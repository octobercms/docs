# Контроллеры

Панель управления October CMS реализует паттерн Model-View-Controller (MVC). В этой статье описывается, как разрабатывать контроллеры панели управления и как настраивать поведения контроллеров.

Каждый контроллер представлен PHP-скриптом, который находится в поддиректории **/controllers** директории плагина. Представления контроллера — это файлы `.php`, расположенные в директории представлений контроллера. Имя директории представлений совпадает с именем класса контроллера в нижнем регистре. Директория представлений также может содержать файлы конфигурации контроллера. Пример структуры директории контроллера:

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `controllers`
|           |   ├── users  _← Директория представлений_
|           |   |   ├── config_form.yaml  _← Файл конфигурации_
|           |   |   ├── _partial.php  _← Файл частичного представления_
|           |   |   └── index.php  _← Файл представления_
|           |   └── Users.php  _← Класс контроллера_
|           └── Plugin.php
:::

:::tip
Практический пример использования контроллеров панели управления можно найти в [серии уроков Beyond Behaviors](https://octobercms.com/support/article/ob-19).
:::

### Определение класса

Команда `create:controller` генерирует контроллер, файлы конфигурации и представлений. Первый аргумент указывает имя автора и плагина. Второй аргумент указывает имя класса контроллера.

```bash
php artisan create:controller Acme.Blog Posts
```

Классы контроллеров должны наследовать класс `Backend\Classes\Controller`. Как и любой другой класс плагина, контроллеры должны принадлежать [пространству имён плагина](../system/plugins.md). Самое базовое представление контроллера, используемого внутри плагина, выглядит так.

```php
namespace Acme\Blog\Controllers;

class Posts extends \Backend\Classes\Controller
{
    public function index()    // ← Action method
    {

    }
}
```

Обычно каждый контроллер реализует функциональность для работы с одним типом данных — например, записями блога или категориями. Все описанные ниже поведения панели управления предполагают эту конвенцию.

### Свойства контроллера

Базовый класс контроллера панели управления определяет ряд свойств, позволяющих настраивать внешний вид страницы и управлять безопасностью страницы:

Свойство | Описание
------------- | -------------
**$fatalError** | позволяет сохранить фатальное исключение, сгенерированное в методе действия, для отображения в представлении.
**$user** | содержит ссылку на объект пользователя панели управления.
**$suppressView** | позволяет предотвратить отображение представления. Может быть обновлено в методе действия или в конструкторе контроллера.
**$params** | массив маршрутизированных параметров.
**$action** | имя метода действия, выполняемого в текущем запросе.
**$publicActions** | определяет массив действий, доступных без аутентификации пользователя панели управления. Может быть переопределено в определении класса.
**$requiredPermissions** | разрешения, необходимые для просмотра этой страницы. Может быть задано в определении класса или в конструкторе контроллера. Подробнее см. [пользователи и разрешения](../backend/users.md).
**$pageTitle** | задаёт заголовок страницы. Может быть задано в методе действия.
**$bodyClass** | свойство CSS-класса body, используемое для настройки макета. Может быть задано в конструкторе контроллера или методе действия.
**$guarded** | специфические для контроллера методы, которые не могут быть вызваны как действия. Может быть расширено в конструкторе контроллера.
**$layout** | указывает пользовательский макет для [представлений контроллера](../system/views.md).

## Логика инициализации

Контроллеры могут выполнять логику инициализации в нативном методе `__construct`.

::: warning
Логика внутри конструктора не защищена и не должна обрабатывать конфиденциальную логику.
```php
public function __construct()
{
    parent::__construct();
}
```
:::

Метод `beforeDisplay` вызывается после проверки разрешений, и большая часть логики должна быть размещена здесь. Это включает инициализацию виджетов и других общих компонентов.

```php
public function beforeDisplay()
{
    // Initialize widgets, handle file uploads, etc.
}
```

## Действия, представления и маршрутизация

Публичные методы контроллера, называемые **действиями**, связаны с **файлами представлений**, которые представляют страницу, соответствующую действию. Файлы представлений панели управления используют синтаксис PHP. Пример содержимого файла представления **index.php**, соответствующего методу действия `index`.

```html
<h1>Hello World</h1>
```

URL этой страницы составляется из имени автора, имени плагина, имени контроллера и имени действия.

```text
admin/[author name]/[plugin name]/[controller name]/[action name]
```

Например, определение класса, использованное в начале этой статьи, доступно по следующему URL.

```text
https://example.tld/admin/acme/blog/users/index
```

Если [плагин зарегистрирован](./plugins.md) с **hint** в методе `pluginDetails`, становится доступна более короткая структура URL, что полезно для маскировки имени автора в URL.

```text
admin/[plugin hint]/[controller name]/[action name]
```

## Передача данных в представления

Используйте свойство контроллера `$vars` для передачи любых данных непосредственно в представление:

```php
$this->vars['myVariable'] = 'value';
```

Переменные, переданные через свойство `$vars`, теперь доступны непосредственно в вашем представлении:

```php
<p>The variable value is <?= $myVariable ?></p>
```

## Установка контекста навигации

Плагины могут регистрировать меню и подменю панели управления в [файле регистрации плагина](../backend/navigation.md). Контекст навигации определяет, какое меню и подменю панели управления активны для текущей страницы. Вы можете установить контекст навигации с помощью класса `BackendMenu`:

```php
BackendMenu::setContext('Acme.Blog', 'blog', 'categories');
```

Первый параметр указывает имена автора и плагина. Второй параметр задаёт код меню. Необязательный третий параметр указывает код подменю. Обычно `BackendMenu::setContext` вызывается в конструкторе контроллера.

```php
namespace Acme\Blog\Controllers;

class Categories extends \Backend\Classes\Controller {

public function __construct()
{
    parent::__construct();

    BackendMenu::setContext('Acme.Blog', 'blog', 'categories');
}
```

Вы можете задать заголовок страницы панели управления через свойство `$pageTitle` класса контроллера (обратите внимание, что поведения формы и списка могут делать это за вас):

```php
$this->pageTitle = 'Blog Categories';
```

## Переопределение ответа

Вы можете переопределять ответы в контроллерах панели управления как механизм для внесения изменений в ответ HTTP-запроса. Например, вы можете захотеть указать HTTP-заголовок для определённых действий контроллера или перенаправить пользователей, если они не соответствуют определённым критериям.

Переопределение ответа особенно полезно при расширении других контроллеров. Однако вы также можете использовать эти методы локально.

```php
\Author\Plugin\Controllers\SomeController::extend(function($controller) {
    $controller->setResponseHeader('Test-Header', 'Test');
});
```

Если вы хотите проверить маршрутизированное действие или параметры, они доступны через методы контроллера `getAction` и `getParams`.

```php
Author\Plugin\Controllers\SomeController::extend(function($controller) {
    if ($controller->getAction() === 'index') {
        // Only do it for the index action
    }

    if ($controller->getParams()[0] ?? null) {
        // Only if first parameter exists
    }
});
```

Для добавления заголовка к ответу используйте метод `setResponseHeader`.

```php
$this->setResponseHeader('Test-Header', 'Test');
```

Для изменения кода состояния ответа используйте метод `setStatusCode`.

```php
$this->setStatusCode(404);
```

Для полного переопределения ответа вызовите метод `setResponse` — он принудительно установит ответ независимо от того, что происходит в жизненном цикле страницы.

```php
$this->setResponse('Page Not Found');
```

Вы также можете передать объект `Response` в этот метод.

```php
$this->setResponse(Response::make(...));
```

Подробнее о создании ответов см. в статье [Представления и ответы](../services/response-view.md).
