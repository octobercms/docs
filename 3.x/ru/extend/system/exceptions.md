# Доступные исключения

### Application Exception

Класс `October\Rain\Exception\ApplicationException`, с псевдонимом `ApplicationException`, является наиболее распространённым типом исключений, используемым когда простое условие приложения не выполнено.

```php
throw new ApplicationException('You must be logged in to do that!');
```

Сообщение об ошибке будет упрощено и никогда не будет содержать конфиденциальную информацию, такую как PHP-файл и номер строки.

### System Exception

Класс `October\Rain\Exception\SystemException`, с псевдонимом `SystemException`, используется для ошибок, критичных для функционирования системы, и всегда записывается в журнал.

```php
throw new SystemException('Unable to contact the mail server API');
```

При выбросе этого исключения отображается подробное сообщение об ошибке с файлом и номером строки, где оно произошло.

### Not Found Exception

Класс `October\Rain\Exception\NotFoundException`, с псевдонимом `NotFoundException`, используется для ошибок, возникающих при обнаружении отсутствующей записи.

```php
throw new NotFoundException('Record not found');
```

При выбросе этого исключения стандартный ответ изменится для отображения ближайшей страницы «не найдено» с HTTP-кодом 404.

### Validation Exception

Класс `October\Rain\Exception\ValidationException`, с псевдонимом `ValidationException`, используется для ошибок, связанных непосредственно с отправкой формы и невалидным полем. Сообщение должно содержать массив с полями и сообщениями об ошибках.

```php
throw new ValidationException(['username' => 'Sorry that username is already taken!']);
```

Вы также можете передать экземпляр [сервиса валидации](../services/validation.md).

```php
$validation = Validator::make(...);

if ($validation->fails()) {
    throw new ValidationException($validation);
}
```

При выбросе этого исключения [AJAX-фреймворк](./ajax.md) предоставит эту информацию в удобном формате и установит фокус на первое невалидное поле.

### AJAX Exception

Класс `October\Rain\Exception\AjaxException`, с псевдонимом `AjaxException`, считается «умной ошибкой» и возвращает HTTP-код 406. Это позволяет передавать содержимое ответа, как если бы это был успешный ответ.

```php
throw new AjaxException(['#flashMessages' => $this->renderPartial(...)]);
```

При выбросе этого исключения [AJAX-фреймворк](./ajax.md) будет следовать стандартному процессу обработки ошибок, но также обновит указанные частичные представления.

## Обработка исключений

Все исключения обрабатываются классом `October\Rain\Foundation\Exception\Handler`. Этот класс содержит два метода: `report` и `render`, которые определяют, должна ли ошибка записываться в журнал и как отвечать на ошибку.

Однако при необходимости вы можете указать пользовательские обработчики с помощью метода `App::error`. Обработчики вызываются на основе type-hint обрабатываемого исключения. Например, вы можете создать обработчик, который обрабатывает только экземпляры `RuntimeException`:

```php
App::error(function(RuntimeException $exception) {
    // Handle the exception...
});
```

Если обработчик исключений возвращает ответ, этот ответ будет отправлен в браузер, и другие обработчики ошибок вызваны не будут.

```php
App::error(function(InvalidUserException $exception) {
    return 'Sorry! Something is wrong with this account!';
});
```

Для прослушивания фатальных ошибок PHP можно проверить тип исключения Error:

```php
App::error(function(Error $exception) {
    //
});
```

Если у вас несколько обработчиков исключений, они должны быть определены от наиболее общих к наиболее специфичным. Так, например, обработчик всех исключений типа `Exception` должен быть определён перед пользовательским типом исключения, таким как `SystemException`.

### Где размещать обработчики ошибок

Регистрация обработчиков ошибок обычно относится к категории загрузочного кода. Другими словами, они подготавливают ваше приложение к обработке запросов и обычно должны выполняться до вызова маршрута или контроллера. Наиболее распространённое место — метод `boot` [файла регистрации плагина](../extending.md). Альтернативно плагины могут предоставить файл **init.php** в директории плагина для размещения регистрации обработчиков ошибок.

## HTTP-исключения

Некоторые исключения описывают HTTP-коды ошибок сервера. Например, это может быть ошибка «страница не найдена» (404), «ошибка авторизации» (401) или сгенерированная разработчиком ошибка 500. Для генерации такого ответа из любого места приложения используйте следующее.

```php
App::abort(404);
```

Метод `abort` немедленно выбросит исключение, которое будет обработано обработчиком исключений. Опционально можно указать текст ответа.

```php
App::abort(403, 'Unauthorized action.');
```

Этот метод может использоваться в любой момент жизненного цикла запроса. Также существует сопутствующий [Twig-фильтр для прерывания запросов](../../markup/function/abort.md).

### Пользовательская страница ошибки

По умолчанию любые ошибки отображаются с подробной страницей ошибки, содержащей содержимое файла, номер строки и трассировку стека. Вы можете отобразить пользовательскую страницу ошибки, установив значение конфигурации `debug` в **false** в скрипте `config/app.php` и создав страницу с URL `/error`.
