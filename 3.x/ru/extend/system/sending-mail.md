# Отправка почты

В этой статье описывается, как создавать содержимое писем, включая использование макетов и частичных представлений, а затем методы, используемые для их отправки. В содержимом писем поддерживаются базовые Twig-теги и выражения. Также поддерживается синтаксис Markdown, подробнее см. раздел [использование HTML в Markdown](../services/parser.md).

## Содержимое сообщения

Почтовые сообщения в October CMS могут быть отправлены с использованием либо почтовых представлений, либо почтовых шаблонов. Почтовое представление предоставляется приложением или плагином в файловой системе в директории **/views**. Почтовый шаблон же управляется через панель управления через **Настройки → Шаблоны писем**.

Опционально почтовые представления могут быть зарегистрированы в [файле регистрации плагина](../extending.md) с помощью метода `registerMailTemplates`. Это автоматически создаёт почтовый шаблон, позволяя настраивать его через панель управления.

### Определение шаблонов в панели управления

Вы можете создавать почтовые шаблоны, хранящиеся в базе данных, через панель управления **Настройки → Шаблоны писем**. **Код**, присвоенный шаблону, является уникальным идентификатором и не может быть изменён после создания.

Например, если вы создадите шаблон с кодом `my-template`, вы сможете отправить его с помощью следующего PHP-кода:

```php
Mail::send('my-template', $data, function($message) {
    // ...
});
```

::: tip
Если почтовый шаблон не существует в системе, этот код попытается найти почтовое представление в файловой системе с тем же кодом.
:::

### Определение макетов в панели управления

Почтовые макеты можно создать, выбрав **Настройки → Шаблоны писем** и нажав на вкладку **Макеты**. Они работают так же, как CMS-макеты — содержат каркас почтового сообщения. Почтовые представления и шаблоны поддерживают использование почтовых макетов.

По умолчанию October CMS поставляется с двумя стандартными почтовыми макетами.

Макет | Код | Описание
------------- | ------------- | -------------
Default | `default` | Используется для публичной, фронтенд-почты.
System | `system` | Используется для внутренней почты панели управления.

### Определение представлений в файловой системе

Почтовые представления находятся в файловой системе, и используемый код представляет путь к файлу представления. Например, отправка почты с кодом `author.plugin::mail.message` использует содержимое следующего файла.

::: dir
├── plugins
|   └── author  _← Сегмент "author"_
|       └── myplugin  _← Сегмент "plugin"_
|           └── `views`
|               └── mail  _← Сегмент "mail"_
|                   └── message.htm  _← Сегмент "message"_
:::

Содержимое файла почтового представления может включать до 3 секций: **конфигурация**, **простой текст** и **HTML-разметка**. Секции разделяются последовательностью `==`. Например:

::: cmstemplate
```ini
subject = "Your product has been added to October CMS project"
```
```twig
Hi {{ name }},

Good news! User {{ user }} just added your product "{{ product }}" to a project.

This message was sent using no formatting (plain text)
```
```twig
<p>Hi {{ name }},</p>

<p>
    <strong>Good news!</strong>
    User {{ user }} just added your product "{{ product }}" to a project.
</p>

<p>This email was sent using formatting (HTML)</p>
```
:::

Секция **простого текста** является необязательной, и представление может содержать только секции **конфигурации** и **HTML-разметки**. Синтаксис Markdown также поддерживается как альтернативный синтаксис.

::: cmstemplate
```ini
layout = "default"
subject = "Your product has been added to October CMS project"
```
```twig
Hi {{ name }},

**Good news!** User {{ user }} just added your product "{{ product }}" to a project.
```
:::

#### Секция конфигурации

Секция конфигурации задаёт свойства почтового представления. Поддерживаются следующие свойства конфигурации.

Свойство | Описание
------------- | -------------
**subject** | тема почтового сообщения, обязательно.
**layout** | код или представление почтового макета, необязательно. Значение по умолчанию — `default`.

### Регистрация шаблонов, макетов и частичных представлений

::: aside
Значение **code** в панели управления будет таким же, как путь к почтовому представлению. Например, `author.plugin:mail.message`.
:::

Почтовые представления могут быть зарегистрированы как шаблоны по умолчанию, создаваемые в панели управления. Шаблоны регистрируются путём переопределения метода `registerMailTemplates` [файла регистрации плагина](../extending.md). Шаблоны могут реализовывать частичные представления и макеты, аналогично CMS-темам, и они регистрируются с помощью `registerMailLayouts` и `registerMailPartials` соответственно.

```php
public function registerMailTemplates()
{
    return [
        // ...Templates defined here
    ];
}

public function registerMailLayouts()
{
    return [
        // ...Layouts defined here
    ];
}

public function registerMailPartials()
{
    return [
        // ...Partials defined here
    ];
}
```

В панели управления, когда сгенерированный шаблон сохраняется впервые, настроенное содержимое будет использоваться при отправке почты для назначенного кода. В этом контексте зарегистрированные почтовые представления могут рассматриваться как представления по умолчанию или запасные.

#### Регистрация шаблона

Ключ `templates` в массиве регистрации используется для регистрации представлений как почтовых шаблонов. Метод должен возвращать массив, где ключ — код шаблона, а значение — имя [пути представления](../services/response-view.md). Код шаблона используется для ссылки на шаблон.

```php
public function registerMailTemplates()
{
    return [
        'rainlab.user:activate' => 'rainlab.user::mail.activate',
        'rainlab.user:restore' => 'rainlab.user::mail.restore',
    ];
}
```

Отправка сообщения использует код шаблона, например.

```php
Mail::send('rainlab.user:activate', ...);
```

#### Регистрация макета

Переопределение метода `registerMailLayouts` используется для регистрации макетов, и каждый макет нуждается в уникальном `code` для идентификации, а также в файле представления по умолчанию для содержимого.

```php
public function registerMailLayouts()
{
    return [
        'marketing' => 'acme.blog::layouts.marketing',
        'notification' => 'acme.blog::layouts.notification',
    ];
}
```

Макет теперь может быть указан в шаблонах с помощью значения `code`.

::: cmstemplate
```ini
layout = "marketing"
```
```twig
Page contents...
```
:::

#### Регистрация частичного представления

Как и макеты, почтовые частичные представления могут быть зарегистрированы с помощью переопределения метода `registerMailPartials`, и каждое частичное представление нуждается в уникальном `code` для идентификации, а также в файле представления по умолчанию для содержимого.

```php
public function registerMailPartials()
{
    return [
        'tracking' => 'acme.blog::partials.tracking',
        'promotion' => 'acme.blog::partials.promotion',
    ];
}
```

Частичное представление теперь может быть указано в шаблонах с помощью тега `{% partial %}` и значения `code`.

```twig
{% partial 'tracking' %}
```

#### Файловые макеты

Для ссылки на файловый макет вы можете передать код представления в свойство **layout**. Например, это почтовое представление ссылается на макет `acme.blog::mail.custom-layout`.

```ini
layout = "acme.blog::mail.custom-layout"
subject = "Your product has been added to October CMS project"
==
...
```

Используя приведённый выше код, система попытается загрузить содержимое макета из пути **plugins/acme/blog/views/mail/custom-layout.htm**, и это содержимое может выглядеть так.

```twig
<html>
<body>
    <h1>HTML Contents</h1>
    <div>
        {{ content|raw }}
    </div>
</body>
</html>
```

::: warning
Содержимое файловых макетов нельзя редактировать в панели администратора.
:::

### Глобальные переменные

Вы можете регистрировать переменные, глобально доступные для всех почтовых шаблонов, с помощью метода `View::share`.

```php
View::share('site_name', 'October CMS');
```

Этот код может быть вызван внутри метода register или boot [файла регистрации плагина](../plugin/registration.md). В приведённом выше примере переменная `{{ site_name }}` будет доступна во всех почтовых шаблонах.

## Отправка почты

Для отправки сообщения используйте метод `send` фасада `Mail`, который принимает три аргумента. Первый аргумент — уникальный почтовый код, используемый для поиска почтового представления или почтового шаблона. Второй аргумент — массив данных, которые вы хотите передать в представление. Третий аргумент — обратный вызов `Closure`, получающий экземпляр сообщения, позволяя вам настраивать получателей, тему и другие аспекты почтового сообщения.

```php
// These variables are available inside the message as Twig
$vars = ['name' => 'Joe', 'user' => 'Mary'];

Mail::send('acme.blog:message', $vars, function($message) {
    $message->to('admin@domain.tld', 'Admin Person');
    $message->subject('This is a reminder');
});
```

Поскольку мы передаём массив, содержащий ключ `name`, в приведённом выше примере, мы можем отобразить значение в нашем представлении электронного письма с помощью следующей Twig-разметки.

```twig
{{ name }}
```

::: warning
Избегайте передачи переменной `message` в ваше сообщение — эта переменная всегда передаётся и позволяет встраивать вложения.
:::

### Быстрая отправка

October CMS также включает альтернативный метод `sendTo`, который может упростить отправку почты.

```php
// Send to address using no name
Mail::sendTo('admin@domain.tld', 'acme.blog:message', $params);

// Send using an object's properties
Mail::sendTo($user, 'acme.blog:message', $params);

// Send to multiple addresses
Mail::sendTo(['admin@domain.tld' => 'Admin Person'], 'acme.blog:message', $params);

// Alternatively send a raw message without parameters
Mail::rawTo('admin@domain.tld', 'Hello friend');
```

Первый аргумент в `sendTo` используется для получателей и может принимать различные типы значений.

Тип | Описание
------------- | -------------
String | один адрес получателя без указания имени.
Array | несколько получателей, где ключ массива — адрес, а значение — имя.
Object | один объект получателя, где свойство *email* используется для адреса, а *name* — опционально для имени.
Collection | коллекция объектов получателей, как описано выше.

Полная сигнатура `sendTo` выглядит следующим образом.

```php
Mail::sendTo($recipient, $message, $params, $callback, $options);
```

- `$recipient` определён как описано выше.
- `$message` — имя шаблона или содержимое сообщения для отправки в сыром виде.
- `$params` — массив переменных, доступных внутри шаблона.
- `$callback` вызывается с одним параметром — построителем сообщения, как описано для метода `send` (необязательно, по умолчанию null). Если значение не является вызываемым, работает как замена следующего аргумента options.
- `$options` — пользовательские параметры отправки, передаваемые как массив (необязательно).

Поддерживаются следующие пользовательские `$options` отправки.

Параметр | Описание
------------- | -------------
**queue** | определяет, ставить ли сообщение в очередь или отправлять напрямую, необязательно. По умолчанию: `false`.
**bcc** | определяет, добавлять ли получателей как Bcc или обычные To адреса. По умолчанию: `false`.

### Построение сообщения

Как упоминалось ранее, третий аргумент метода `send` — это `Closure`, позволяющее указать различные параметры самого почтового сообщения. С помощью этого замыкания вы можете указать другие атрибуты сообщения, такие как копии, скрытые копии и т.д.:

```php
Mail::send('acme.blog:welcome', $vars, function($message) {
    $message->from('us@example.tld', 'October');
    $message->to('foo@example.tld')->cc('bar@example.tld');
});
```

Вот список доступных методов экземпляра построителя сообщений `$message`.

```php
$message->from($address, $name = null);
$message->sender($address, $name = null);
$message->to($address, $name = null);
$message->cc($address, $name = null);
$message->bcc($address, $name = null);
$message->replyTo($address, $name = null);
$message->subject($subject);
$message->priority($level);
$message->attach($pathToFile, array $options = []);

// Attach a file from a raw $data string...
$message->attachData($data, $name, array $options = []);
```

#### Отправка простого текста

По умолчанию представление, переданное методу `send`, считается содержащим почтовое представление, где вы можете указать представление простого текста для отправки в дополнение к HTML-представлению.

```php
Mail::send('acme.blog:message', $data, $callback);
```

Или, если вам нужно отправить только текстовое электронное письмо, вы можете указать это с помощью ключа `text` в массиве:

```php
Mail::send(['text' => 'acme.blog:text'], $data, $callback);
```

#### Отправка обработанных сырых строк

Вы можете использовать метод `raw`, если хотите отправить сырую строку напрямую. Это содержимое будет обработано Markdown.

```php
Mail::raw('Text to e-mail', function ($message) {
    //
});
```

Кроме того, эта строка будет обработана Twig. Если вы хотите передать переменные в эту среду, используйте метод `send`, передав содержимое как ключ `raw`.

```php
Mail::send(['raw' => 'Text to email'], $vars, function ($message) {
    //
});
```

#### Отправка сырых строк

Если вы передаёте массив, содержащий ключи `text` или `html`, это будет явный запрос на отправку почты. Макет и обработка Markdown не используются.

```php
Mail::raw([
    'text' => 'This is plain text',
    'html' => '<strong>This is HTML</strong>'
], function ($message) {
    //
});
```

### Отправка вложений

Для добавления вложений к электронному письму используйте метод `attach` объекта `$message`, переданного в ваше замыкание. Метод `attach` принимает полный путь к файлу в качестве первого аргумента:

```php
Mail::send('acme.blog:welcome', $data, function ($message) {
    //

    $message->attach($pathToFile);
});
```

При прикреплении файлов к сообщению вы также можете указать отображаемое имя и/или MIME-тип, передав `array` вторым аргументом метода `attach`:

```php
$message->attach($pathToFile, ['as' => $display, 'mime' => $mime]);
```

### Встроенные вложения

#### Встраивание изображения в содержимое письма

Встраивание встроенных изображений в электронные письма обычно затруднительно, однако существует удобный способ прикрепления изображений и получения соответствующего CID. Для встраивания встроенного изображения используйте метод `embed` переменной `message` в вашем представлении письма. Помните, переменная `message` доступна во всех ваших почтовых представлениях:

```twig
<body>
    Here is an image:

    <img src="{{ message.embed(pathToFile) }}">
</body>
```

Если вы планируете использовать очереди для отправки писем, убедитесь, что путь к файлу является абсолютным. Для этого можно просто использовать [фильтр app](../../markup/filter/app.md):

```twig
<body>
    Here is an image:
    {% set pathToFile = 'storage/app/media/path/to/file.jpg'|app %}
    <img src="{{ message.embed(pathToFile) }}">
</body>
```

#### Встраивание сырых данных в содержимое письма

Если у вас уже есть строка сырых данных, которую вы хотите встроить в почтовое сообщение, вы можете использовать метод `embedData` переменной `message`:

```twig
<body>
    Here is an image from raw data:

    <img src="{{ message.embedData(data, name) }}">
</body>
```

## Очередь почты

### Постановка почтового сообщения в очередь

Поскольку отправка почтовых сообщений может значительно увеличить время ответа вашего приложения, многие разработчики предпочитают ставить сообщения в очередь для фоновой отправки. Это легко сделать с помощью встроенного [унифицированного API очередей](../services/queue.md). Для постановки почтового сообщения в очередь используйте метод `queue` фасада `Mail`:

```php
Mail::queue('acme.blog:welcome', $data, function ($message) {
    //
});
```

Этот метод автоматически добавит задачу в очередь для отправки почтового сообщения в фоновом режиме. Конечно, перед использованием этой функции необходимо [настроить очереди](../services/queue.md).

### Отложенная постановка в очередь

Если вы хотите задержать доставку поставленного в очередь электронного письма, используйте метод `later`. Для начала просто передайте количество секунд задержки отправки сообщения первым аргументом метода.

```php
Mail::later(5, 'acme.blog:welcome', $data, function ($message) {
    //
});
```

### Отправка в конкретные очереди

Если вы хотите указать конкретную очередь для отправки сообщения, используйте методы `queueOn` и `laterOn`:

```php
Mail::queueOn('queue-name', 'acme.blog:welcome', $data, function ($message) {
    //
});

Mail::laterOn('queue-name', 5, 'acme.blog:welcome', $data, function ($message) {
    //
});
```
