# Модели

October CMS предоставляет красивую и простую реализацию Active Record для работы с вашей базой данных, основанную на [Eloquent от Laravel](http://laravel.com/docs/eloquent). Каждая таблица базы данных имеет соответствующую «Модель», которая используется для взаимодействия с этой таблицей. Модели позволяют запрашивать данные из таблиц, а также вставлять новые записи.

Классы моделей находятся в поддиректории **models** директории плагина. Пример структуры директории модели.

::: dir
├── plugins
|   └── acme
|       └── blog
|           ├── `models`
|           |   ├── post  _← Директория конфигурации_
|           |   |   ├── fields.yaml  _← Файл конфигурации_
|           |   |   └── columns.yaml  _← Файл конфигурации_
|           |   └── Post.php  _← Класс модели_
|           └── Plugin.php
:::

Директория конфигурации модели может содержать [определения полей формы](../../element/form-fields.md) модели. Имя директории конфигурации модели совпадает с именем класса модели в нижнем регистре.

## Определение моделей

Команда `create:model` генерирует файлы, необходимые для новой модели. Первый аргумент указывает имя автора и плагина. Второй аргумент указывает имя класса модели.

```bash
php artisan create:model Acme.Blog Post
```

В большинстве случаев для каждой таблицы базы данных следует создавать один класс модели. Все классы моделей должны наследовать класс `Model`. Самое базовое представление модели, используемой внутри плагина, выглядит так.

```php
namespace Acme\Blog\Models;

use Model;

class Post extends Model
{
    protected $table = 'acme_blog_posts';
}
```

Защищённое поле `$table` указывает таблицу базы данных, соответствующую модели. Имя таблицы представляет собой snake_case имя автора, плагина и множественное число типа записи.

### Поддерживаемые свойства

Существует ряд стандартных свойств моделей, помимо тех, что предоставляются [трейтами моделей](traits.md). Например:

```php
class User extends Model
{
    protected $primaryKey = 'id';

    public $exists = false;

    protected $dates = ['last_seen_at'];

    public $timestamps = true;

    protected $jsonable = ['permissions'];

    protected $guarded = ['*'];
}
```

Свойство | Описание
------------- | -------------
**$primaryKey** | имя первичного ключа, используемого для идентификации модели.
**$incrementing** | логическое значение, если false — указывает, что первичный ключ не является автоинкрементным целым числом.
**$exists** | логическое значение, если true — указывает, что модель существует.
**$dates** | значения преобразуются в экземпляры объектов Carbon/DateTime после извлечения.
**$timestamps** | логическое значение, если true — автоматически устанавливает поля created_at и updated_at.
**$jsonable** | значения кодируются как JSON перед сохранением и преобразуются в массивы после извлечения.
**$fillable** | значения — поля, доступные для массового присваивания.
**$guarded** | значения — поля, защищённые от массового присваивания.
**$visible** | значения — поля, видимые при [сериализации данных модели](../database/serialization.md).
**$hidden** | значения — поля, скрытые при [сериализации данных модели](../database/serialization.md).
**$connection** | строка, содержащая [имя подключения](../../setup/database-config.md), используемого моделью по умолчанию.

#### Первичный ключ

Модели предполагают, что каждая таблица имеет столбец первичного ключа с именем `id`. Вы можете определить свойство `$primaryKey` для переопределения этой конвенции.

```php
class Post extends Model
{
    protected $primaryKey = 'id';
}
```

#### Автоинкремент

Модели предполагают, что первичный ключ является автоинкрементным целым числом, что означает, что по умолчанию первичный ключ будет автоматически приведён к целому числу. Если вы хотите использовать неинкрементный или нечисловой первичный ключ, установите публичное свойство `$incrementing` в false.

```php
class Message extends Model
{
    public $incrementing = false;
}
```

#### Метки времени

По умолчанию модель ожидает наличия столбцов `created_at` и `updated_at` в ваших таблицах. Если вы не хотите, чтобы эти столбцы управлялись автоматически, установите свойство `$timestamps` модели в `false`.

```php
class Post extends Model
{
    public $timestamps = false;
}
```

Если вам нужно настроить формат меток времени, установите свойство `$dateFormat` модели. Это свойство определяет, как атрибуты дат хранятся в базе данных, а также их формат при сериализации модели в массив или JSON.

```php
class Post extends Model
{
    protected $dateFormat = 'U';
}
```

#### Значения, хранящиеся как JSON

Когда имена атрибутов передаются в свойство `$jsonable`, значения будут сериализованы и десериализованы из базы данных как JSON.

```php
class Post extends Model
{
    protected $jsonable = ['data'];
}
```

## События модели

Модели генерируют несколько событий, позволяя вам подключаться к различным точкам жизненного цикла модели. События позволяют легко выполнять код каждый раз, когда определённый класс модели сохраняется или обновляется в базе данных. События определяются путём переопределения специальных методов в классе, доступны следующие переопределения методов:

Событие | Описание
------------- | -------------
**beforeCreate** | перед сохранением модели при первом создании.
**afterCreate** | после сохранения модели при первом создании.
**beforeSave** | перед сохранением модели, будь то создание или обновление.
**afterSave** | после сохранения модели, будь то создание или обновление.
**beforeValidate** | перед валидацией предоставленных данных модели.
**afterValidate** | после валидации предоставленных данных модели.
**beforeUpdate** | перед сохранением существующей модели.
**afterUpdate** | после сохранения существующей модели.
**beforeDelete** | перед удалением существующей модели.
**afterDelete** | после удаления существующей модели.
**beforeRestore** | перед восстановлением мягко удалённой модели.
**afterRestore** | после восстановления мягко удалённой модели.
**beforeFetch** | перед заполнением существующей модели.
**afterFetch** | после заполнения существующей модели.

Пример использования события.

```php
public function beforeCreate()
{
    $this->slug = Str::slug($this->name);
}
```

### Базовое использование

Каждый раз, когда новая модель сохраняется впервые, будут вызваны события `beforeCreate` и `afterCreate`. Если модель уже существовала в базе данных и вызывается метод `save`, будут вызваны события `beforeUpdate` / `afterUpdate`. Однако в обоих случаях будут вызваны события `beforeSave` / `afterSave`.

Например, определим обработчик события, который заполняет атрибут `slug` при первом создании модели.

```php
public function beforeCreate()
{
    $this->slug = Str::slug($this->name);
}
```

Возврат `false` из события отменит операцию `save` / `update`.

```php
public function beforeCreate()
{
    if (!$user->isValid()) {
        return false;
    }
}
```

Можно получить доступ к старым значениям с помощью атрибута `original`. Например:

```php
public function afterUpdate()
{
    if ($this->title !== $this->original['title']) {
        // Title has changed
    }
}
```

Вы можете обнаружить, что связи, созданные с использованием [отложенных привязок](../database/relations.md) (например, вложения файлов), ещё недоступны внутри событий модели. Для раннего доступа к ним используйте метод запроса к базе данных `withDeferred` на связи.

```php
public function beforeCreate()
{
    $avatar = $this->avatar()->withDeferred()->first();

    $gallery = $this->gallery()->withDeferred()->get();
}
```

Вы можете внешне привязаться к [локальным событиям](../services/event.md) для одного экземпляра модели с помощью метода `bindEvent`. Имя события должно совпадать с именем переопределяемого метода с префиксом `model.`.

```php
$flight = new Flight;
$flight->bindEvent('model.beforeCreate', function() use ($model) {
    $model->slug = Str::slug($model->name);
});
```

## Расширение моделей

Поскольку модели [приспособлены для использования поведений](./behaviors.md), они могут быть расширены с помощью статического метода `extend`. Метод принимает замыкание и передаёт в него объект модели.

Внутри замыкания вы можете добавлять связи к модели. Здесь мы расширяем модель `User`, добавляя связь профиля (has one), ссылающуюся на модель `Profile`.

```php
User::extend(function($model) {
    $model->hasOne['profile'] = [Profile::class, 'key' => 'user_id'];
});
```

Этот подход также можно использовать для привязки к локальным событиям. Следующий код прослушивает событие `model.beforeSave`.

```php
User::extend(function($model) {
    $model->bindEvent('model.beforeSave', function() use ($model) {
        // ...
    });
});
```

Кроме того, существует несколько методов для расширения защищённых свойств модели.

```php
User::extend(function($model) {
    // Add cast attributes
    $model->addCasts([
        'some_extended_field' => 'int',
    ]);

    // Add a date attribute
    $model->addDateAttribute('updated_at');

    // Adds fillable or jsonable fields
    $model->addFillable('first_name');
    $model->addJsonable('some_data');
});
```

Как правило, лучшее место для размещения кода — метод `boot` вашего [файла регистрации плагина](../extending.md), так как он выполняется при каждом запросе, обеспечивая доступность ваших расширений модели везде.
