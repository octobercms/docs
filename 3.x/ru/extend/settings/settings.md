# Введение

Существует два основных способа настройки системы плагинами. Рекомендуется сначала определить, какой вариант лучше подходит для ваших требований.

- [Файловая конфигурация](./file-settings.md) без пользовательского интерфейса, хранящаяся в файловой системе.
- [Настройки на основе модели](./model-settings.md) с необязательным пользовательским интерфейсом, хранящиеся в базе данных.

Использование настроек на основе модели со страницами панели управления обеспечивает лучший пользовательский опыт, но требует больших затрат на начальную разработку. Файловая конфигурация подходит для конфигурации, которая редко изменяется и не имеет интерфейса, например для настройки политик.

## Регистрация страницы настроек

При использовании настроек на основе модели вы можете опционально зарегистрировать их в специальной области для управления настройками и конфигурацией, доступной по нажатию ссылки **Настройки** в главном меню.

Страницы настроек должны быть зарегистрированы путём переопределения метода `registerSettings` в [файле регистрации плагина](../extending.md). Метод возвращает массив с ключом для каждого элемента настроек и значением, настраивающим модель или контроллер настроек для отображения в области настроек. Ниже приведён пример регистрации модели настроек.

```php
public function registerSettings()
{
    return [
        'settings' => [
            'label' => 'User Settings',
            'description' => 'Manage user based settings.',
            'category' => 'CATEGORY_USERS',
            'icon' => 'icon-cog',
            'class' => \Acme\User\Models\UserSetting::class,
        ]
    ];
}
```

### Свойства настроек

Следующие свойства доступны для каждого ключа при регистрации настроек.

Свойство | Описание
------------- | -------------
**label** | указывает ключ строки локализации метки меню, обязательно.
**category** | указывает ключ строки локализации метки категории для группировки страниц настроек, обязательно.
**keywords** | указывает ключевые слова, используемые для поиска настроек.
**order** | числовой вес при определении порядка отображения.
**icon** | имя иконки из [коллекции иконок October CMS](../../element/available-icons.md), необязательно.
**iconSvg** | SVG-иконка для использования вместо стандартной иконки, SVG-иконка должна быть прямоугольной и может поддерживать цвета, необязательно.
**url** | URL панели управления, на который должен ссылаться элемент меню, например `Backend::url('author/plugin/controller/action')`.
**class** | класс модели, на который должен ссылаться элемент настроек, например `Acme\User\Models\UserSetting::class`.
**permissions** | массив разрешений, которые должен иметь пользователь панели управления для просмотра элемента меню (Примечание: прямой доступ по URL по-прежнему требует отдельных проверок разрешений), необязательно.
**context** | указывает размещение элемента настроек: `system` или `mysettings`. По умолчанию: `system`.
**size** | размер формы настроек при использовании с определением `class`. Поддерживаемые значения: `tiny`, `small`, `medium`, `large`, `huge`, `giant`, `adaptive`. По умолчанию: `large`.

Для совместимости с другими плагинами доступны следующие общие константы для свойства `category`.

<div class="content-list" markdown="1">

- CATEGORY_CMS
- CATEGORY_MISC
- CATEGORY_MAIL
- CATEGORY_LOGS
- CATEGORY_SHOP
- CATEGORY_TEAM
- CATEGORY_USERS
- CATEGORY_SOCIAL
- CATEGORY_SYSTEM
- CATEGORY_EVENTS
- CATEGORY_BACKEND
- CATEGORY_CUSTOMERS
- CATEGORY_MYSETTINGS
- CATEGORY_NOTIFICATIONS
- CATEGORY_GLOBALS
- CATEGORY_COLLECTIONS

</div>

Необязательный параметр `keywords` используется функцией поиска настроек. Если ключевые слова не указаны, поиск использует только метку и описание элемента настроек.

## Привязка к классу модели

При привязке к `class` модели, указанному в свойствах настроек, вам не нужно создавать собственный контроллер, и это полезно для большинства случаев. Следующий пример создаёт ссылку на модель настроек, подробнее описанную в [статье о настройках модели](./model-settings.md).

```php
public function registerSettings()
{
    return [
        'settings' => [
            'label' => 'User Settings',
            'description' => 'Manage user based settings.',
            'category' => 'Users',
            'icon' => 'icon-cog',
            'class' => \Acme\User\Models\UserSetting::class,
            'order' => 500,
            'keywords' => 'security location',
            'permissions' => ['acme.users.access_settings']
        ]
    ];
}
```

Для формы используется универсальный контроллер панели управления с базовыми функциями, такими как сохранение и сброс значений по умолчанию. Активная навигация настраивается автоматически. Определённые разрешения также применяются контроллером.

## Привязка к классу контроллера

При указании `url` страницы в свойствах настроек вы можете создать собственный контроллер и связать его в области настроек. Следующий пример показывает, как создать ссылку на страницу панели управления.

```php
public function registerSettings()
{
    return [
        'location' => [
            'label' => 'Locations',
            'description' => 'Manage available user countries and states.',
            'category' => 'Users',
            'icon' => 'icon-globe',
            'url' => Backend::url('acme/user/locations'),
            'order' => 500,
            'keywords' => 'geography place placement'
        ]
    ];
}
```

### Определение класса страницы настроек

Контроллеры страниц настроек могут быть любыми [контроллерами панели управления](../system/controllers.md), но для упрощения вы можете наследовать базовый класс `Backend\Classes\SettingsController`. Этот класс автоматически регистрирует контекст навигации настроек в контроллере. Вам нужно лишь указать код настроек в свойстве `$settingsItemCode`, используемом для определения активного элемента меню.

```php
namespace Acme\Blog\Controllers;

class Posts extends \Backend\Classes\SettingsController
{
    public $settingsItemCode = 'location';

    public function index() {}
}
```
