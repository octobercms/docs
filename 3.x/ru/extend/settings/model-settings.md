# Настройки модели

Настройки модели хранят значения в базе данных и могут быть переопределены через пользовательский интерфейс в панели управления.

## Настройки базы данных

Плагины могут использовать конфигурацию на основе базы данных, используя модели для хранения настроек в базе данных, наследуя базовый класс `System\Models\SettingModel`. Эта модель может использоваться непосредственно для создания формы настроек панели управления. Вам не нужно создавать таблицу базы данных и контроллер для создания форм настроек панели управления на основе модели настроек. Пример структуры директории модели настроек:

::: dir
├── plugins
|   └── acme
|       └── demo
|           ├── models
|           |   ├── usersetting  _← Директория конфигурации_
|           |   |   └── fields.yaml  _← Поля формы_
|           |   └── `UserSetting.php`  _← Класс модели_
|           └── Plugin.php
:::

Модели настроек могут быть зарегистрированы для отображения в [области настроек панели управления](./settings.md), но это не является обязательным — вы можете устанавливать и читать значения настроек как любую другую модель.

### Определение класса модели

Классы моделей настроек должны наследовать класс `System\Models\SettingModel` и, как любая другая модель, должны быть определены в поддиректории **models** директории плагина. Модель из следующего примера должна быть определена в файле **plugins/acme/demo/models/UserSetting.php**.

```php
namespace Acme\Demo\Models;

class UserSetting extends \System\Models\SettingModel
{
    public $settingsCode = 'acme_demo_settings';

    public $settingsFields = 'fields.yaml';
}
```

Свойство `$settingsCode` является обязательным для моделей настроек. Оно определяет уникальный ключ настроек, который используется для сохранения настроек в базе данных.

Свойство `$settingsFields` является обязательным, если вы собираетесь создать форму настроек панели управления на основе модели. Свойство указывает имя YAML-файла, содержащего определение полей формы. Поля формы описаны в [статье о контроллере форм](../forms/form-controller.md). YAML-файл должен быть размещён в директории с именем, совпадающим с именем класса модели в нижнем регистре.

## Запись в модель настроек

Модель настроек имеет статический метод `set`, который позволяет сохранять отдельные или множественные значения. Вы также можете использовать стандартные возможности модели для установки свойств модели и сохранения модели.

```php
use Acme\Demo\Models\UserSetting;

// Set a single value
UserSetting::set('api_key', 'ABCD');

// Set an array of values
UserSetting::set(['api_key' => 'ABCD']);

// Set object values
$settings = UserSetting::instance();
$settings->api_key = 'ABCD';
$settings->save();
```

## Чтение из модели настроек

Модель настроек имеет статический метод `get`, который позволяет загружать отдельные свойства. Также, когда вы создаёте экземпляр модели с помощью метода `instance`, он загружает свойства из базы данных, и вы можете обращаться к ним напрямую.

```php
// Outputs: ABCD
echo UserSetting::instance()->api_key;

// Get a single value
echo UserSetting::get('api_key');

// Get a value and return a default value if it doesn't exist
echo UserSetting::get('is_activated', true);
```

## Интеграция с мультисайтом

Модели настроек могут предоставлять различные значения конфигурации для каждого сайта, определённого [конфигурацией мультисайта](../../cms/resources/multisite.md). Для включения мультисайта добавьте [трейт](../database/traits.md) `October\Rain\Database\Traits\Multisite` в модель и определите свойство `$propagatable`, которое может указывать поля, распространяющиеся на все сайты.

```php
namespace Acme\Demo\Models;

class UserSetting extends \System\Models\SettingModel
{
    use \October\Rain\Database\Traits\Multisite;

    public $settingsCode = 'acme_demo_settings';

    public $settingsFields = 'fields.yaml';

    protected $propagatable = [];
}
```
