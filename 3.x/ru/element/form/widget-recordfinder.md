# Поле Record Finder

`recordfinder` — рендерит поле с деталями связанной записи. При раскрытии поля отображается всплывающий список для поиска среди большого количества записей. Поддерживается только единичными отношениями.

```yaml
user:
    label: User
    type: recordfinder
    list: ~/plugins/rainlab/user/models/user/columns.yaml
```

Поддерживаются и обычно используются следующие [свойства поля](../form-fields.md).

Свойство | Описание
------------- | -------------
**label** | имя при отображении поля формы пользователю.
**default** | значение по умолчанию (строка), необязательно.
**comment** | пояснительный комментарий под полем.
**keyFrom** | имя столбца в отношении, используемого для ключа. По умолчанию: `id`.
**nameFrom** | имя столбца в отношении, используемого для отображения имени. По умолчанию: `name`.
**descriptionFrom** | имя столбца в отношении, используемого для отображения описания. По умолчанию: `description`.
**title** | текст для отображения в заголовке всплывающего окна.
**list** | массив конфигурации или ссылка на файл определения столбцов списка.
**filter** | ссылка на файл определения областей фильтрации, см. [фильтры списков](../../extend/lists/filters.md).
**showSetup** | отображает кнопку настройки для конфигурации столбцов списка и количества записей на странице. По умолчанию: `false`
**structure** | включает структурированный список только для чтения для выбора записей, см. [статью о сортировке записей](../../extend/lists/structures.md). Установите `false` для отключения, иначе включается, когда модель использует древовидный интерфейс.
**defaultSort** | устанавливает столбец сортировки и направление по умолчанию, когда предпочтения пользователя не определены. Поддерживает строку или массив с ключами `column` и `direction`. Направление может быть `asc` для возрастающего (по умолчанию) или `desc` для убывающего порядка.
**recordsPerPage** | количество записей на странице, используйте 0 для отключения пагинации. По умолчанию: `10`
**conditions** | задаёт необработанное условие where для применения к запросу модели списка.
**modelScope** | применяет метод [области запроса модели](../../extend/database/model.md) к **связанной модели формы**, может быть именем метода модели или статическим методом PHP-класса (`Class::method`). Первый аргумент будет содержать модель, к которой виджет будет прикреплять своё значение, т.е. родительскую модель.
**searchMode** | определяет стратегию поиска: все слова, любое слово или точная фраза. Поддерживаемые варианты: all, any, exact. По умолчанию: `all`.
**searchScope** | задаёт метод [области запроса модели](../../extend/database/model.md), определённый в **связанной модели формы**, для применения к поисковому запросу, первый аргумент будет содержать поисковый термин.
**useRelation** | флаг для использования имени поля как имени отношения для прямого взаимодействия с родительской моделью. По умолчанию: `true`. Отключите для возврата только ID выбранной модели.
**modelClass** | класс модели для списка записей, когда `useRelation` установлен в `false`.
**popupSize** | изменяет размер всплывающего окна поиска: `giant`, `huge`, `large`, `small`, `tiny` или `adaptive`. По умолчанию: `huge`
**inlineOptions** | отображает поле с кнопками рядом с выбранной записью, отключите этот режим при ограниченном горизонтальном пространстве. По умолчанию: `true`.

Вы можете ограничить количество записей на странице с помощью свойства `recordsPerPage`.

```yaml
user:
    label: User
    type: recordfinder
    recordsPerPage: 10
```

Используйте свойство `title` для изменения заголовка формы управления.

```yaml
user:
    label: User
    type: recordfinder
    title: Find A User
```

При выборе записи атрибуты отображения могут быть выбраны из атрибутов модели с помощью свойств `nameFrom` и `descriptionFrom`.

```yaml
user:
    label: User
    type: recordfinder
    nameFrom: name
    descriptionFrom: email
```

Если обнаружена [структура модели](../../extend/lists/structures.md), список будет отображаться как структура. Это можно явно отключить или включить с помощью свойства **structure**.

```yaml
user:
    label: User
    type: recordfinder
    structure: false
```

## Использование в Tailor

Когда поле `recordfinder` используется как [контентное поле в Tailor](../../cms/tailor/content-fields.md), необходимо указать свойство `modelClass` для определения и нахождения отношения модели.

```yaml
products:
    label: Products
    type: recordfinder
    modelClass: Acme\Test\Models\Product
    list: $/october/test/models/product/columns.yaml
```

Когда `maxItems` установлен в **1**, отношение определяется как `belongsTo`. В противном случае отношение определяется как `belongsToMany`.

```yaml
products:
    label: Products
    type: recordfinder
    modelClass: Acme\Test\Models\Tag
    maxItems: 1
```

Свойство `inverse` может быть установлено в имя отношения на связанной модели. Это изменит определение отношения на `hasOne`, `hasMany` или `belongsToMany` в зависимости от настройки `maxItems` и типа отношения связанной модели.

```yaml
tags:
    label: Tags
    type: recordfinder
    modelClass: Acme\Test\Models\Tag
    inverse: tags
```
