# Поля формы

Поля формы, элементы UI формы и виджеты формы — это определения полей, используемые формами, например, текстовое поле ввода. Они обычно применяются в следующих областях:

- [Настройки темы CMS](../cms/themes/settings.md)
- [Поля контента Tailor](../cms/tailor/content-fields.md)
- [Контроллер форм панели администрирования](../extend/forms/form-controller.md)
- [Контроллер связей панели администрирования](../extend/forms/relation-controller.md)

Все поля формы идентифицируются по их индивидуальному свойству **type**.

```yaml
fields:
    myfield:
        type: textarea
        # ...
```

Поля формы содержат общие и простые поля. Элементы UI формы — это элементы пользовательского интерфейса, которые можно включить в формы для улучшения дизайна макета. Виджеты формы часто предоставляют более сложную функциональность, плагины обычно предоставляют собственные пользовательские виджеты формы. Поля Tailor — это поля, доступные только внутри чертежей Tailor.

## Свойства полей

Для каждого поля можно указать следующие общие свойства, где применимо.

Свойство | Описание
------------- | -------------
**label** | имя, отображаемое при показе поля формы пользователю.
**type** | определяет, как это поле должно рендериться. По умолчанию: `text`.
**span** | выравнивает поле формы по одной стороне. Варианты: `auto`, `left`, `right`, `row`, `full`. По умолчанию: `full`.
**spanClass** | используется вместе со свойством span `row` для отображения формы в виде сетки Bootstrap, например, `spanClass: col-4`.
**size** | определяет размер поля для полей, которые его используют, например, textarea. Варианты: `tiny`, `small`, `large`, `huge`, `giant`.
**placeholder** | если поле поддерживает значение placeholder.
**comment** | размещает описательный комментарий под полем.
**commentAbove** | размещает комментарий над полем.
**commentHtml** | разрешает HTML-разметку внутри комментария. Варианты: `true`, `false`.
**default** | определяет значение по умолчанию для поля. Для виджетов `dropdown`, `checkboxlist`, `radio` и `balloon-selector` можно указать ключ опции для выбора по умолчанию.
**defaultFrom** | берёт значение по умолчанию из значения другого атрибута модели.
**tab** | назначает поле на вкладку.
**cssClass** | назначает CSS-класс контейнеру поля.
**autoFocus** | помечает поле для фокусировки при загрузке формы. По умолчанию: `false`.
**readOnly** | предотвращает изменение поля. Варианты: `true`, `false`.
**disabled** | предотвращает изменение поля и исключает его из сохраняемых данных. Варианты: `true`, `false`.
**hidden** | скрывает поле из представления и исключает его из сохраняемых данных. Варианты: `true`, `false`.
**stretch** | определяет, растягивается ли это поле по высоте родителя.
**context** | определяет, какой контекст следует использовать при отображении поля. Контекст также можно передать, используя символ `@` в имени поля, например, `name@update`.
**dependsOn** | массив имён других полей, от которых [зависит](../extend/forms/field-dependencies.md) это поле. При изменении других полей это поле обновится.
**changeHandler** | имя AJAX-обработчика для вызова при изменении значения поля, необязательно.
**trigger** | определяет условия для этого поля с использованием событий триггера.
**preset** | позволяет начально устанавливать значение поля по значению другого поля, преобразованному с помощью конвертера предустановки ввода.
**required** | размещает красную звёздочку рядом с меткой поля для обозначения обязательности. Убедитесь, что используете [трейт валидации в модели](../extend/database/traits.md), так как это не обеспечивается контроллером формы.
**attributes** | определяет пользовательские HTML-атрибуты для добавления к элементу поля формы.
**containerAttributes** | определяет пользовательские HTML-атрибуты для добавления к контейнеру поля формы.
**order** | числовой вес при определении порядка отображения, значение по умолчанию увеличивается на 100 для каждого поля.
**permissions** | [разрешения](../extend/backend/permissions.md), которые должен иметь текущий пользователь панели администрирования для использования поля. Поддерживает строку для одного разрешения или массив разрешений, из которых достаточно одного для предоставления доступа.

### Свойства вкладок

Пример определения полей во вкладках.

```yaml
tabs:
    fields:
        username:
            type: text
            label: Username
            tab: User

        groups:
            type: relation
            label: Groups
            tab: Groups
```

Для каждого определения вкладок, а именно `tabs` и `secondaryTabs`, можно указать следующие свойства.

Свойство | Описание
------------- | -------------
**stretch** | определяет, растягивается ли эта вкладка по высоте родителя.
**defaultTab** | вкладка по умолчанию для назначения полей. По умолчанию: Misc.
**activeTab** | выбранная вкладка при первой загрузке формы, имя или индекс. По умолчанию: `1`
**icons** | назначает иконки вкладкам, используя имена вкладок в качестве ключа.
**lazy** | массив вкладок, загружаемых динамически при клике. Полезно для вкладок с большим количеством контента.
**identifiers** | массив пользовательских HTML-идентификаторов для вкладок. Полезно для показа и скрытия вкладок с помощью JavaScript.
**linkable** | определяет, могут ли вкладки быть связаны с помощью фрагментов URL. По умолчанию: `true`
**cssClass** | назначает CSS-класс контейнеру вкладок.
**paneCssClass** | назначает CSS-класс отдельной панели вкладки. Значение — массив, ключ — индекс или метка вкладки, значение — CSS-класс. Также может быть указано как строка, в этом случае значение будет применено ко всем вкладкам.

Пример применения свойств к вкладкам.

```yaml
tabs:
    stretch: true
    defaultTab: User
    cssClass: text-blue

    lazy:
        - Groups

    paneCssClass:
        1: first-tab
        2: second-tab

    icons:
        User: icon-user
        Groups: icon-group

    identifiers:
        User: userTab

    fields:
        # [...]
```

### Пользовательские типы полей

Существуют различные встроенные типы полей, которые можно использовать для настройки **type**. Также возможно рендерить поле напрямую, указав имя PHP-класса [виджета поля формы](../extend/forms/form-widgets.md).

```yaml
blog_content:
    type: Backend\FormWidgets\RichEditor
    size: huge
```

### Вложенный выбор полей

```yaml
avatar[name]:
    label: Avatar
    comment: will be saved in the Avatar table
```

Приведённый выше пример будет получать и сохранять значение в PHP-эквиваленте `$record->avatar->name` или `$record->avatar['name']` соответственно.

### Фасады полей

Иногда вам может потребоваться отобразить поле, предотвратив его отправку. Поле можно определить как фасад, добавив символ подчёркивания (\_) перед именем поля. Эти поля очищаются автоматически и больше не сохраняются в модели, как в следующем примере с полем `_map`.

```yaml
address:
    label: Title
    type: text

_map:
    label: Point your address on the map
    type: mapviewer
```

## Условия полей

Иногда вам может потребоваться изменить значение или внешний вид поля формы при определённых условиях, например, скрыть поле ввода при установке флажка или предустановить значение другого поля.

### События триггера

События триггера определяются с помощью свойства `trigger` поля формы и представляют собой простое решение на стороне браузера с использованием JavaScript. Они позволяют изменять атрибуты элементов, такие как видимость или значение, на основе состояния другого элемента. Вот пример определения:

```yaml
is_delayed:
    label: Send later
    comment: Place a tick in this box if you want to send this message at a later time.
    type: checkbox

send_at:
    label: Send date
    type: datepicker
    cssClass: field-indent
    trigger:
        action: show
        field: is_delayed
        condition: checked
```

В приведённом выше примере поле формы `send_at` будет отображаться только если поле `is_delayed` отмечено. Другими словами, поле покажется (action), если другое поле ввода (field) отмечено (condition).

Определение `trigger` указывает следующие свойства.

Свойство | Описание
------------- | -------------
**action** | определяет действие, применяемое к этому полю при выполнении условия. Поддерживаемые значения: `show`, `hide`, `enable`, `disable`, `empty`, `fill[somevalue]`.
**field** | ссылка на имя другого поля, которое запускает действие. Пример: `color` или `color[]`.
**condition** | определяет условие, которому должно удовлетворять указанное поле для того, чтобы условие считалось `true`. Поддерживаемые значения: `checked`, `unchecked`, `value[somevalue]`.

#### Множественные действия

Вы можете комбинировать несколько действий, разделяя их символом вертикальной черты `|`. Следующее определение одновременно покажет и очистит поле ввода при выполнении условия триггера.

```yaml
trigger:
    action: show|empty
    condition: checked
    field: name
```

#### Множественные условия значений

При использовании условия `value[]` вы можете проверять несколько значений, передавая дополнительные значения после первого в формате `value[][]`.

```yaml
trigger:
    action: show
    condition: value[csv][csv_custom]
    field: file_format
```

#### Условия значений с подстановочными символами

Вы можете проверить, соответствует ли условие `value[]` нескольким возможным значениям, используя подстановочный символ (`*`), например, **foo\*** соответствует всему, что начинается с "foo", а **\*bar** — всему, что заканчивается на "bar".

```yaml
trigger:
    action: show
    condition: value[*.mp4]
    field: file_name
```

#### Множественные значения полей

Некоторые поля, такие как [Checkbox List](./form/field-checkboxlist.md) и [Tag List](./form/widget-taglist.md), хранят свои значения как массив. При ссылке на эти поля имя поля должно использовать суффикс массива (`[]`) для проверки всех возможных значений. Например, если поле `colors` поддерживает множественные значения, в качестве ссылки следует использовать имя поля `colors[]`.

```yaml
trigger:
    action: show
    condition: value[red][green]
    field: colors[]
```

#### Ссылка на родительские поля

Обычно имя поля ссылается на поле того же уровня формы. Например, если это поле находится в [виджете repeater](./form/widget-repeater.md), проверяются только поля того же виджета repeater. Однако если перед именем поля стоит символ каретки `^`, например: `^parent_field`, он будет ссылаться на виджет repeater или форму на один уровень выше.

В приведённом ниже примере поле `colors` будет показано, когда поле `type` установлено в **Complex**.

```yaml
fields:
    type:
        label: Type
        type: dropdown
        options:
            1: Simple
            2: Complex

    content:
        label: Content
        type: nestedform
        form:
            fields:
                colors:
                    label: Colors
                    type: colorpicker
                    trigger:
                        action: show
                        field: ^type
                        condition: value[2]
```

::: tip
Кроме того, если используется более одного символа `^`, он будет ссылаться на соответствующее количество уровней выше: `^^grand_parent_field`, `^^^grand_grand_parent_field` и т.д.
:::

### Конвертер предустановки ввода

Конвертер предустановки ввода определяется с помощью свойства `preset` поля формы и позволяет конвертировать текст, введённый в элемент, в значение URL, slug или имени файла в другом элементе ввода.

В этом примере мы автоматически заполним значение поля `url`, когда пользователь вводит текст в поле `title`. Если для заголовка набран текст **Hello world**, URL последует с преобразованным значением **/hello-world**. Это поведение будет происходить только когда поле назначения (`url`) пусто и не тронуто.

```yaml
title:
    label: Title

url:
    label: URL
    preset:
        field: title
        type: url
```

В качестве альтернативы значение `preset` также может быть строкой, ссылающейся только на **field**, опция `type` тогда по умолчанию будет **slug**.

```yaml
slug:
    label: Slug
    preset: title
```

Для опции `preset` доступны следующие параметры:

Опция | Описание
------------- | -------------
**field** | определяет имя другого поля, из которого берётся значение.
**type** | определяет тип конвертации. Поддерживаемые значения см. ниже.
**prefixInput** | необязательно, добавляет к конвертированному значению префикс значения из указанного элемента ввода, используя CSS-селектор.

Поддерживаются следующие типы:

Тип | Описание
------------- | -------------
**exact** | копирует точное значение
**slug** | форматирует скопированное значение как slug
**url** | то же, что slug, но с префиксом /
**camel** | форматирует скопированное значение в camelCase
**file** | форматирует скопированное значение как имя файла с заменой пробелов на дефисы
