# {% content %}

Тег `{% content %}` отображает [блок контента CMS](../../cms/themes/content.md) на странице. Чтобы отобразить блок контента с именем **contacts.htm**, передайте имя файла после тега `content` в кавычках как строку.

```twig
{% content "contacts.htm" %}
```

Блок контента в поддиректории рендерится аналогичным образом.

```twig
{% content "sidebar/content.htm" %}
```

::: tip
[Документация по темам](../../cms/themes/themes.md) содержит подробности об использовании поддиректорий.
:::

Блоки контента могут рендериться как обычный текст:

```twig
{% content "readme.txt" %}
```

Также можно использовать синтаксис Markdown:

```twig
{% content "changelog.md" %}
```

Блоки контента можно использовать в сочетании с [плейсхолдерами макетов](../../cms/themes/layouts.md).

```twig
{% put sidebar %}
    {% content 'sidebar-content.htm' %}
{% endput %}
```

## Переменные

Вы можете передавать переменные в блоки контента, указав их после имени файла:

```twig
{% content "welcome.htm" name=user.name %}
```

Вы также можете назначать новые переменные для использования в контенте:

```twig
{% content "location.htm" city="Vancouver" country="Canada" %}
```

Внутри контента к переменным можно обращаться с помощью базового синтаксиса с одинарными *фигурными скобками*:

```
<p>Country: {country}, city: {city}.</p>
```

Вы также можете передать коллекцию переменных как простой массив:

```twig
{% content "welcome.htm" likes=[
    {name:'Dogs'},
    {name:'Fishing'},
    {name:'Golf'}
] %}
```

Доступ к коллекции переменных осуществляется с помощью открывающего и закрывающего набора скобок:

```
<ul>
    {likes}
        <li>{name}</li>
    {/likes}
</ul>
```

> **Примечание**: Синтаксис Twig не поддерживается в блоках контента. Рассмотрите возможность использования [CMS-фрагмента](../cms/partials.md).

## Сохранение содержимого в Twig-переменную

В любом шаблоне вы можете сохранить содержимое в переменную с помощью функции `content()`. Это позволяет манипулировать выводом перед отображением. Не забудьте использовать фильтр `|raw`, чтобы предотвратить экранирование вывода.

```twig
{% set welcomeContent = content('welcome.htm') %}

{{ welcomeContent|raw }}
```

Вы также можете передать переменные в контент как второй аргумент.

```twig
{% set welcomeContent = content('welcome.htm', { foo: 'bar' }) %}
```

## Проверка существования файла контента

Функция `hasContent()` может использоваться для проверки существования контента без его рендеринга. Чтобы предотвратить рендеринг контента, передайте второй аргумент как false — функция вернёт true или false в зависимости от того, найден ли файл контента.

```twig
{% if hasContent('welcome.htm') %}
    {% content 'welcome.htm' %}
{% else %}
    <p>Welcome content not found!</p>
{% endif %}
```

## Парсинг контента как строки

При использовании тега `{% content %}` он автоматически разрешает [CMS-сниппеты](../../cms/themes/snippets.md) и ссылки, созданные [виджетом формы поиска страниц](../../element/form/widget-pagefinder.md).

Аналогично, фильтр `|content` может использоваться для парсинга HTML-строки на предмет нескольких объектов контента и их разрешения в выводе.

```twig
{{ post.content|content }}
```

Фильтр `|md` также можно использовать для парсинга Markdown-контента, содержащегося в строке.

```twig
{{ post.markdown_content|md|content }}
```
