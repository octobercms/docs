# {% ajaxPartial %}

::: aside
Этот тег расширяет [`{% partial %}` Twig-тег](./partial.md).
:::

Тег `{% ajaxPartial %}` рендерит содержимое фрагмента на странице и включает поддержку [AJAX-обработчиков](../../cms/ajax/introduction.md), самообновления и сокращённого синтаксиса обновления. Это обычно называется самообновляющимся фрагментом.

```twig
{% ajaxPartial "contact-form" %}
```

Содержимое фрагмента оборачивается определённым HTML-тегом только при первой загрузке. Последующие обновления фрагмента через AJAX не включают тег-обёртку.

```html
<div data-ajax-partial="contact-form">
    ... Contents go here ...
</div>
```

## Сокращённый синтаксис обновления

При использовании AJAX-фрагмента вам больше не нужно указывать селектор для его обновления. Просто передайте `true` в [API атрибутов данных](../../cms/ajax/attributes-api.md) при использовании атрибута `data-request-update`.

```html
<button
    data-request="onRefresh"
    data-request-update="{ contact-form: true }">
    Refresh
</button>
```

Вы также можете обновить фрагмент изнутри, используя `_self` в качестве имени фрагмента.

```html
<button
    data-request="onRefresh"
    data-request-update="{ _self: true }">
    Refresh
</button>
```

Вы также можете передать символ `^` для добавления в начало и символ `@` для добавления в конец контейнера вместо замены его содержимого.

```html
<button
    data-request="onRefresh"
    data-request-update="{ _self: '@' }">
    Append
</button>
```

## Отложенная загрузка фрагментов

Тег `{% ajaxPartial %}` принимает атрибут `lazy`, который откладывает рендеринг содержимого до загрузки страницы. В следующем примере фрагмент **posts** будет обновлён после завершения загрузки страницы.

```twig
{% ajaxPartial 'posts' lazy %}
```

Атрибуты `lazy body` позволяют указать начальное содержимое перед загрузкой, за которым следует тег `{% endpartial %}`.

```twig
{% ajaxPartial 'posts' lazy body %}
    <p>Loading posts...</p>
{% endpartial %}
```

Важно отметить, что тег `{% ajaxPartial lazy %}` не рендерит фрагмент немедленно. Вместо этого он выводит начальное содержимое, включающее атрибут данных `data-auto-submit`, используемый [запросами опроса](../../cms/features/polling.md). Этот атрибут выполняет AJAX-запрос для загрузки содержимого фрагмента после загрузки страницы. Атрибут не включается в последующие обновления фрагмента, чтобы предотвратить бесконечный цикл.

Вот как это будет выглядеть в браузере при первой загрузке страницы:

```html
<div
    data-request="onAjax"
    data-request-update="{ _self: true }"
    data-auto-submit>
    <p>Loading posts...</p>
</div>
```

::: tip
Не включайте приведённую выше разметку в свой фрагмент. Тег `{% ajaxPartial lazy %}` включит её автоматически.
:::

## Вызов AJAX-обработчиков

При вызове AJAX-обработчика из AJAX-фрагмента запускается захватывающий жизненный цикл страницы (см. ниже), который обеспечивает использование AJAX-обработчиков в запрашиваемых фрагментах.

Следующий пример показывает, как отправить простую контактную форму с помощью самообновляющегося фрагмента.

::: cmstemplate
```ini
description = "Self Updating Partial"
```
```php
<?
function onSubmitContactForm()
{
    $this['submitted'] = true;
}
?>
```
```twig
{% if submitted %}
    <p>Thank you for contacting us!</p>
{% endif %}

<button
    data-request="onSubmitContactForm"
    data-request-update="{ _self: true }">
    Submit
</button>
```
:::

Фрагменты, использующие [CMS-компоненты](../../cms/themes/components.md), также имеют доступ к их AJAX-обработчикам.

::: cmstemplate
```ini
[contactForm]
```
```html
<button
    data-request="contactForm::onSubmit"
    data-request-update="{ _self: true }">
    Submit
</button>
```
:::

### Захватывающий жизненный цикл

При вызове обработчика из AJAX-фрагмента запускается другой жизненный цикл, называемый захватывающим жизненным циклом. Захватывающий жизненный цикл рендерит всю страницу, однако содержимое рендерится «в пустоту». Таким образом, страница инициализируется полностью, включая все используемые фрагменты и AJAX-обработчики.

Поскольку это считается полным рендером страницы, это может означать, что [метод компонента](../../extend/cms-components.md) `onRun` вызывается при использовании обработчика AJAX-фрагмента. Вы можете использовать [вспомогательный метод](../../extend/services/request-input.md) `Request::ajax()`, чтобы определить, является ли запрос результатом AJAX-запроса.
