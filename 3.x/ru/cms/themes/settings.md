# Настройки темы

Директория темы может включать файлы **theme.yaml**, **version.yaml** и **assets/images/theme-preview.png**. Эти файлы необязательны для локальной разработки, но обязательны для тем, публикуемых на маркетплейсе October CMS.

## Информационный файл темы

Информационный файл темы **theme.yaml** содержит описание темы, имя автора, URL веб-сайта автора и другую информацию. Файл должен быть размещён в корневой директории темы:

::: dir
├── themes
|   └── website
|       ├── pages
|       ├── layouts
|       ├── partials
|       ├── content
|       ├── assets
|       └── `theme.yaml`  _← Информационный файл_
:::

В файле **theme.yaml** поддерживаются следующие поля:

Поле | Описание
------------- | -------------
**name** | задаёт имя темы, обязательное.
**author** | задаёт имя автора, обязательное.
**homepage** | задаёт URL веб-сайта автора, обязательное.
**description** | описание темы, обязательное.
**previewImage** | пользовательское изображение предпросмотра, путь относительно директории темы, например: `assets/images/preview.png`, необязательное.
**code** | код темы, необязательное. Значение используется на маркетплейсе October CMS для инициализации кода темы.
**authorCode** | код автора темы, необязательное. Значение используется на маркетплейсе October CMS для определения владельца темы.
**form** | массив конфигурации или ссылка на файл определения полей формы, используется для кастомизации темы, необязательное.
**require** | массив имён плагинов, используемых в качестве зависимостей темы, необязательное.

Пример информационного файла темы:

```yaml
name: "October CMS Demo"
description: "Demonstrates the basic concepts of the front-end theming."
author: "October CMS"
homepage: "https://octobercms.com"
code: "Demo"
authorCode: "Acme"
```

## Файл версий

Файл версий темы **version.yaml** определяет текущую версию темы и журнал изменений. Файл должен быть размещён в корневой директории темы.

::: dir
├── themes
|   └── website
|       ├── ...
|       └── theme.yaml
|       └── `version.yaml`  _← Файл версий_
:::

Файл имеет следующий формат.

```yaml
v1.0.1: Theme initialization
v1.0.2: Added more features
v1.0.3: Some features are removed
```

## Изображение предпросмотра темы

Изображение предпросмотра темы используется в селекторе тем в панели администрирования. Файл изображения **theme-preview.png** должен быть размещён в директории **assets/images** темы:

::: dir
├── themes
|   └── website
|       ├── ...
|       └── assets
|           └── images
|               └── `theme-preview.png`  _← Изображение предпросмотра_
:::

Ширина изображения должна быть не менее 600px. Идеальное соотношение сторон — 1.5, например 600x400px.

## Зависимости темы

Тема может зависеть от плагинов, для чего необходимо определить параметр **require** в информационном файле темы. Параметр должен содержать массив имён плагинов, являющихся обязательными. Тема, зависящая от **Acme.Blog** и **Acme.User**, может определить это требование следующим образом:

```yaml
name: "October CMS Demo"
# [...]

require:
    - "Acme.User"
    - "Acme.Blog"
```

При первой установке темы система попытается одновременно установить требуемые плагины. Для более удобного процесса рассмотрите возможность [добавления этих плагинов в список зависимостей Composer](../../extend/resources/publishing-packages.md).

## Кастомизация темы

Темы могут поддерживать конфигурационные значения, если определить ключ `form` в информационном файле темы. Этот ключ должен содержать массив конфигурации или ссылку на файл определения полей формы, подробнее см. в разделе [определение полей формы](../../element/form-fields.md).

Ниже приведён пример определения поля конфигурации для имени сайта под названием **site_name**:

```yaml
name: My Theme
# [...]

form:
    fields:
        site_name:
            label: Site name
            comment: The website name as it should appear on the front-end
            default: My Amazing Site!
```

Доступ к значению можно получить в любом шаблоне темы с помощью [глобальной Twig-переменной](../../markup/property/this-theme.md) `this.theme`.

```twig
<h1>Welcome to {{ this.theme.site_name }}!</h1>
```

Конфигурацию также можно определить в отдельном файле, путь к которому указывается относительно темы. Следующее определение загружает поля формы из файла **config/fields.yaml** внутри темы.

```yaml
name: My Theme
# [...]

form: config/fields.yaml
```

**themes/demo/config/fields.yaml**:

```yaml
fields:
    site_name:
        label: Site name
        comment: The website name as it should appear on the front-end
        default: My Amazing Site!
```

### Использование данных темы в CSS

Иногда необходимо включить визуальные настройки в таблицу стилей темы. Для этого можно использовать пользовательские свойства CSS (переменные). В следующем примере мы используем [поле типа Color Picker](../../element/form/widget-colorpicker.md) для задания пользовательского цвета ссылок.

```yaml
form:
    fields:
        # [...]

        link_color:
            label: Link color
            type: colorpicker
```

На основе приведённого примера можно определить [CMS-фрагмент](./partials.md), который передаёт выбранное значение в CSS с помощью локальной таблицы стилей. Фрагмент затем подключается в [макете темы](./layouts.md) внутри тега `<head>`.

```html
<style>
    :root {
        --my-color: {{ this.theme.link_color }};
    }
</style>
```

::: tip
Имена пользовательских свойств чувствительны к регистру, поэтому `--my-color` будет считаться отдельным пользовательским свойством от `--My-color`.
:::

Теперь в вашей таблице стилей пользовательское свойство может использоваться в любом месте — достаточно указать имя пользовательского свойства внутри функции `var()` вместо обычного значения свойства.

```css
a {
    color: var(--my-color);
}
```

### Использование данных темы с объединёнными ресурсами

Ресурсы, объединённые с помощью [фильтра и комбинатора](../markup/filter-theme.md) `|theme`, могут получать значения, передаваемые в поддерживаемые фильтры, такие как фильтр LESS. Просто укажите параметр `assetVar` при определении поля формы — значение должно содержать желаемое имя переменной.

```yaml
form:
    fields:
        # [...]

        link_color:
            label: Link color
            type: colorpicker
            assetVar: 'link-color'
```

В приведённом выше примере выбранное значение цвета будет доступно внутри LESS-файла как `@link-color`. Предположим, у нас есть следующая ссылка на таблицу стилей:

```twig
<link href="{{ ['assets/less/theme.less']|theme }}" rel="stylesheet">
```

Пример содержимого файла **themes/yourtheme/assets/less/theme.less**:

```less
a { color: @link-color }
```
