# Макеты

Макеты определяют общий каркас для ваших страниц, который обычно включает всё, что повторяется на каждой странице, например, шапку и подвал. Они почти всегда содержат HTML-код, такой как теги HEAD, TITLE и BODY.

Файлы шаблонов макетов располагаются в каталоге **layouts** вашей темы. Файлы шаблонов макетов должны иметь расширение **htm**. Внутри файла макета следует использовать тег `{% page %}` для вывода содержимого страницы. Далее приведён пример простейшего макета.

```twig
<html>
    <body>
        {% page %}
    </body>
</html>
```

::: aside
Помните, что при обращении к макету из подкаталога необходимо указывать имя подкаталога.
:::

Чтобы использовать макет для [страницы](./pages.md), страница должна ссылаться на имя файла макета (без расширения) в секции конфигурации. Ниже приведён пример шаблона страницы, использующего макет **default.htm**.

::: cmstemplate
```ini
url = "/"
layout = "default"
```
```twig
<p>Hello, world!</p>
```
:::

При запросе этой страницы её содержимое объединяется с макетом, а точнее — тег `{% page %}` макета заменяется содержимым страницы. Предыдущие примеры сгенерируют следующую разметку:

```html
<html>
    <body>
        <p>Hello, world!</p>
    </body>
</html>
```

Обратите внимание, что вы можете [рендерить фрагменты](./partials.md) в макетах. Это позволяет использовать общие элементы разметки в разных макетах. Например, вы можете создать фрагмент, который выводит ссылки на CSS и JavaScript файлы сайта. Такой подход упрощает управление ресурсами — если вам нужно добавить ссылку на JavaScript, достаточно изменить один фрагмент вместо редактирования всех макетов.

Секция конфигурации является необязательной для макетов. Поддерживаемые параметры конфигурации: **name** и **description**. Эти параметры необязательны и используются в интерфейсе администрирования. Пример шаблона макета с описанием:

::: cmstemplate
```ini
description = "Basic layout example"
```
```twig
<html>
    <body>
        {% page %}
    </body>
</html>
```
:::

## Использование динамического заголовка страницы

Свойства `meta_title` и `meta_description` [страницы](pages.md) поддерживают парсинг переменных из жизненного цикла страницы. Следующий шаблон макета установит заголовок страницы на основе значения активной страницы.

```html
<html>
    <head>
        <title>{{ this.page.meta_title }} - October CMS</title>
    </head>
    <body>
        {% page %}
    </body>
<html>
```

Шаблон страницы может затем определить свой заголовок, используя Twig-подобный синтаксис переменных с использованием значений, доступных в глобальном окружении — в данном случае используется значение **post.title**.

```ini
url = "/blog"
meta_title = "{{ post.title }} - Blog"
```

> **Примечание**: Поддерживаются только базовые переменные Twig. Фильтры, теги и функции использовать нельзя.

## Заполнители

Заполнители позволяют страницам внедрять содержимое в макет. Заполнители определяются в шаблонах макетов с помощью тега `{% placeholder %}`. Следующий пример показывает шаблон макета с заполнителем **head**, определённым в секции HTML HEAD.

```twig
<html>
    <head>
        {% placeholder head %}
    </head>
    ...
</html>
```

Страницы могут внедрять содержимое в заполнители с помощью тегов `{% put %}` и `{% endput %}`. Следующий пример демонстрирует простой шаблон страницы, который внедряет ссылку на CSS в заполнитель **head**, определённый в предыдущем примере.

::: cmstemplate
```ini
url = "/my-page"
layout = "default"
```
```twig
{% put head %}
    <link href="/themes/demo/assets/css/page.css" rel="stylesheet">
{% endput %}

<p>The page content goes here.</p>
```
:::

Более подробную информацию о заполнителях можно найти [в руководстве по разметке](../markup/tag-placeholder.md).

## Динамические макеты

Макеты, как и страницы, могут использовать любые возможности Twig. Подробнее см. раздел [Динамические страницы](pages.md) документации.

### Жизненный цикл выполнения макета

В секции PHP макета вы можете определить следующие функции для обработки жизненного цикла выполнения страницы: `onInit`, `onStart`, `onBeforePageStart` и `onEnd`.

Функция `onInit` выполняется, когда все компоненты инициализированы и до обработки AJAX-запросов. Функция `onStart` выполняется в начале обработки страницы. Функция `onBeforePageStart` выполняется после выполнения [компонентов](./components.md) макета, но до выполнения функции `onStart` страницы. Функция `onEnd` выполняется после рендеринга страницы. Последовательность выполнения обработчиков следующая:

1. Layout `onInit()` function.
1. Page `onInit()` function.
1. Layout `onStart()` function.
1. Layout components `onRun()` method.
1. Layout `onBeforePageStart()` function.
1. Page `onStart()` function.
1. Page components `onRun()` method.
1. Page `onEnd()` function.
1. Layout `onEnd()` function.

### Доступ к методам и переменным

При доступе к переменным и методам внутри фрагментов, страниц и макетов используется ближайший контекст. Возьмём следующее определение [секции PHP-кода](./themes.md).

```php
function onStart()
{
    $this['myVariable'] = 'foo';
}

function myMethod()
{
    return 'bar';
}
```

В приведённом выше примере при обращении к `myVariable` или `this.myMethod()` внутри Twig проверка существования выполняется в следующем порядке:

1. Фрагмент
1. Страница
1. Макет

### Приоритетные макеты

Макеты могут указывать атрибут `is_priority` в своих настройках для активации приоритетного режима. В обычных условиях содержимое макета рендерится после содержимого страницы. Это позволяет странице управлять свойствами макета, такими как заголовок или мета-описание. Визуально порядок выглядит так.

```text
Layout (3) ← Page (1) → Partials (2)
```

В приоритетном режиме макет использует более естественный порядок загрузки, при котором тег `{% page %}` рендерится в одной последовательности с содержимым макета. Однако при использовании этого режима заполнители не поддерживаются. Порядок загрузки приоритетного макета выглядит примерно так.

```text
Layout (1) → Page (2) → Partials (3)
```

Это особенно полезно при [создании API-эндпоинтов](../resources/building-apis.md). В следующем примере логика страницы не будет выполнена, поскольку тег page никогда не вызывается.

::: cmstemplate
```ini
description = "API Layout"
is_priority = 1
```
```twig
{% if false %}
    {% page %}
{% endif %}
```
:::
