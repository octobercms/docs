# Компоненты

Компоненты — это ключевая возможность для создания масштабируемых и современных решений с помощью October CMS. Каждый компонент реализует определённую функциональность, расширяющую ваш сайт. Компоненты могут выводить HTML-разметку на странице, но это не обязательно — другие важные возможности компонентов включают [обработку AJAX-запросов](../ajax/introduction.md), обработку отправки форм и управление жизненным циклом выполнения страницы, что позволяет внедрять переменные на страницы или реализовывать безопасность сайта.

Эта статья описывает основы работы с компонентами и не объясняет, как использовать [компоненты с AJAX](../ajax/handlers.md), [разрабатывать компоненты](../../extend/cms-components.md) как часть плагинов или [компоненты, включённые](../components/section.md) в October CMS.

## Введение

Компоненты можно найти в редакторе панели администрирования. Вы можете добавлять компоненты на страницы, во фрагменты и в макеты, нажав кнопку «Компоненты» на панели инструментов любого открытого документа. Если вы используете текстовый редактор, вы можете подключить компонент к странице или макету, добавив его имя в секцию конфигурации файла шаблона. Следующий пример демонстрирует добавление демонстрационного компонента To-Do на страницу.

::: cmstemplate
```ini
title = "Components demonstration"
url = "/components"

[demoTodo]
maxItems = 20
```
```twig
<!-- HTML Content Here -->
```
:::

Это инициализирует компонент со свойствами, определёнными в секции компонента. Многие компоненты имеют свойства, но это не обязательное требование. Некоторые свойства являются обязательными, а некоторые имеют значения по умолчанию. Если вы не уверены, какие свойства поддерживает компонент, обратитесь к документации, предоставленной разработчиком, или используйте Инспектор в редакторе панели администрирования. Инспектор открывается при нажатии на компонент в панели компонентов страницы или макета.

::: aside
Если два компонента с одинаковым именем назначены странице и макету одновременно, приоритет имеет компонент страницы.
:::

При обращении к компоненту автоматически создаётся переменная страницы, совпадающая с именем компонента (`demoTodo` в предыдущем примере). Компоненты, предоставляющие HTML-разметку, могут быть отрендерены на странице с помощью тега `{% component %}`, как показано ниже.

```twig
{% component 'demoTodo' %}
```

::: warning
Использование компонентов внутри фрагментов имеет ограниченную функциональность, это подробнее описано в разделе [Динамические фрагменты](./partials.md) документации.
:::

## Псевдонимы компонентов

Если два плагина регистрируют компоненты с одинаковым именем, вы можете подключить компонент, используя его полное имя класса и назначив ему *псевдоним*.

```ini
[October\Demo\Components\Todo demoTodoAlias]
maxItems = 20
```

Первый параметр в секции — это имя класса, второй — псевдоним компонента, который будет использоваться при подключении к странице. Если вы указали псевдоним компонента, его следует использовать повсюду в коде страницы при обращении к компоненту. Обратите внимание, что следующий пример ссылается на псевдоним компонента:

```twig
{% component 'demoTodoAlias' %}
```

Псевдонимы также позволяют определять несколько компонентов одного класса на одной странице, используя сначала краткое имя, а затем псевдоним. Это позволяет использовать несколько экземпляров одного компонента на странице.

```ini
[demoTodo todoA]
maxItems = 10
[demoTodo todoB]
maxItems = 20
```

## Использование внешних значений свойств

По умолчанию значения свойств инициализируются в секции конфигурации, где определён компонент, и значения свойств являются статическими, как показано ниже:

```ini
[demoTodo]
maxItems = 20
==
...
```

::: v-pre
Однако существует способ инициализировать свойства значениями, загруженными из внешних параметров — параметров URL или параметров [фрагмента](partials.md) (для компонентов, определённых во фрагментах). Используйте синтаксис `{{ paramName }}` для значений, которые должны загружаться из переменных фрагмента:
:::

```ini
[demoTodo]
maxItems = {{ maxItems }}
==
...
```

В приведённом выше примере, предполагая, что компонент **demoTodo** определён во фрагменте, он будет инициализирован значением, загруженным из переменной фрагмента **maxItems**:

```twig
{% partial 'my-todo-partial' maxItems='10' %}
```

Вы можете использовать точечную нотацию для получения глубоко вложенного значения из внешнего параметра:

```ini
[demoTodo]
maxItems = {{ data.maxItems }}
==
...
```

::: v-pre
Для загрузки значения свойства из параметра URL используйте синтаксис `{{ :paramName }}`, где имя начинается с двоеточия (`:`), например.
:::

```ini
[demoTodo]
maxItems = {{ :maxItems }}
==
...
```

Страница, к которой принадлежит компонент, должна иметь соответствующий определённый [параметр URL](pages.md).

```ini
url = "/todo/:maxItems"
```

В панели администрирования October вы можете использовать Инспектор для назначения внешних значений свойствам компонентов. В Инспекторе не нужно использовать фигурные скобки для ввода имени параметра. Каждое поле в Инспекторе имеет значок справа, который открывает редактор имени внешнего параметра. Введите имя параметра как `paramName` для переменных фрагмента или `:paramName` для параметров URL.

## Передача переменных в компоненты

Компоненты могут быть спроектированы для использования переменных во время рендеринга, аналогично [переменным фрагментов](./partials.md), они могут быть указаны после имени компонента в теге `{% component %}`. Указанные переменные явно переопределяют значения [свойств компонента](../../extend/cms-components.md), включая внешние значения свойств.

В этом примере свойство **maxItems** компонента будет установлено в *7* во время рендеринга компонента:

```twig
{% component 'demoTodoAlias' maxItems='7' %}
```

## Настройка разметки по умолчанию

::: aside
Разметка по умолчанию в компоненте является шаблонным кодом, цель которого — предоставить простой пример использования.
:::

Существуют два способа настройки разметки компонента по умолчанию:

- скопировать разметку по умолчанию в вашу тему
- переопределить фрагмент компонента по одному

Переопределение фрагмента компонента имеет очень ограниченный набор применений. В большинстве случаев преобразование фрагмента компонента в CMS-фрагмент значительно проще, и разница в таком подходе минимальна.

В качестве примера рассмотрим компонент блога, рендеримый следующим образом.

::: cmstemplate
```ini
[blog]
```
```twig
{% component 'blog' %}
```
:::

Приведённый выше код фактически эквивалентен следующему.

::: cmstemplate
```ini
[blog]
```
```twig
{% partial 'blog::default' %}
```
:::

Если вы скопируете фрагмент **default.htm** из компонента в вашу тему как фрагмент **blog-default.htm**, вы сможете рендерить его тем же способом.

::: cmstemplate
```ini
[blog]
```
```twig
{% partial 'blog-default' %}
```
:::

Здесь видно, что использование CMS-фрагментов для настройки содержимого — это просто, и это демонстрирует истинную мощь компонентов. Существуют лишь редкие случаи, когда тема должна переопределять фрагменты компонентов, и это подробнее описано ниже.

### Перенос разметки по умолчанию во фрагмент

Каждый компонент имеет точку входа — фрагмент **default.htm**, который рендерится при вызове тега `{% component %}`. В следующем примере мы предполагаем, что компонент называется **blogPost**.

::: cmstemplate
```ini
url = "blog/post"

[blogPost]
```
```twig
{% component "blogPost" %}
```
:::

Результат будет отрендерен из каталога плагина **components/blogpost/default.htm**. Вы можете скопировать всю разметку из этого файла и вставить её непосредственно на страницу или в новый фрагмент, например, **blog-post.htm**.

```twig
<h1>{{ __SELF__.post.title }}</h1>
<p>{{ __SELF__.post.description }}</p>
```

Внутри разметки вы можете заметить ссылки на переменную `__SELF__` — она ссылается на объект компонента и должна быть заменена псевдонимом компонента, используемым на странице, в данном примере это `blogPost`.

```twig
<h1>{{ blogPost.post.title }}</h1>
<p>{{ blogPost.post.description }}</p>
```

Это единственное изменение, необходимое для того, чтобы разметка компонента по умолчанию работала в любом месте темы. Теперь разметку компонента можно настроить и рендерить с помощью фрагмента темы.

```twig
{% partial 'blog-post' %}
```

Этот процесс можно повторить для всех остальных фрагментов, находящихся в каталоге фрагментов компонента.

### Переопределение фрагментов компонента

Все фрагменты компонента могут быть переопределены с помощью фрагментов темы. Это полезно, когда компонент имеет строгую реализацию и предоставляет возможность настройки определённых областей своей разметки.

В качестве примера, если компонент с именем **channel** использует фрагмент **title.htm**.

::: cmstemplate
```ini
url = "mypage"

[channel]
```
```twig
{% component "channel" %}
```
:::

Мы можем переопределить фрагмент, создав файл в нашей теме с именем **partials/channel/title.htm**.

Сегменты пути файла разбиваются следующим образом:

Segment | Description
------------- | -------------
**partials** | каталог фрагментов темы
**channel** | псевдоним компонента (подкаталог фрагментов)
**title.htm** | фрагмент компонента для переопределения

Имя подкаталога фрагмента можно изменить на любое, просто назначив компоненту псевдоним с таким же именем. Например, назначив компоненту **channel** другой псевдоним **foobar**, каталог переопределения также изменится.

::: cmstemplate
```ini
[channel foobar]
```
```twig
{% component "foobar" %}
```
:::

Теперь мы можем переопределить фрагмент **title.htm**, создав файл в нашей теме с именем **partials/foobar/title.htm**.

## Компонент "View Bag"

::: aside
Компонент viewBag скрыт в панели администрирования и доступен только при файловом редактировании. Он также может использоваться другими плагинами для хранения данных.
:::

В October CMS есть специальный встроенный компонент `viewBag`, который можно использовать на любой странице или в любом макете. Он позволяет определять произвольные свойства и легко обращаться к ним в области разметки как к переменным. Хороший пример использования — определение активного пункта меню внутри страницы.

::: cmstemplate
```ini
title = "About"
url = "/about.html"
layout = "default"

[viewBag]
activeMenu = "about"
```
```twig
<p>Page content...</p>
```
:::

Любое свойство, определённое для компонента, становится доступным внутри разметки страницы, макета или фрагмента через переменную `viewBag`. Например, в этом макете класс **active** добавляется к элементу списка, если значение `viewBag.activeMenu` установлено в **about**.

::: cmstemplate
```ini
description = "Default layout"
```
```twig
...

<!-- Main navigation -->
<ul>
    <li class="{{ viewBag.activeMenu == 'about' ? 'active' }}">About</li>
    ...
</ul>
```
:::

### AJAX-обработчики и фрагменты

Компоненты могут вводить [AJAX-обработчики](../ajax/introduction.md) и [фрагменты](./partials.md) в жизненный цикл темы, используя префикс с именем компонента и два символа `::`. Например, все AJAX-обработчики, определённые компонентами, доступны глобально.

```html
data-request="onMyComponentHandler"
```

Однако при конфликте имён можно использовать полное имя.

```html
data-request="componentName::onMyComponentHandler"
```

Фрагменты, рендеримые вне компонента, должны использовать своё полное имя.

```twig
{% partial 'componentName::component-partial' %}
```

Подробнее о фрагментах компонентов читайте в разделе [разработка компонентов](../../extend/cms-components.md).
