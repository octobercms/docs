# Страницы

Каждый сайт содержит хотя бы одну страницу, и в October CMS страница представлена шаблоном страницы. Файлы шаблонов страниц располагаются в каталоге **pages** вашей темы. Имена файлов страниц не влияют на маршрутизацию, но рекомендуется называть страницы в соответствии с их назначением. Файлы должны иметь расширение **htm**.

Секции конфигурации и Twig-шаблона обязательны для страниц, а секция PHP является необязательной. Ниже вы можете увидеть простейший пример главной страницы.

::: cmstemplate
```ini
url = "/"
```
```twig
<h1>Hello, world!</h1>
```
:::

## Конфигурация страницы

Конфигурация страницы определяется в секции конфигурации файла шаблона страницы. Конфигурация страницы задаёт параметры, необходимые для маршрутизации и рендеринга страницы и её [компонентов](./components.md), которые описаны в отдельной статье. Для страниц поддерживаются следующие параметры конфигурации:

Parameter | Description
------------- | -------------
**url** | URL страницы, обязательный. Синтаксис URL описан ниже.
**title** | заголовок страницы, обязательный.
**layout** | [макет](./layouts.md) страницы, необязательный. Если указан, должен содержать имя файла макета без расширения, например: `default`.
**description** | описание страницы для интерфейса администрирования, необязательный.
**hidden** | скрытые страницы доступны только авторизованным пользователям панели администрирования, необязательный.

### Синтаксис URL

URL страницы определяется параметром конфигурации **url**. URL должен начинаться с символа прямой косой черты и может содержать параметры. URL без параметров являются фиксированными и строгими. В следующем примере URL страницы — `/blog`.

::: tip
URL страницы по умолчанию нечувствителен к регистру.

```ini
url = "/blog"
```
:::


URL с параметрами являются более гибкими. Страница с шаблоном URL, определённым в следующем примере, будет отображаться для любого адреса вида `/blog/post/something`. Параметры URL могут быть доступны компонентам October или из секции PHP-кода страницы.

```ini
url = "/blog/post/:post_id"
```

Вот как можно получить доступ к параметру URL из секции PHP страницы (подробнее см. раздел «Динамические страницы»).

::: cmstemplate
```ini
url = "/blog/post/:post_id"
```
```php
function onStart()
{
    $postId = $this->param('post_id');
}
```
```twig
```
:::

Имена параметров должны быть совместимы с именами переменных PHP. Чтобы сделать параметр необязательным, добавьте знак вопроса после его имени:

```ini
url = "/blog/post/:post_id?"
```

Параметры в середине URL не могут быть необязательными. В следующем примере параметр `:post_id` помечен как необязательный, но обрабатывается как обязательный.

```ini
url = "/blog/:post_id?/comments"
```

Необязательные параметры могут иметь значения по умолчанию, которые используются в качестве запасных значений, если реальное значение параметра отсутствует в URL. Значения по умолчанию не могут содержать звёздочки, символы вертикальной черты или вопросительные знаки. Значение по умолчанию указывается после **вопросительного знака**. В следующем примере значение параметра `category_id` будет равно `10` для URL `/blog/category`.

```ini
url = "/blog/category/:category_id?10"
```

Вы также можете использовать регулярные выражения для валидации параметров. Чтобы добавить выражение валидации, поставьте символ вертикальной черты после имени параметра или вопросительного знака и укажите выражение. Символ прямой косой черты не допускается в этих выражениях. Примеры:

```ini
url = "/blog/:post_id|^[0-9]+$/comments" ; this will match /blog/10/comments

url = "/blog/:post_id|^[0-9]+$" ; this will match /blog/3

url = "/blog/:post_name?|^[a-z0-9\-]+$" ; this will match /blog/my-blog-post
```

Можно использовать специальный *подстановочный* параметр, поставив **звёздочку** после параметра. В отличие от обычных параметров, подстановочные параметры могут совпадать с одним или несколькими сегментами URL. URL может содержать только один подстановочный параметр, он не может использовать регулярные выражения и за ним не может следовать необязательный параметр.

```ini
url = "/blog/:category*/:slug"
```

Сами подстановочные параметры могут быть сделаны необязательными, поставив символ `?` перед звёздочкой.

```ini
url = "/blog/:slug?*"
```

Например, URL вида `/color/:color/make/:make*/edit` будет совпадать с `/color/brown/make/volkswagen/beetle/retro/edit` и извлечёт следующие значения параметров:

- color: `brown`
- make: `volkswagen/beetle/retro`

::: tip
Подкаталоги не влияют на URL страниц — URL определяется только параметром **url**.
:::

## Динамические страницы

Внутри секции Twig шаблона страницы вы можете использовать любые [функции, фильтры и теги, предоставляемые October CMS](../../markup/templating.md). Любая динамическая страница требует **переменных**, которые могут быть подготовлены в секции PHP страницы или макета, либо [компонентами](./components.md). В этой статье мы описываем, как подготавливать переменные в секции PHP.

### Жизненный цикл выполнения страницы

Существуют специальные функции, которые можно определить в секции PHP страниц и макетов: `onInit`, `onStart` и `onEnd`. Функция `onInit` выполняется, когда все компоненты инициализированы и до обработки AJAX-запросов. Функция `onStart` выполняется в начале выполнения страницы. Функция `onEnd` выполняется перед рендерингом страницы и после выполнения [компонентов](./components.md) страницы. В функциях `onStart` и `onEnd` вы можете передавать переменные в окружение Twig. Используйте `$this` с нотацией массива для передачи переменных на страницу.

::: cmstemplate
```ini
url = "/"
```
```php
function onStart()
{
    $this['hello'] = "Hello world!";
}
```
```twig
<h3>{{ hello }}</h3>
```
:::

Следующий пример более сложный. Он показывает, как загрузить коллекцию записей блога из базы данных и отобразить их на странице (плагин `Acme\Blog` — вымышленный).

::: cmstemplate
```ini
url = "/blog"
```
```php
use Acme\Blog\Classes\Post;

function onStart()
{
    $this['posts'] = Post::orderBy('created_at', 'desc')->get();
}
```
```twig
<h2>Latest posts</h2>
<ul>
    {% for post in posts %}
        <h3>{{ post.title }}</h3>
        {{ post.content }}
    {% endfor %}
</ul>
```
:::

Переменные по умолчанию и расширения Twig, предоставляемые October CMS, описаны в [руководстве по разметке](../../markup/templating.md). Последовательность выполнения обработчиков описана в разделе [Динамические макеты](./layouts.md).

### Отправка пользовательского ответа

Все методы, определённые в жизненном цикле выполнения, могут прервать процесс и вернуть ответ — просто верните ответ из функции жизненного цикла. Пример ниже не загружает содержимое страницы, а вместо этого возвращает строку *Hello world!* в браузер:

```php
function onStart()
{
    return 'Hello world!';
}
```

Более полезным примером может быть перенаправление с использованием фасада `Redirect`:

```php
public function onStart()
{
    return Redirect::to('http://google.com');
}
```

### Обработка форм

Вы можете обрабатывать стандартные формы с помощью методов-обработчиков, определённых в секции PHP страницы или макета (обработка AJAX-запросов описана в статье [AJAX Framework](../ajax/introduction.md)). Используйте [Twig-функцию](../../markup/function/form.md) `form_open()` для определения формы, которая ссылается на обработчик событий.

```html
<form data-request="onHandleForm">
    <div>
        <label>Please enter a string</label>
        <input name="value"/>
    </div>

    <button data-attach-loading>
        Submit
    </button>
</form>

<p>Last submitted value: {{ lastValue }}</p>
```

Функция `onHandleForm` может быть определена в секции PHP страницы или макета.

```php
function onHandleForm()
{
    $this['lastValue'] = post('value');
}
```

Обработчик загружает значение с помощью функции `post` и инициализирует атрибут-переменную `lastValue` страницы, которая отображается под формой в первом примере.

::: tip
Если обработчик с одинаковым именем определён в макете страницы, на самой странице и в [компоненте страницы](./components.md), October CMS выполнит обработчик страницы. Если обработчик определён в компоненте и в макете, будет выполнен обработчик макета. Приоритет обработчиков: страница, макет, компонент.
:::

Если вы хотите обратиться к обработчику, определённому в конкретном компоненте, используйте имя или псевдоним компонента в ссылке на обработчик:

```html
<form data-request="myComponent::onHandleForm">...</form>
```

## Страница 404

Если тема содержит страницу с URL `/404`, она отображается, когда система не может найти запрошенную страницу.

## Страница ошибки

По умолчанию любые ошибки отображаются на детальной странице ошибки, содержащей содержимое файла, номер строки и стек вызовов, где произошла ошибка. Вы можете отображать пользовательскую страницу ошибки, установив значение конфигурации `debug` в **false** в скрипте `config/app.php` и создав страницу с URL `/error`.

## Установка заголовка страницы

Установка заголовка страницы может быть выполнена в PHP с использованием объекта страницы или в Twig с использованием [тега placeholder](../../markup/tag/placeholder.md).

### Использование свойств страницы

Свойства страницы доступны в секции PHP-кода или [компонентах](./components.md) через обращение к `$this->page`. Следующий пример устанавливает новое значение атрибута `meta_title`.

```php
function onEnd()
{
    $this->page->meta_title = 'A different page title';
}
```

Переменная `{{ this.page }}` доступна в Twig через переменную `this.page`. Например, для возврата атрибута `meta_title` внутри макета.

```twig
<title>{{ this.page.meta_title }}</title>
```

::: tip
Более подробную информацию о `this.page` можно найти в [руководстве по разметке](../../markup/property/this-page.md).
:::

### Использование переменных-заполнителей

Тег `{% put %}` позволяет сохранить значение в переменной-заполнителе. Следующий пример устанавливает переменную `pageTitle`.

```twig
{% put pageTitle = 'Yet another page title' %}
```

Twig-функция `placeholder()` используется для доступа к переменной внутри макета.

```twig
<title>{{ placeholder('pageTitle') }}</title>
```

Значение по умолчанию (второй аргумент) может быть указано в качестве запасного.

```twig
<title>{{ placeholder('pageTitle', this.page.meta_title) }}</title>
```

::: tip
Более подробную информацию о теге placeholder можно найти в [статье о теге placeholder](../../markup/tag/placeholder.md).
:::

## Программное подключение ресурсов страницы

При необходимости вы можете подключать ресурсы (файлы CSS и JavaScript) к страницам с помощью методов контроллера `addCss` и `addJs`. Это можно сделать в функции `onStart`, определённой в секции PHP страницы или [шаблона макета](./layouts.md).

```php
function onStart()
{
    $this->addCss('assets/css/hello.css');
    $this->addJs('assets/js/app.js');
}
```

Если путь, указанный в аргументе методов `addCss` и `addJs`, начинается с косой черты (/), он будет относительным к корню сайта. Если путь к ресурсу не начинается с косой черты, он является относительным к теме.

Подключаемые ресурсы можно объединять, передавая их в виде массива:

```php
function onStart()
{
    $this->addCss(['assets/css/hello.css', 'assets/css/goodbye.css']);
    $this->addJs(['assets/js/app.js', 'assets/js/nav.js']);
}
```

Ресурсы LESS и SCSS могут быть подключены и скомпилированы с помощью комбайнера.

```php
function onStart()
{
    $this->addCss(['assets/less/base.less']);
}
```

Второй аргумент методов `addCss` и `addJs` позволяет указать дополнительные атрибуты для подключаемых ресурсов:

```php
function onStart()
{
    $this->addJs(['assets/js/app.js', 'assets/js/nav.js'], ['defer' => true]);
}
```

Для вывода подключённых ресурсов на страницах или [макетах](./layouts.md) используйте теги `{% styles %}` и `{% scripts %}`. Пример:

```twig
<head>
    ...
    {% styles %}
</head>
<body>
    ...
    {% scripts %}
</body>
```

::: tip
Более подробную информацию о тегах `{% styles %}` и `{% scripts %}` можно найти в [руководстве по разметке](../../markup/tag/placeholder.md).
:::
