# Темы

::: aside
Активная тема задаётся параметром `active_theme` в файле `config/cms.php` или через панель администрирования **Settings → Frontend Theme**. Настройка в панели администрирования имеет приоритет над значением в файле `config/cms.php`.
:::

Темы полностью основаны на файлах и могут управляться любой системой контроля версий, например, Git. На этой странице представлено общее описание тем October CMS. Более подробную информацию о страницах, фрагментах, макетах и файлах содержимого вы найдёте в соответствующих статьях ниже.

Темы представляют собой каталоги, которые по умолчанию располагаются в директории **themes**. Темы могут содержать следующие объекты:

Object | Description
------------- | -------------
[Pages](./pages.md) | представляют страницы сайта.
[Partials](./partials.md) | содержат многоразовые фрагменты HTML-разметки.
[Layouts](./layouts.md) | определяют каркас страницы.
[Content Files](./content.md) | текстовые, HTML или [Markdown](http://daringfireball.net/projects/markdown/syntax) блоки, которые можно редактировать отдельно от страницы или макета.
**Asset Files** | файлы ресурсов, такие как изображения, CSS и JavaScript файлы.

## Структура каталогов

Ниже вы можете увидеть пример структуры каталогов темы. Каждая тема представляет собой отдельный каталог, и, как правило, одна тема является активной для отображения сайта. В этом примере показан каталог темы **website**.

::: dir
├── themes
|   └── website  _← Theme Starts Here_
|       ├── `pages`
|       │   └── index.htm
|       ├── `layouts`
|       │   └── default.htm
|       ├── `partials`
|       │   └── sidebar.htm
|       ├── `content`
|       │   └── footer-contacts.md
|       └── `assets`
|           ├── css
|           |   └── my-styles.css
|           ├── js
|           └── images
:::

### Подкаталоги

October CMS поддерживает вложенность до пяти подкаталогов для файлов **pages**, **partials**, **layouts** и **content**, в то время как каталог **assets** может иметь неограниченную глубину вложенности. Такой подход упрощает организацию больших сайтов. В примере структуры каталогов ниже каталоги **pages** и **partials** содержат подкаталог **blog**, а каталог **content** содержит подкаталог **home**.

::: dir
├── themes
|   └── website
|       ├── pages
|       │   ├── index.htm
|       │   └── `blog`  _← Page Subdirectory_
|       │       ├── index.htm
|       │       └── category.htm
|       ├── layouts
|       │   └── default.htm
|       ├── partials
|       │   ├── sidebar.htm
|       │   └── `blog`  _← Partial Subdirectory_
|       │       └── category-list.htm
|       ├── content
|       │   ├── footer-contacts.md
|       │   └── `home`  _← Content Subdirectory_
|       │       └── intro.md
|       └── assets
:::

Для обращения к шаблону в подкаталоге укажите имя подкаталога перед именем шаблона. Например, рендеринг фрагмента **category-list** из подкаталога **blog**.

::: tip
Пути к шаблонам всегда являются абсолютными. Если в одном фрагменте вы рендерите другой фрагмент из того же подкаталога, вам всё равно необходимо указывать имя подкаталога.

```twig
{% partial "blog/category-list" %}
```
:::

## Структура шаблона

Страницы, фрагменты и макеты могут содержать до 3 секций: **конфигурация**, **PHP-код** и **Twig-разметка**. Секции разделяются последовательностью `==`.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
function onStart()
{
    $this['posts'] = [...];
}
```
```twig
<h3>Blog archive</h3>
{% for post in posts %}
    <h4>{{ post.title }}</h4>
    {{ post.content }}
{% endfor %}
```
:::

### Секция конфигурации

Секция конфигурации задаёт параметры шаблона. Поддерживаемые параметры конфигурации специфичны для различных CMS-шаблонов и описаны в соответствующих статьях документации. Секция конфигурации использует простой [формат INI](http://en.wikipedia.org/wiki/INI_file), в котором строковые значения параметров заключаются в кавычки. Пример секции конфигурации для шаблона страницы:

```ini
url = "/blog"
layout = "default"

[component]
parameter = "value"
```

### Секция PHP-кода

Код в секции PHP выполняется каждый раз перед рендерингом шаблона. Секция PHP является необязательной для всех CMS-шаблонов, и её содержимое зависит от типа шаблона, в котором она определена. Секция PHP-кода может содержать необязательные открывающие и закрывающие теги PHP для подсветки синтаксиса в текстовых редакторах. Открывающие и закрывающие теги всегда должны указываться на отдельной строке от разделителя секций `==`.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
<?
function onStart()
{
    $this['posts'] = [...];
}
?>
```
```twig
<h3>Blog archive</h3>
{% for post in posts %}
    <h4>{{ post.title }}</h4>
    {{ post.content }}
{% endfor %}
```
:::

В секции PHP можно только определять функции и ссылаться на пространства имён с помощью ключевого слова PHP `use`. Никакой другой PHP-код в секции PHP не допускается. Это связано с тем, что секция PHP преобразуется в PHP-класс при парсинге страницы. Вот пример использования ссылки на пространство имён.

::: cmstemplate
```ini
url = "/blog"
layout = "default"
```
```php
<?
use Acme\Blog\Classes\Post;

function onStart()
{
    $this['posts'] = Post::get();
}
?>
```
```twig
```
:::

В качестве общего способа установки переменных следует использовать доступ к массиву через `$this`, хотя для простоты можно использовать **объектный доступ только для чтения**, например:

```php
// Write via array
$this['foo'] = 'bar';

// Read via array
echo $this['foo'];

// Read-only via object
echo $this->foo;
```

При определении функций они становятся доступными как методы через свойство `$this` в PHP и переменную `this` в Twig. Следующий пример определяет функцию **doSomething** и вызывает метод в обоих местах.

::: cmstemplate
```ini
url = "/"
```
```php
function onStart()
{
    $this['foo'] = $this->doSomething();
}

function doSomething()
{
    return 'bar';
}
```
```twig
<h3>{{ this.doSomething() }}</h3>
```
:::

### Секция Twig-разметки

Секция Twig определяет разметку, которая будет отрендерена шаблоном. В секции Twig вы можете использовать функции, теги и фильтры, [предоставляемые October CMS](../../markup/templating.md), все [встроенные возможности Twig](https://twig.symfony.com/doc/) или [те, что предоставляются плагинами](../../extend/twig-tags.md). Содержимое секции Twig зависит от типа шаблона (страница, макет или фрагмент). Более подробную информацию о специфических объектах Twig вы найдёте далее в документации.

::: tip
Более подробную информацию можно найти в [руководстве по разметке](../../markup/templating.md).
:::

## Журналирование темы

Поскольку макеты и страницы хранят большую часть данных в обычных файлах, вы или ваши клиенты можете случайно потерять содержимое. Например, смена макета страницы изменит каркас страницы и, как следствие, приведёт к потере данных.

October CMS может записывать каждое изменение, внесённое в тему — эта функция называется «Журналирование темы» и по умолчанию отключена. Чтобы включить журналирование темы, перейдите в **Settings → Log Settings** и включите **Log Theme Changes**.

Теперь вы можете просматривать журнал изменений темы через **Settings → Theme Log**, где можно увидеть обзор каждого изменения. Вы можете использовать эту информацию для принятия решения о необходимых действиях для отката этих изменений, если это потребуется.
