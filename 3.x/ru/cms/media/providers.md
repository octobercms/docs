# Провайдеры

Менеджер медиа по умолчанию использует провайдер локального диска. Перед использованием функций Amazon S3 необходимо установить пакет Flysystem S3.

```bash
composer require league/flysystem-aws-s3-v3 "^3.0"
```

После изменения конфигурации менеджера медиа следует сбросить его кэш. Это можно сделать, нажав кнопку **Обновить** на панели инструментов менеджера медиа.

## Локальный диск

По умолчанию менеджер медиа работает с подкаталогом **storage/app/media** директории установки. Для использования Amazon S3 необходимо обновить системную конфигурацию в файле **config/filesystems.php** и следовать инструкциям из этой статьи.

```php
'media' => [
    'driver' => 'local',
    'root' => storage_path('app/media'),
    'url' => '/storage/app/media',
    'visibility' => 'public',
    'throw' => false,
],
```

## Настройка доступа к Amazon S3

Для использования Amazon S3 с October CMS необходимо создать S3-бакет, папку в бакете и API-пользователя.

Зарегистрируйтесь в Amazon AWS или войдите с существующей учётной записью в AWS Console. Откройте панель управления S3. Создайте новый бакет и присвойте ему любое имя (имя бакета будет частью публичных URL ваших файлов).

По умолчанию файлы в S3-бакетах недоступны напрямую. Чтобы сделать бакет публичным, вернитесь к списку бакетов и нажмите на бакет. Нажмите кнопку **Properties** в правой боковой панели. Разверните вкладку **Permissions**. Нажмите ссылку **Edit bucket policy**. Вставьте следующий код в окно политики. Замените имя бакета на фактическое:

```json
{
    "Version": "2008-10-17",
    "Id": "Policy1397632521960",
    "Statement": [
        {
            "Sid": "Stmt1397633323327",
            "Effect": "Allow",
            "Principal": {
                "AWS": "*"
            },
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::BUCKETNAME/*"
        }
    ]
}
```

Нажмите кнопку **Save** для применения политики. Политика предоставляет публичный доступ только для чтения ко всем папкам и директориям в бакете. Если вы собираетесь использовать бакет для других целей, можно настроить публичный доступ к конкретной папке, указав имя директории в значении **Resource**:

```
"arn:aws:s3:::BUCKETNAME/media/*"
```

Также необходимо создать API-пользователя, которого October CMS будет использовать для управления файлами бакета. В консоли AWS перейдите в раздел IAM. Перейдите на вкладку Users и создайте нового пользователя. Имя пользователя не имеет значения. Убедитесь, что флажок "Generate an access key for each user" установлен при создании пользователя. После создания пользователя AWS позволит увидеть учётные данные безопасности — **Access Key ID** и **Secret Access Key**. Скопируйте ключи и сохраните их во временном текстовом файле.

Вернитесь к списку пользователей и нажмите на созданного пользователя. В разделе **Permissions** нажмите кнопку **Attach Policy**. Выберите политику **AmazonS3FullAccess** в списке и нажмите кнопку **Attach Policy**.

Теперь у вас есть вся информация для обновления конфигурации October CMS. Откройте скрипт **config/filesystems.php** и найдите раздел **disks**. Он уже содержит конфигурацию media. Измените `driver` на **s3** и замените параметры API-учётных данных и информации о бакете:

Параметр | Значение
------------- | -------------
**driver** | драйвер хранилища, local или s3.
**key** | значение **Access Key ID** созданного пользователя.
**secret** | значение **Secret Access Key** созданного пользователя.
**bucket** | имя вашего бакета.
**region** | код региона бакета, см. ниже.
**url** | публичный путь к папке в бакете, см. ниже.

Регион бакета можно найти в консоли управления S3, в свойствах бакета. Вкладка Properties отображает название региона, например Oregon. Конфигурация драйвера S3 требует код бакета. Используйте эту таблицу для поиска кода вашего бакета. Вы также можете обратиться к [документации AWS](http://docs.aws.amazon.com/general/latest/gr/rande.html#s3_region).

Регион | Код
------------- | -------------
**US East (Ohio)** | us-east-2
**US East (N. Virginia)** | us-east-1
**US West (N. California)** | us-west-1
**US West (Oregon)** | us-west-2
**Asia Pacific (Hong Kong)** | ap-east-1
**Asia Pacific (Mumbai)** | ap-south-1
**Asia Pacific (Osaka-Local)** | ap-northeast-3
**Asia Pacific (Seoul)** | ap-northeast-2
**Asia Pacific (Singapore)** | ap-southeast-1
**Asia Pacific (Sydney)** | ap-southeast-2
**Asia Pacific (Tokyo)** | ap-northeast-1
**Canada (Central)** | ca-central-1
**China (Beijing)** | cn-north-1
**China (Ningxia)** | cn-northwest-1
**EU (Frankfurt)** | eu-central-1
**EU (Ireland)** | eu-west-1
**EU (London)** | eu-west-2
**EU (Paris)** | eu-west-3
**EU (Stockholm)** | eu-north-1
**South America (São Paulo)** | sa-east-1
**Middle East (Bahrain)** | me-south-1

Чтобы получить URL папки, откройте консоль AWS и перейдите в раздел S3. Перейдите к бакету и нажмите на созданную папку. Загрузите любой файл в папку и нажмите на файл. Нажмите кнопку **Properties** в правой боковой панели. URL файла находится в параметре **Link**. Скопируйте URL и удалите из него имя файла и завершающую косую черту.

Пример конфигурации после обновления:

```php
'disks' => [
    // ...
    'media' => [
        'driver' => 's3',
        'key'    => 'XXXXXXXXXXXXXXXXXXXX',
        'secret' => 'xxxXxXX+XxxxxXXxXxxxxxxXxxXXXXXXXxxxX9Xx',
        'region' => 'us-west-2',
        'bucket' => 'my-bucket',
        'url' => 'https://s3-us-west-2.amazonaws.com/your-bucket-name',
        'visibility' => 'public',
        'throw' => false
    ],
    // ...
]
```

Сохраните скрипт **config/filesystems.php** — поздравляем! Теперь вы готовы использовать Amazon S3 с October CMS. Обратите внимание, что вы также можете настроить Amazon CloudFront CDN для работы с вашим бакетом. Эта тема не рассматривается в данном документе, обратитесь к [документации CloudFront](http://aws.amazon.com/cloudfront/). После настройки CloudFront необходимо обновить параметр **url** в конфигурации файловых систем.

## Устранение неполадок

Наиболее распространённая проблема при использовании удалённых сервисов — проблема SSL-соединения. Если вы получаете ошибки SSL, убедитесь, что на вашем сервере установлены актуальные SSL-сертификаты публичных центров сертификации (CA).
