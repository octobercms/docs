# Введение

October CMS включает AJAX-фреймворк, предоставляющий полный набор возможностей, позволяющий загружать данные с сервера без обновления страницы в браузере. Эта же библиотека может использоваться в CMS-темах и в любом месте панели администрирования.

AJAX-фреймворк представлен в двух вариантах: вы можете использовать [JavaScript API](./javascript-api.md) или [API атрибутов данных](./attributes-api.md). API атрибутов данных не требует знания JavaScript для использования AJAX в October CMS.

## Подключение фреймворка

::: aside
AJAX-фреймворк является необязательным в вашей CMS-теме, и вы всегда можете подключить предпочитаемый вами фреймворк вместо него.
:::

При работе с [CMS-темой](../../cms/themes/themes.md) подключение библиотеки сводится к использованию Twig-тега. Разместите тег `{% framework %}` в любом месте вашей страницы или макета. Это добавит ссылку на фронтенд-библиотеку JavaScript October CMS, например:

```twig
{% framework %}
```

### Дополнительные возможности

Тег `{% framework %}` поддерживает необязательный параметр **extras**, который подключает дополнительные файлы стилей и JavaScript для расширенных функций, включая [валидацию форм](../features/validation.md), [индикаторы загрузки](../features/loaders.md) и [flash-сообщения](../features/flash-messages.md).

```twig
{% framework extras %}
```

Вы также можете добавить параметр **turbo** для включения [турбо-маршрутизации](./turbo-router.md) на каждой странице.

```twig
{% framework extras turbo %}
```

## Как работают AJAX-запросы

Страница может отправить AJAX-запрос с помощью атрибутов данных или JavaScript. Каждый запрос вызывает **обработчик событий** — также называемый [AJAX-обработчиком](./handlers.md) — на сервере и может обновлять элементы страницы с помощью фрагментов. AJAX-запросы лучше всего работают с формами, поскольку данные формы автоматически отправляются на сервер. Вот рабочий процесс запроса:

1. Клиентский браузер отправляет AJAX-запрос, указывая имя обработчика и другие необязательные параметры.
2. Сервер находит [AJAX-обработчик](./handlers.md) и выполняет его.
3. Обработчик выполняет необходимую бизнес-логику и обновляет окружение, внедряя переменные страницы.
4. Сервер [рендерит фрагменты](./update-partials.md), запрошенные клиентом с помощью опции `update`.
5. Сервер отправляет ответ, содержащий отрендеренную разметку фрагментов.
6. Клиентский фреймворк обновляет элементы страницы данными фрагментов, полученными от сервера.

## Пример использования

Ниже приведён простой пример, использующий API атрибутов данных для определения формы с поддержкой AJAX. Форма отправит AJAX-запрос обработчику **onTest** и запросит обновление контейнера результата разметкой фрагмента **mypartial**.

::: tip
Данные формы для `value1` и `value2` автоматически отправляются вместе с AJAX-запросом.

```html
<!-- AJAX enabled form -->
<form data-request="onTest" data-request-update="{ mypartial: '#myDiv' }">

    <!-- Input two values -->
    <input name="value1"> + <input name="value2">

    <!-- Action button -->
    <button type="submit">Calculate</button>

</form>

<!-- Result container -->
<div id="myDiv"></div>
```
:::

Фрагмент **mypartial** содержит разметку, которая считывает переменную `result`.

```twig
<p>The answer is {{ result }}</p>
```

Метод обработчика **onTest** получает данные формы с помощью вспомогательного метода `input` ([helper-метод](../../extend/services/helpers.md)), и результат передаётся в переменную страницы `result`.

```php
function onTest()
{
    $this['result'] = input('value1') + input('value2');
}
```

Пример можно прочитать так: «Когда форма отправлена, выполнить AJAX-запрос к обработчику **onTest**. Когда обработчик завершит работу, отрендерить фрагмент **mypartial** и вставить его содержимое в элемент **#myDiv**».
