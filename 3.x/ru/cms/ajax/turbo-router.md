# Turbo-маршрутизатор

Turbo-маршрутизация — это реализация PJAX (push state и AJAX), которая обеспечивает производительность одностраничного приложения без сложности клиентского фреймворка. При клике по ссылке страница автоматически подменяется на стороне клиента без полной перезагрузки.

```twig
{% framework turbo %}
```

## Маршрутизация ссылок

Вы можете программно перейти по ссылке следующим образом.

```js
oc.visit(location);
```

Чтобы заменить текущий URL без добавления в историю навигации, аналогично `window.history.replaceState`, установите параметр `action` в значение **replace**.

```js
oc.visit(location, { action: 'replace' });
```

Чтобы проверить, включён ли turbo-маршрутизатор и следует ли его использовать.

```js
if (oc.useTurbo && oc.useTurbo()) {
    // Use PJAX
}
```

## Отключение маршрутизации

Чтобы отключить PJAX-маршрутизацию на конкретной странице, можно вызвать полную перезагрузку, добавив мета-тег `turbo-visit-control` в секцию head страницы со значением `reload`. Это отключит функцию только для входящих запросов.

```html
<head>
    <meta name="turbo-visit-control" content="reload" />
</head>
```

Чтобы полностью отключить PJAX на вашем сайте, установите значение `disable`. Это отключит функцию для всех входящих и исходящих запросов.

```html
<meta name="turbo-visit-control" content="disable" />
```

## Отключение для определённых ссылок

По умолчанию все внутренние HTML-ссылки маршрутизируются через PJAX, но вы можете отключить это, пометив ссылки или их родительский контейнер атрибутом `data-turbo="false"`. Отключённые ссылки обрабатываются браузером обычным образом.

```html
<a href="/" data-turbo="false">Disabled</a>
```

Вы можете повторно включить маршрутизацию, когда родительский элемент её отключил:

```html
<div data-turbo="false">
    <a href="/" data-turbo="true">Enabled</a>
</div>
```

## Отключение прокрутки при переходе

Каждый переход прокручивает страницу вверх, как и большинство ссылок в браузере. Однако в некоторых случаях полезно сохранять позицию прокрутки, например, когда ссылки действуют как фильтры. Вы можете отключить прокрутку при переходе с помощью атрибута `data-turbo-no-scroll` на элементе ссылки.

```html
<a href="/" data-turbo-no-scroll>Filter</a>
```

## Сохранение элементов страницы

В некоторых случаях вам может потребоваться включить на странице статические элементы, которые не должны обновляться при изменении страницы. Используйте атрибут `data-turbo-permanent` на родительском элементе. Элемент также должен иметь атрибут `id`, чтобы исходная страница могла быть сопоставлена с новой, включая обработчики событий.

```html
<div id="main-navigation" data-turbo-permanent>...</div>
```

## Установка корневого пути

По умолчанию PJAX используется для всех ссылок в пределах одного доменного имени, а переход на любой другой URL приводит к полной перезагрузке страницы. В некоторых случаях ваше приложение может находиться в подкаталоге, и ссылки должны применяться только к корневому пути.

Например, если ваш сайт расположен в `/app` и вы не хотите, чтобы ссылки применялись к другому сайту в `/docs`, вы можете ограничить ссылки корневым путём. Установить корневой путь можно, добавив мета-тег `turbo-root` в секцию head страницы.

```html
<head>
    <meta name="turbo-root" content="/app">
</head>
```

## Нативные страницы ошибок

При использовании PJAX, когда сервер отвечает кодом ошибки, например 404 или 500, полный HTML-элемент заменяется целиком, включая скрипты и стили. Это предотвращает случайную замену body контентом, созданным другим приложением.

Вы можете отключить это поведение, добавив мета-тег `turbo-visit-control` в секцию head страницы со значением `error`. Это сообщит turbo-маршрутизатору, что содержимое страницы ошибки создаётся нативным приложением.

```html
<meta name="turbo-visit-control" content="error">
```

## Кэширование страниц

С включённым кэшированием turbo-маршрутизатор повышает производительность сайта, отображая ранее посещённые страницы без обращения к сети, что делает сайт быстрее. При клике по ссылке содержимое показывается из локального хранилища браузера, пока страница запрашивается в фоновом режиме. Последняя версия страницы отображается после завершения сетевого запроса, что означает двойной рендеринг страницы.

### Прослушивание события кэширования

Вы можете слушать событие `page:before-cache`, если нужно подготовить документ перед помещением в кэш. Это можно использовать для сброса форм, сворачивания элементов интерфейса или очистки сторонних элементов управления, чтобы страница была готова к повторному отображению.

```js
addEventListener('page:before-cache', function() {
    // Close any open submenus, etc.
});
```

### Определение загрузки из кэша

Вы можете определить, когда содержимое страницы получено из кэша, по атрибуту `data-turbo-preview` на HTML-элементе. В JavaScript это выглядит так:

```js
if (document.documentElement.hasAttribute('data-turbo-preview')) {
    // Page shown is loaded from cache
}
```

Или с помощью стилей:

```css
html[data-turbo-preview] {
    /* Hide overlays from previous view */
}
```

### Отключение кэширования

Вы можете отключить кэширование для отдельных страниц с помощью мета-тега `turbo-cache-control` в секции head страницы. Установка значения **no-cache** полностью отключит кэш. Вы также можете установить значение **no-preview**, чтобы сохранить кэшированную версию при навигации кнопками «Назад» и «Вперёд» браузера.

```html
<head>
    <meta name="turbo-cache-control" content="no-cache">
</head>
```

## Работа с JavaScript

При работе с PJAX содержимое страницы может загружаться динамически, что отличается от обычного поведения браузера. Для решения этой проблемы используется обработчик события `render`, который вызывается каждый раз при загрузке страницы, включая [AJAX-обновления](./update-partials.md).

```js
addEventListener('render', function() {
    // Page has rendered something new
});
```

Функция `oc.pageReady` используется для вызова кода, когда страница и скрипты готовы. Функция возвращает промис, который разрешается после загрузки всех скриптов страницы или немедленно, если они уже загружены.

```js
oc.pageReady().then(() => {
    // Page has finished loading scripts
});
```

Ещё одна полезная функция — `oc.waitFor`, которая ждёт появления объекта или переменной. Функция возвращает промис, который разрешается при обнаружении переменной.

```js
oc.waitFor(() => window.propName).then(() => [
    // window.propName is now available
]);
```

Второй аргумент задаёт интервал ожидания в миллисекундах. Следующий пример прекратит ожидание через две секунды.

```js
oc.waitFor(() => window.propName, 2000).then(() => {
    console.log('Found the variable!')
}).catch(() => {
    console.error('Gave up waiting...')
});
```

### Встроенные элементы script

Turbo-маршрутизатор поддерживает скрипты в теге `<head>` страницы, сравнивая различия. Если вы используете теги script в теге `<body>`, скрипт будет выполняться каждый раз при рендеринге страницы, что может быть нежелательно.

Вы можете добавить `data-turbo-eval="false"`, чтобы скрипт выполнялся только при первой загрузке страницы. Скрипт не будет вызываться для PJAX-запросов.

```html
<body>
    <script data-turbo-eval="false" src="{{ ['@framework.bundle']|theme }}"></script>
</body>
```
::: tip
Если вы размещаете скрипты в теге `<body>` для повышения производительности, рассмотрите перенос их в тег `<head>` с использованием `<script defer>`.
:::

Чтобы выполнить встроенный JavaScript-код только один раз, независимо от первой загрузки страницы или PJAX-запроса, установите уникальное значение атрибута `data-turbo-eval-once`. Уникальное значение (например, `myAjaxPromise`) используется для определения, был ли скрипт уже обработан.

```html
<script data-turbo-eval-once="myAjaxPromise">
    // This script will run once only
    addEventListener('ajax:promise', function(event) {
        //
    });
</script>
```

### Идемпотентность элементов управления

::: aside
October CMS предоставляет вспомогательную библиотеку для простого создания [идемпотентных элементов управления](./hot-controls.md).
:::

При переходе на страницу и инициализации JavaScript-компонентов важно, чтобы эти функции были идемпотентными. Простыми словами, идемпотентная функция безопасна для многократного вызова без изменения результата после первого применения.

Один из способов сделать функцию идемпотентной — отслеживать, была ли она уже выполнена, добавляя значение в свойство `dataset` каждого обработанного элемента. Это полезно для внешних скриптов.

```js
addEventListener('page:loaded', function() {
    // Find my control
    var myControl = document.querySelector('.my-control');

    // Check if control has already been initialized
    if (!myControl.dataset.hasMyControl) {
        myControl.dataset.hasMyControl = true;

        // Initialize since this is the first time
        initializeMyControl(myControl);
    }
});
```

В качестве общего совета — более простой подход заключается в том, чтобы позволить функции выполняться многократно и применять техники идемпотентности внутри. Например, проверить, существует ли разделитель меню, прежде чем создавать новый.

### Очистка элементов управления

В некоторых случаях вы можете привязывать глобальные события только для конкретной страницы, например, привязать горячую клавишу к определённому действию.

```js
addEventListener('keydown', myKeyDownFunction);
```

Чтобы предотвратить утечку этого события на другие страницы, следует удалить событие с помощью метода `page:unload`, который уничтожает все события и элементы управления. Событие можно использовать однократно для безопасной очистки элементов управления и событий.

```js
addEventListener('page:unload', function() {
    removeEventListener('keydown', myKeyDownFunction);
}, { once: true });
```

::: tip
October CMS включает вспомогательную библиотеку для [создания одноразовых элементов управления](./hot-controls.md).
:::

### Приостановка рендеринга

Если вы хотите анимировать элементы, такие как выпадающие меню или меню за пределами экрана, перед загрузкой новой страницы, вы можете приостановить событие `page:before-render`, предотвратив поведение по умолчанию и возобновив его с помощью функции `resume()` из данных события.

```js
addEventListener('page:before-render', async (event) => {
    event.preventDefault();

    await animateOut();

    event.detail.resume();
});
```

::: warning
Имейте в виду, что событие **page:before-render** может сработать дважды: один раз из кэша и ещё раз после запроса нового содержимого страницы.
:::

## Глобальные события

AJAX-фреймворк генерирует несколько событий во время жизненного цикла навигации и ответов страниц. События обычно генерируются на объекте `document`, а данные доступны через свойство `event.detail`.

Событие | Описание
------------- | -------------
**render** | генерируется при обновлении страницы через PJAX или AJAX.
**page:click** | генерируется при клике на ссылку с turbo-маршрутизацией.
**page:before-visit** | генерируется перед переходом по адресу, за исключением навигации через историю браузера.
**page:visit** | генерируется после начала перехода по клику.
**page:request-start** | генерируется перед запросом страницы.
**page:request-end** | генерируется после завершения запроса страницы.
**page:before-cache** | генерируется перед кэшированием страницы.
**page:before-render** | генерируется перед рендерингом содержимого страницы.
**page:render** | генерируется после рендеринга страницы. Срабатывает дважды: один раз из кэша и ещё раз после запроса нового содержимого.
**page:load** | генерируется один раз после начальной загрузки страницы и повторно при каждом переходе.
**page:loaded** | аналогично `page:load`, но ожидает загрузки всех новых скриптов.
**page:updated** | аналогично `DOMContentLoaded`, но генерируется только при переходе на страницу.
**page:unload** | вызывается, когда ранее загруженная страница должна быть очищена.

## Примеры использования

Следующий JavaScript будет выполняться каждый раз при загрузке страницы, включая скрипты.

```js
addEventListener('page:loaded', function() {
    // ...
});
```

## Работа с горячей перезагрузкой

В некоторых случаях turbo-маршрутизатор может мешать при разработке сайта с горячей перезагрузкой или технологией синхронизации браузера, например, при использовании [Laravel Mix](https://laravel-mix.com/) в режиме разработки с `laravel-mix & browsersync`. Для решения этой проблемы добавьте следующий код в конфигурацию `browserSync` вашего webpack.

```js
snippetOptions: {
    rule: {
        match: /<\/head>/i,
        fn: function (snippet, match) {
            return '<meta name="turbo-visit-control" content="disable" />';
        }
   }
}
```
