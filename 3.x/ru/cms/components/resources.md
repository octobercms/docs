# Resources

Компонент `resources` может создавать новые переменные, добавлять заголовки и внедрять ресурсы на страницу. Компонент resources может использоваться на любой странице, макете или фрагменте.

## Доступные свойства

Компонент поддерживает следующие свойства.

Свойство | Описание
-------- | -------------
**js** | Массив JavaScript-файлов в папке **assets/js** темы
**less** | Массив LESS-файлов в папке **assets/less** темы
**scss** | Массив SCSS-файлов в папке **assets/scss** темы
**css** | Массив файлов стилей в папке **assets/css** темы
**vars** | Включает переменные, доступные на странице или макете.
**headers** | Включает заголовки в ответ страницы.

## Базовое использование

Следующий пример использует свойство `vars` для создания новой переменной **activeNav**, которая становится доступной в жизненном цикле страницы, включая макеты и фрагменты, используемые на странице. Переменная доступна через Twig-переменную `{{ activeNav }}`.

::: cmstemplate
```ini
[resources]
vars[activeNav] = 'blog'
```
```twig
{% if activeNav == 'blog' %}
    <p>The blog is active!</p>
{% endif %}
```
:::

## Внедрение переменных

Компонент resources позволяет определять любое количество переменных на странице. Они становятся доступны макету как обычные Twig-переменные.

```ini
[resources]
vars[activeNav] = 'blog'
```

Вы также можете использовать параметры из цикла страницы. В следующем примере переменная `activeNav` будет содержать значение из маршрута страницы `:slug`.

```ini
url = "mypage/:slug"

[resources]
vars[activeNav] = '{{ :slug }}'
```

Эта концепция также работает для переменных компонентов. Следующий пример ищет автора по `:slug` из маршрута страницы, а затем назначает `author.id` переменной страницы **authorIdPage**.

```ini
url = "/author/:slug"

[section author]
handle = "Blog\Author"
identifier = "slug"

[resources]
vars[authorIdPage] = 'Author ID is: {{ author.id }}'
```

## Внедрение ресурсов

Если макет включает стандартные теги `{% scripts %}` и `{% styles %}`, можно внедрять ресурсы в эти заполнители. Ресурсы будут объединены и скомбинированы в единую ссылку на скрипт/стиль.

Ресурсы, загруженные через компонент resources, должны находиться в определённой папке внутри темы, как описано в доступных свойствах. Пример — фрагмент с именем **blocks/carousel.htm**

::: cmstemplate
```ini
[resources]
css[] = "blocks/carousel.css"
scss[] = "blocks/carousel.scss"
less[] = "blocks/carousel.less"
js[] = "blocks/carousel.js"
```
```html
<!-- Carousel Contents Here -->
```
:::

Теперь, когда фрагмент загружен на страницу, скрипты и стили будут внедрены в макет. Ресурсы должны располагаться в директориях **assets/js/blocks/carousel.js** и **assets/less/blocks/carousel.less** соответственно.

```twig
<!-- Assets for the carousel are injected automatically -->
{% partial 'blocks/carousel' %}
```

::: tip
При двойном использовании фрагмента на странице ресурсы будут внедрены только один раз.
:::

## Использование пользовательских заголовков

В качестве примера определения пользовательских заголовков вы можете отрендерить XML-контент на странице вместо HTML. Это возможно путём внедрения заголовка `Content-Type` на страницу со значением **text/xml**. Этот заголовок будет отправлен с ответом при загрузке страницы.

::: cmstemplate
```ini
url = "/blog/rss"

[resources]
headers[Content-Type] = 'text/xml'
```
```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">
    <!-- RSS contents here -->
</rss>
```
