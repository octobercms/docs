# Поля контента

::: aside
Вы можете создавать пользовательские поля контента, [расширяя Tailor](../../extend/tailor-fields.md).
:::

Поля контента — это основа модуля Tailor, определяющая способ настройки и отображения полей. Эти определения обычно находятся в свойстве **fields** чертежа.

```yaml
fields:
    name:
        label: Full Name
        type: text
```

::: tip
Полный список доступных полей можно найти в [разделе элементов панели управления](../../element/form-fields.md).
:::

Для каждого поля можно указать следующие общие свойства, где применимо.

Свойство | Описание
------------- | -------------
**label** | имя, отображаемое при показе поля формы пользователю.
**shortLabel** | более короткая метка для использования в списках и фильтрах.
**type** | определяет способ отображения поля, см. [определения полей формы](../../element/form-fields.md). По умолчанию: text.
**span** | выравнивает поле формы по одной стороне. Варианты: auto, left, right, row, full, adaptive. По умолчанию: `full`.
**spanClass** | используется с параметром span `row` для отображения формы в виде сетки Bootstrap, например, `spanClass: col-4`.
**size** | указывает размер поля для полей, поддерживающих это свойство, например, поле textarea.
**placeholder** | если поле поддерживает значение-заполнитель.
**comment** | размещает описательный комментарий под полем.
**commentAbove** | размещает комментарий над полем.
**commentHtml** | разрешает HTML-разметку внутри комментария. По умолчанию: `false`.
**default** | указывает значение по умолчанию для поля. Для виджетов `dropdown`, `checkboxlist`, `radio` и `balloon-selector` можно указать ключ варианта для выбора по умолчанию.
**tab** | назначает поле на вкладку.
**validation** | определяет правила валидации для поля формы, см. [статью о валидации](../../extend/services/validation.md) для определений правил.
**trigger** | указывает условия для этого поля с помощью [событий триггера](../../element/form-fields.md).
**preset** | позволяет устанавливать начальное значение поля на основе значения другого поля, преобразованного с помощью [конвертера предустановок ввода](../../element/form-fields.md).
**translatable** | отключает перевод для этого поля при использовании `multisite` в определении чертежа.

## Свойства списка и фильтра

Что касается отображения поля в списке или фильтре, каждое поле имеет собственные настройки по умолчанию. Вы можете переопределить эти настройки для каждого поля, что подходит для незначительных изменений. Для более сложных случаев рекомендуется определять столбцы и фильтры отдельно от полей (см. ниже).

Свойство | Описание
------------- | -------------
**column** | определяет способ отображения поля в списке, см. [определения столбцов списка](../../element/list-columns.md).
**scope** | определяет способ отображения поля в фильтре, см. [определения фильтров](../../element/filter-scopes.md).

### Конфигурация поля

Примером может быть указание различных меток с помощью свойств `column` или `scope` поля.

```yaml
myfield:
    label: Form Label
    column:
        label: List Label
    scope:
        label: Filter Label
```

Если установлено значение `false`, поле будет отключено и не отображается.

```yaml
myfield:
    label: Form Label
    column: false
    scope: false
```

Тип `column` может быть установлен в `invisible`, чтобы сделать его скрытым из списка по умолчанию.

```yaml
myfield:
    label: Form Label
    column: invisible
```

### Внешняя конфигурация

Вы можете определить фильтры и столбцы отдельно от полей формы, используя свойства `columns` и `scopes` в чертеже. При использовании внешней конфигурации представление по умолчанию будет заменено только определёнными полями.

```yaml
scopes:
    myfield:
        label: Filter Label
        # [...]

columns:
    myfield:
        label: List Label
        # [...]

fields:
    myfield:
        label: Form Label
        # [...]
```

::: tip
Определение **fields** должно существовать для того, чтобы определение **columns** или **scopes** было допустимым. Чтобы скрыть определение из формы, используйте `hidden: true`, а затем `hidden: false` для отображения в столбце или фильтре.
:::

Столбцы списка имеют сокращённые значения. Передача строки заменит метку, передача `true` включит столбец по умолчанию, передача `false` удалит столбец, а передача `invisible` сделает столбец невидимым.

```yaml
columns:
    myfield: List Label   # New Label
    myfield: true         # Shown
    myfield: false        # Hidden
    myfield: invisible    # Invisible
    myfield: [...]        # Config Array
```

Фильтры имеют аналогичные сокращённые значения.

```yaml
scopes:
    myfield: Filter Label # New Label
    myfield: true         # Shown
    myfield: false        # Hidden
    myfield: [...]        # Config Array
```

## Валидация полей формы

Вы можете указать правила валидации для полей формы с помощью свойства `validation`, см. [статью о валидации](../../extend/services/validation.md) для определений правил.

```yaml
fields:
    myfield:
        label: Featured Text
        validation: "required|min:15"
```

Правила валидации также можно определить внешне в файле чертежа с помощью свойства `validation` чертежа. Это позволяет устанавливать пользовательские имена атрибутов и сообщения валидации.

```yaml
validation:
    rules:
        myfield: "required|min:15"
    attributeNames:
        myfield: My Field
    customMessages:
        myfield.min: "My field has to be at least 15 characters long"

fields:
    myfield:
        label: Form Label
        # [...]
```

Правило валидации `unique` настраивается автоматически и не требует указания имени таблицы.

```yaml
unique_field:
    label: Unique Field
    validation: unique
```

Правило валидации `required` поддерживает модификаторы **create** и **update** для применения только при создании или обновлении модели соответственно. Следующее правило обязательно только при создании новой записи.

```yaml
password:
    label: Password
    validation: "required:create"
```

## Модификация основных полей

Каждая запись чертежа имеет несколько основных полей, [определённых атрибутами модели](./models.md). Вы можете изменить эти поля при определённых условиях.

Запись Entry включена по умолчанию, однако вы можете изменить это, указав новое значение по умолчанию для поля `is_enabled`.

```yaml
fields:
    is_enabled:
        default: false
```

Заполнитель поля `title` генерируется на основе имени чертежа, однако вы можете настроить его для более полезного описания в зависимости от случая. Например, _Имя и Фамилия_, _Название мероприятия_ или _Название места_.

```yaml
fields:
    title:
        placeholder: Event Title
```

В некоторых случаях поле `title` может быть не обязательным, например, при использовании [единичного чертежа](./blueprints.md). Вы можете установить свойство `hidden` в `true`. Скрытие заголовка отключит встроенную валидацию для этого поля.

```yaml
fields:
    title:
        hidden: true
```
