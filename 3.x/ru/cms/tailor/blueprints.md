# Чертежи

## Entry

Чертёж Entry — это стандартная структура контента, используемая для определения разделов вашего сайта. Структуры контента и записи могут быть организованы различными способами, которые подробнее описаны ниже.

Тип `entry` поддерживает множественные записи и должен использоваться, когда не подходит ни один другой вариант.

```yaml
handle: Team\Member
type: entry
name: Team Member

fields:
    name:
        label: First Name
        type: text
```

Чертёж Entry поддерживает следующие свойства.

Свойство | Описание
-------- | -------------
**handle** | Осмысленный и уникальный код для идентификации записи.
**type** | Тип чертежа, может быть вариантом `entry`, `single`, `structure` или `stream`.
**name** | Метка, отображаемая при работе с этой записью.
**fields** | поля формы, принадлежащие группе, см. [поля формы](../../element/form-fields.md).
**groups** | ссылается на группу полей формы, переводя запись в режим групп (см. ниже).
**structure** | конфигурация структуры, используемая при типе `structure`.
**drafts** | включает черновики для этой записи. По умолчанию: `false`
**softDeletes** | включает мягкое удаление для этой записи. По умолчанию: `true`
**multisite** | включает мультисайт для этой записи, синхронизация записей между группой, локалью или всеми сайтами. Поддерживаемые значения: `true`, `false`, `sync`, `locale`, `all`. По умолчанию: `false`
**pagefinder** | включает тип чертежа в [виджет поиска страниц](../../element/form/widget-pagefinder.md), поддерживаемые значения: `true`, `false`, `item`, `list` или массив (см. ниже). По умолчанию: `true`
**defaultSort** | используется типами `entry` и `stream`, устанавливает столбец и направление сортировки по умолчанию, когда пользовательские настройки не определены. Поддерживает строку или массив с ключами `column` и `direction`. Направление может быть `asc` для восходящего (по умолчанию) или `desc` для нисходящего порядка.
**customMessages** | настройка сообщений, используемых в пользовательском интерфейсе (см. ниже).
**showExport** | отображает кнопку на панели инструментов для экспорта записей. По умолчанию: `true`.
**showImport** | отображает кнопку на панели инструментов для импорта записей. По умолчанию: `true`.

### Варианты Entry

Тип entry не имеет специфического поведения, но существует несколько вариантов для организации контента. Следующие типы являются вариантами entry.

- **entry** — базовая запись для общих целей.
- **single** — единичная запись с выделенными полями, например: Страница «Контакты».
- **structure** — определённая структура записей, например: Документация.
- **stream** — поток записей с временными метками, например: Публикации блога.

#### Единичные записи

Тип `single` создаёт одну запись для каждого определения секции. Это полезно для одноразового контента, такого как Главная страница или страница «Контакты». Следующий пример определяет секцию **Homepage** с текстовым полем Welcome Message (`welcome_message`).

```yaml
handle: Homepage
type: single
name: Homepage Content

fields:
    welcome_message:
        label: Welcome Message
        type: text
```

#### Структурные записи

Тип `structure` допускает множественные структурированные записи с родительско-дочерними отношениями. Это полезно для вложенного контента, такого как раздел Документации. Записи типа `structure` могут быть отсортированы. Порядок сортировки можно изменить перетаскиванием в режиме списка. Следующий пример определяет древовидную секцию **Documentation** с полем Article Content (`article_content`) типа markdown.

```yaml
handle: Docs\Article
type: structure
name: Documentation Article

fields:
    content:
        label: Article Content
        type: markdown
```

По умолчанию структуры поддерживают неограниченную вложенность, однако вы можете указать максимальную глубину дерева с помощью `maxDepth` в свойстве `structure`. В следующем примере допускается только верхний уровень и второй уровень.

```yaml
# ...
type: structure

structure:
    maxDepth: 2
    # ...
```

Свойство `structure` поддерживает следующие значения.

Свойство | Описание
-------- | -------------
**maxDepth** | Максимальная глубина структуры. По умолчанию: `0` для неограниченной.
**treeExpanded** | должны ли узлы дерева быть развёрнуты по умолчанию. По умолчанию: `true`
**showReorder** | отображает интерфейс для изменения порядка записей. По умолчанию: `true`
**showSorting** | разрешает сортировку записей, отключает структуру при сортировке. По умолчанию: `true`

#### Потоковые записи

Тип `stream` используется для записей на основе времени, которые часто перечисляются в хронологическом порядке. Это полезно для публикации недавней активности, например раздела Блога. Следующий пример определяет секцию ленты **Blog** с полем Post Content (`content`) типа rich editor.

```yaml
handle: Blog\Post
type: stream
name: Blog Post

fields:
    content:
        label: Post Content
        type: richeditor
```

Свойство `defaultSort` используется для установки столбца сортировки по умолчанию при отображении записей чертежа в виде списка. По умолчанию устанавливается дата публикации.

```yaml
handle: Blog\Post
type: stream
name: Blog Post

defaultSort:
    column: title
    direction: asc
```

### Группы контента

Все записи опционально поддерживают возможность определения нескольких групп контента для секции. Например, секция блога может иметь обычную публикацию и избранную публикацию — это две группы записей.

Группы записей определяются свойством **groups** в файле чертежа секции, и для каждого типа могут быть указаны различные **fields**. Выбранное значение группы доступно как атрибут `content_group` на записи.

```yaml
handle: Blog\Post
type: stream
name: Blog Post

groups:
    regular_post:
        name: Regular Post
        fields:
            # ...

    featured_post:
        name: Featured Post
        fields:
            # ...
```

::: tip
Рекомендуется использовать [чертежи миксинов](#mixin) для группировки общих определений полей.
:::

### Пользовательские сообщения

Укажите свойство `customMessages` для переопределения стандартных сообщений интерфейса. Значения могут быть обычным текстом или ссылкой на [строку локализации](../../extend/system/localization.md).

```yaml
customMessages:
    buttonCreate: Create New Event
```

Следующие сообщения доступны для переопределения.

::: details Просмотреть список доступных сообщений
Сообщение | Сообщение по умолчанию
------------- | -------------
**buttonCreate** | Create :name Entry
**titleIndexList** | Manage :name Entries
**titleCreateForm** | Create :name
**titleUpdateForm** | Update :name
**pagefinderItemType** | :name Entry
**pagefinderListType** | All :name Entries
:::

### Отключение обязательных полей

Запись требует заполнения полей `title` и `slug` перед сохранением, кроме того, поле `slug` должно быть уникальным. Вы можете изменить эту функциональность, переопределив эти поля в вашем чертеже — установив свойство `validation` в **false** или установив свойство `hidden` в **true** для скрытия из пользовательского интерфейса. Следующий пример отключает валидацию для обоих полей и скрывает поле slug.

```yaml
fields:
    title:
        validation: false

    slug:
        hidden: true
```

### Конфигурация поиска страниц

По умолчанию все записи включены в значения поиска [виджета поиска страниц](../../element/form/widget-pagefinder.md). Это можно отключить, установив **pagefinder** в `false`.

```yaml
pagefinder: false
```

Вы можете ограничить контекст поиска страниц, разрешив поиск страницы только как единичный `item` (например, Публикация блога) или как `list` элементов (например, Все публикации блога), или при значении `all` будут отображаться оба варианта.

```yaml
pagefinder: item
pagefinder: list
```

Поиск страниц автоматически разрешает атрибуты `id`, `code`, `slug` и `fullslug` и использует их в качестве замен в [параметрах URL страницы](../themes/pages.md). Вы можете указать пользовательские **replacements** в виде массива, используя свойства **pagefinder**, включая необязательный **context** выше.

```yaml
pagefinder:
    context: list
    replacements: []
```

Каждый ключ замены должен соответствовать имени URL-параметра и использовать точечную нотацию для пути к значению атрибута. Рассмотрим следующий пример URL для страницы публикации блога.

```ini
url = "/blog/post/:author/:category/:slug/:id"
```

Следующие **replacements** установят параметр `:author` в значение атрибута slug связанного автора, а параметр `:category` в значение атрибута slug первой связанной категории.

```yaml
pagefinder:
    replacements:
        author: author.slug
        category: categories.0.slug
```

## Global

Глобальные записи используются для определения глобально доступного контента для вашего сайта. Значения полей часто используются в [CMS-макетах](../../cms/themes/layouts.md) и содержат настройки, такие как ссылки на социальные сети.

Следующий пример определяет глобальную запись **Footer Config** с текстовым полем Facebook Link (`facebook_link`).

```yaml
handle: Site\Footer
type: global
name: Footer Config

fields:
    facebook_link:
        label: Facebook Link
        type: text
```

Чертёж Global поддерживает следующие свойства.

Свойство | Описание
-------- | -------------
**handle** | Осмысленный и уникальный код для идентификации записи.
**name** | Метка, отображаемая при работе с этой записью.
**fields** | поля формы, принадлежащие группе, см. [поля формы](../../element/form-fields.md).
**multisite** | включает мультисайт для этой записи, поддерживаемые значения: `true`, `false`. По умолчанию: `false`
**formSize** | размер формы настроек, поддерживаемые значения: `tiny`, `small`, `medium`, `large`, `huge`, `giant`, `adaptive`. По умолчанию: `huge`.

## Mixin

Миксины — это группы полей, используемые для избежания повторений при определении структур контента. Например, поле Location может использоваться в нескольких местах, но мы можем определить его один раз с помощью определения миксина.

Следующий пример определяет коллекцию **Location** с текстовыми полями Country (`country_code`) и State (`state_code`).

```yaml
handle: Fields\Location
type: mixin
name: Location

fields:
    country_code:
        label: Country
        type: text

    state_code:
        label: State
        type: text
```

Чертёж Mixin поддерживает следующие свойства.

Свойство | Описание
-------- | -------------
**handle** | Осмысленный и уникальный код для идентификации записи.
**name** | Метка, отображаемая при работе с этой записью.
**fields** | поля формы, принадлежащие группе, см. [поля формы](../../element/form-fields.md).

::: tip
Рекомендуется добавлять к файлу миксина и именам полей префикс в виде подчёркивания (\_), чтобы тип чертежа было легко найти. Например: `_location_fields.yaml`
:::

### Использование миксина

Чтобы включить эти поля в ваши записи, как и любое другое поле формы, используйте `type` равный **mixin** и укажите UUID или handle в свойстве `source`.

```yaml
_location_fields:
    type: mixin
    source: Fields\Location
```

Подробнее см. [поле миксина](../../element/content/field-mixin.md).
