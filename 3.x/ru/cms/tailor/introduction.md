# Введение

<VideoBlockLink src="https://www.youtube.com/watch?v=_WMH4mlMdjk" title="Руководство по Tailor" description="Это видео описывает, как быстро создать полноценный блог с помощью Tailor." prompt="Смотреть руководство" />

Tailor — это функция, определяющая файловые структуры контента, используемые вашим сайтом, такие как корпоративный блог или страница команды. Tailor автоматически генерирует пользовательский интерфейс для управления записями в панели администрирования и предоставляет CMS-компоненты для отображения и связывания записей на фронтенде.

При использовании Tailor вы можете пропустить традиционный процесс разработки плагинов и перейти непосредственно к определению контента. Поля определяются просто как шаблоны чертежей (blueprint), а содержимое хранится в специальных таблицах базы данных. Шаблон чертежа также может определять навигацию и другие модификаторы.

## Структура директорий

Чертежи — это YAML-файлы, которые по умолчанию находятся в директории **app/blueprints**, а также в директории **themes/.../blueprints** для [CMS-темы](../themes/themes.md). Размещение чертежей зависит от контекста: **чертежи приложения** доступны глобально, тогда как **чертежи темы** доступны только при выбранной теме.

### Чертежи приложения

Ниже показан пример структуры директории чертежей. Каждый чертёж может располагаться в любой директории с любым именем файла. Чертежи можно организовывать в подкаталогах любой глубины вложенности.

::: dir
├── app
|   └── `blueprints`  _← Чертежи начинаются здесь_
|       ├── blog
|       │   └── blog.yaml
|       │   └── author.yaml
|       ├── about
|       │   └── about.yaml
|       ├── wiki
|       │   └── article.yaml
:::

### Чертежи темы

Далее показан пример структуры чертежей внутри темы **demo**. Как и в директории app, чертежи могут располагаться в любой директории с любым именем файла и любой глубиной вложенности. Навигация панели администрирования для этих чертежей будет отображаться только при выбранной теме, что обычно контролируется [настройками мультисайта](../resources/multisite.md).

::: dir
├── themes
|   └── demo
|       ├── `blueprints`  _← Чертежи начинаются здесь_
|       │   └── settings.yaml
|       │   └── color-scheme.yaml
:::

## Типы чертежей

Свойство **type** чертежа определяет способ его реализации. Доступно несколько типов, и большинство чертежей определяют [поля формы](../../element/form-fields.md).

Тип | Описание
------------- | -------------
Entry | стандартная структура контента с поддержкой черновиков.
Global | единственная запись в базе данных, часто используемая для настроек и конфигурации.
Mixin | определяет повторно используемые определения полей, которые можно импортировать и смешивать с другими определениями полей.

Каждый тип чертежа подробнее описан в [статье о чертежах](./blueprints.md).

## Структура чертежа

::: aside
Чертежи полностью переносимы. Они используют внутренние идентификаторы и могут располагаться в любой директории с любым именем файла.
:::

Чертежи определяются с помощью синтаксиса YAML и всегда содержат три идентификатора: уникальный UUID, удобный для пользователя handle и тип чертежа. Имя файла и директория чертежа используются только для организации и не являются идентификаторами. Все остальные свойства определены в соответствующей документации чертежа.

```yaml
uuid: edcd102e-0525-4e4d-b07e-633ae6c18db6
handle: Blog\Post
type: entry
name: Post

fields:
    # [...]
```

**Handle** чертежа — это удобочитаемый способ обращения к объекту чертежа. Используя приведённый выше чертёж в качестве примера, мы можем обращаться к записям с помощью handle.

::: tip
Handle следуют аналогичному соглашению об именовании, что и пространства имён PHP, и могут быть организованы с помощью разделителя обратной косой черты `\`.
:::

```ini
[section blog]
handle = "Blog\Post"
```

**UUID** чертежа — это уникальный идентификатор, используемый, когда чертежи ссылаются на другие чертежи. Например, когда поле ссылается на миксин. При первом создании чертежа можно не указывать UUID — он будет автоматически создан при первой миграции.

```yaml
_blog_content:
    source: edcd102e-0525-4e4d-b07e-633ae6c18db6
    type: mixin
```

## Интеграция с мультисайтом

Чертежи по умолчанию не используют [возможности мультисайта](../resources/multisite.md). Для их включения используйте свойство `multisite`. При включении записи могут быть уникальными для каждого настроенного сайта.

```yaml
handle: Blog\Post
type: entry
# ...
multisite: true
```

При включённом мультисайте все поля в чертеже становятся переводимыми. Чтобы сохранить одинаковое значение поля, установите свойство `translatable` в false. В этом примере при сохранении записи поле **name** будет скопировано на каждый сайт.

```yaml
# ...
multisite: true

fields:
    name:
        label: Full Name
        type: text
        translatable: false
```

Вы также можете установить значение **sync** для синхронизации записей между сайтами, что полезно для категорий и тегов. При использовании sync каждая запись всегда существует на каждом сайте, хотя содержимое может отличаться.

```yaml
multisite: sync
```

При использовании [групп сайтов](../resources/multisite.md) записи будут распространяться на все сайты в этой группе. Это можно изменить, установив свойство `multisite` в **all** для синхронизации между всеми сайтами.

```yaml
multisite: all
```

Установка значения **locale** синхронизирует записи со всеми сайтами, имеющими одну и ту же локаль.

```yaml
multisite: locale
```

## Миграция чертежей

Чертежи и их структура мигрируются в базе данных в рамках обычного процесса миграции. При ручном изменении файла чертежа следует выполнить команду `tailor:migrate` для обновления таблиц базы данных.

```bash
php artisan tailor:migrate
```

::: tip
Чертежи кэшируются, когда режим отладки отключён. Команда миграции также может использоваться для очистки кэша чертежей.
:::

### Обновление контента

Вы можете удалить весь контент, управляемый Tailor, с помощью команды `tailor:refresh`.

```bash
php artisan tailor:refresh
```

Для обновления одного чертежа используйте опцию `--blueprint` и укажите его handle.

```bash
php artisan tailor:refresh --blueprint="Blog\Post"
```

### Распространение контента

При использовании опции **sync** для мультисайта вы можете ретроактивно распространить записи с помощью команды `tailor:propagate`.

```bash
php artisan tailor:propagate
```

Для распространения одного чертежа используйте опцию `--blueprint` и укажите его handle.

```bash
php artisan tailor:propagate --blueprint="Blog\Category"
```

### Очистка контента

Как правило, Tailor никогда не удаляет столбцы таблиц и контент. Если поле удалено, столбец будет переименован, а не удалён. Например, старое поле `content` может отображаться в таблице базы данных как `x_content_fb418fac`. Таблицы для старых чертежей также сохраняются на случай их восстановления.

Вы можете очистить неиспользуемые столбцы базы данных с помощью команды `tailor:prune`. Эта команда также удаляет таблицы, у которых больше нет связанного чертежа.

```bash
php artisan tailor:prune
```

Вы можете очистить только поля с помощью модификатора `--fields`. Для очистки только таблиц используйте модификатор `--tables`.

```bash
php artisan tailor:prune --fields
php artisan tailor:prune --tables
```

Для очистки одного чертежа используйте опцию `--blueprint` и укажите его handle.

```bash
php artisan tailor:prune --blueprint="Blog\Post"
```
